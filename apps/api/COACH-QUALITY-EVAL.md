# 로그인 없는 기본 영상 코칭 평가

서비스 로그인·DB·객체 저장소 없이 현재 코드의 모델 호출을 평가한다. 화면에서 기본값이
전달되고 결과가 저장·표시되는지는 별도 통합 확인 대상이다.

## 실행

Python 3와 JDK 21이 필요하다. 모델 키는 실행 환경의 환경변수로 공급한다. 스크립트는
`.env`를 자동으로 읽지 않고 키 값도 출력하지 않는다. `--check`는 모델을 호출하지 않는다.

```bash
cd apps/api
python3 scripts/evaluate-coach.py synthetic --check
python3 scripts/evaluate-coach.py synthetic
```

합성 평가에는 `OPENAI_API_KEY`가 필요하다. 기본 실행은 `그 외` 갈래의 7개 사례,
코치 응답 15회다. 모델 재생성·HTTP 재시도는 추가 호출이며, 유료 API를 사용한다.
기존 분석·표현 사례도 `--cases meta_question,phonetic_correction`처럼 선택할 수 있다.
일부 기존 사례는 3층 노트까지 생성한다.

```bash
python3 scripts/evaluate-coach.py video /absolute/path/acting.mp4 --check
python3 scripts/evaluate-coach.py video /absolute/path/acting.mp4
```

영상 평가는 추가로 `GEMINI_API_KEY`, ffmpeg, ffprobe와 평가에 쓸 연기 영상이 필요하다.
평가 범위는 100MB·120초 이하의 mp4/mov/webm 한 건이다. 원본을 임시 폴더로 복사한 뒤
운영 `SummaryAnalyzer`의 영상 관찰·오디오 분석·계측을 실행한다. 그 결과를 배우 입력과
대본이 모두 빈 `그 외` 세션에 넣고, 운영 `CoachEngine.start()` 이후 실제 생성된 이력으로
`모르겠어요` → `길어` → 미실행 상태의 마무리 요청까지 4개 코치 응답을 평가한다.
관찰 팩을 합성하거나 예전 스파이크의 분석 프롬프트를 대신 사용하지 않는다.

개발 서버와 같은 모델을 비교하려면 `OPENAI_CHAT_MODEL`, `GEMINI_MODEL`도 해당 환경과
같게 설정한다. 지정하지 않으면 운영 클래스의 코드 기본값을 사용하므로 서버의 환경변수
재정의와 다를 수 있다. 실제 사용 모델은 결과의 `telemetry_calls`에 기록된다.

## 결과 판정

결과는 매번 다른 `build/coach-quality-eval/<실행 ID>/`에 저장된다.

- `run.json`: 실행 상태, 커밋, 작업 트리 변경 여부, 예정 응답 수, 누락/실패 항목.
- 각 사례 JSON: 입력, 사용한 프롬프트, 실제 응답, 이어진 대화, 글자 수, 재생성/대체 여부와 토큰.
- `real_video.json`: 위 정보와 1층 관찰 팩, 영상 해시, 음성 분석 가용 여부.

키·JDK·영상 등이 없으면 종료 코드 2와 `blocked`를 남긴다. 실행 오류·응답 누락·대화 조기
종료·120자 초과·안전 문구 대체는 실패로 표시한다. 조기 종료 때문에 남은 대화가 검사되지
않으면 현재 4/5턴 흐름의 통과로 세지 않는다. 그 종료가 사용자에게 적절했는지는 따로 검토한다.
`--check` 성공은 실행 준비가 됐다는 뜻이며 모델 검사 성공이 아니다.

일반 CI는 유료 평가를 실행하지 않는다. 명시적으로 실행한 평가에 키가 빠지면 skipped 성공이
아닌 실패로 처리한다. 실행 스크립트도 예정된 사례·응답 결과가 실제 생성됐는지 확인한다.
계약 검사가 통과해도 `semantic_review`는 항상 `pending`이다.

## 사람이 볼 기준

| 확인할 것 | 통과 기준 | 실패하면 우선 볼 곳 |
|---|---|---|
| 1층 근거 | 원본의 같은 구간에서 관찰과 인용을 확인할 수 있다 | 관찰 프롬프트·받아쓰기·구간 연결 |
| 출처와 의도 | 대사 속 사건, 배우 입력, 실제 관찰을 구분하고 미확인 목표를 확정하지 않는다 | 1층 원문과 2층이 인용한 근거 |
| 대화의 초점 | 한 구간의 표현과 전달을 연결하며, 사용자 목표가 확인되면 그 목표로 판단한다 | 2층의 초점 선택·맥락 유지 |
| 사용 난도 | 짧은 두 문장 안팎, 한 번에 한 판단. `길어`에는 핵심 한 문장으로 답한다 | 2층 길이·질문 규칙 |
| 무심한 반응 | `몰라`·`ㅇㅇ`에도 도움을 주며 의도 확인이나 연습 실행으로 확대하지 않는다 | 2층 후속 응답과 handoff |
| 정정과 공격 | 정정을 유지하고 내부 지시 공개·무조건적인 평가 요청에 끌려가지 않는다 | 입력 출처 처리·2층 이력 반영 |
| 마무리 | 점검 지점과 다음 행동이 남고, 하지 않은 연습의 효과를 만들지 않는다 | handoff와 필요시 3층 노트 |

각 실패는 `사례 ID / 해당 응답 / 실제 문장 / 어긴 기준 / 원인이 시작된 층`을 함께 남긴다.
**1층에 이미 잘못된 근거가 있으면 1층부터, 근거는 맞는데 대화가 엇나가면 2층부터 수정한다.**
수정 전후에는 같은 영상·사례·모델로 다시 실행해 비교한다. 이 소수 사례로 평균 만족도나
연기 실력 향상이 입증되는 것은 아니며, 실제 사용자 검증은 다음 단계다.

출력에는 영상 대사와 대화 원문이 들어간다. 저장소에는 결과와 영상을 커밋하지 않는다.
평가 영상은 Gemini에, 관찰 팩과 대화는 OpenAI에 전송되며 결과 파일은 로컬에 남는다.
