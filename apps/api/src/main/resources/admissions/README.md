# 연기 입시 공고 데이터

연극영화과 실기 전형 정보를 손으로 확인해 채운 파일이다. `notices.json` 하나가 전부이고,
`GET /v2/admissions`가 이 파일을 읽어 내보낸다.

손으로 채우는 이유는 팀 위키 `decisions/admissions-manual-curation`, 수집하며 찾은 사실(2027 모집이 없는 곳, 바뀐 학과 명칭,
대학별 입시결과 공개 여부, robots.txt로 막혔던 곳)은 팀 위키 `research/2026-08-04-admissions-collection-notes`에 있다.

## 가장 중요한 규칙

**확인하지 않은 값은 채우지 않는다.** 비워 두거나 `null`로 남긴다. 그럴듯한 날짜를 지어
넣는 것이 이 데이터에서 제일 위험한 실수다.

- 모든 항목에 `verified_at`(사람이 원문을 확인한 날짜)을 남긴다.
- 화면은 항상 원문 링크와 안내 문구(`disclaimer`)를 함께 보여준다.
- 날짜는 `YYYY-MM-DD`. 기간은 `apply_start`/`apply_end`로 나눈다.
- 미확정이면 `null` + `note`에 사정을 적는다.
- 정시 모집요강이 아직 없으면 정시 공고는 전형시행계획을 근거로 채운다. 시행계획도 없으면 공고를 만들지 않는다.

### 값의 출처는 대학 공식 요강뿐

진학사·메가스터디 같은 사설 업체 자료는 **어느 대학에 연기 모집단위가 있는지 찾는
인덱스로만** 쓴다. 경쟁률·등급컷·일정 같은 숫자를 그쪽에서 옮겨 오지 않는다. 상업
데이터라 출처를 밝힐 수 없고, 2차 가공을 거치며 틀어지기 때문이다.

### 서술형이 정본, 구조화 필드는 보조

`stages` · `practical_items` · `weights`는 필터와 비교를 위해 원문을 쪼갠 것이다.
대학마다 실기 구성이 제각각이라 여기에 다 담기지 않는다. **원문 서술(`practical_task`,
`dress_code`)은 항상 그대로 남기고**, 구조화 필드는 확실한 것만 채운다.

`weights`는 특히 조심한다. 모집요강 PDF의 표를 텍스트로 뽑으면 행·열이 뒤엉켜
오독하기 쉬운데, 이 값이 틀리면 지원 전략을 통째로 그르친다. **숫자가 문장이나 표에
또렷하게 적혀 있을 때만 채우고, 조금이라도 애매하면 전부 `null`로 두고 원문 표기를
`weights_note`에 그대로 옮긴다.**

### 부팅 때 걸러지는 것

[`ClasspathAdmissionsCatalog`](../../java/com/acttub/actingapi/feature/admissions/adapter/resource/ClasspathAdmissionsCatalog.java)가
기동 때 파일을 읽으며 검사한다. 걸리면 서버가 뜨지 않으므로 배포 전에 드러난다. 검사 항목과 허용되는
값 목록(실기 종목 `category` 등)은 그 클래스가 정본이다.

## 칸의 뜻

JSON의 모양은 [`Admissions`](../../java/com/acttub/actingapi/feature/admissions/app/Admissions.java) 레코드가 정본이다.
레코드에 설명이 없는 칸의 뜻은 이렇다.

- `universities[].admission_url`: 공식 입학처 주소. 실제로 200을 주는지 확인하고 넣는다.
- `universities[].campus`: "서울"·"ERICA"처럼 캠퍼스별로 전형이 갈릴 때 적는다. `type`은 `univ`(4년제)·`college`(전문대)다.
  둘 다 화면 필터로 쓰인다.
- `notices[].admission_year`: 학년도다. 2027학년도는 2026년에 치르는 입시다.
- `notices[].practical_date`: 여러 날이면 첫날이다. `practical_date_end`는 마지막 날이고 하루면 비운다.
- `notices[].announce_date`: 합격발표일이다.
- `notices[].source_url`: 그 전형이 실린 원문 페이지다.
- 지금 몇 곳·몇 건이 들어 있는지는 `notices.json`에서 센다.

## 전년도 입시결과

**실기 성적 커트라인은 어느 대학도 공개하지 않는다.** `results`에 담기는 등급은 전부
최종등록자의 *학생부 교과* 성적이다. 화면에서도 이 점을 밝힌다.

### 입시결과를 채우는 규칙

대학별로 무엇을 못 찾았는지는 각 결과의 `note`에 남긴다.

- **허용한 출처**: 입학처 입시결과 게시판·PDF·엑셀·게시글 이미지, 대학어디가(대교협)에 대학이
  낸 입결, 그리고 **입학처가 직접 링크한 원서접수 대행사의 실시간 경쟁률 페이지**
  (`ratio.uwayapply.com`·`jinhakapply`). 마지막은 접수 원자료라 예측치가 아니다. 대행사
  본사 사이트(진학사·유웨이 입시 정보)의 컷·분석은 여전히 쓰지 않는다.
- 한 공고에 같은 학년도 결과가 둘일 수 있다(정원 내/정원 외, 주간/야간 같은 하위 전형). 구분은
  `note`에 적는다.
- `competition_rate`는 `"N:1"`로 통일한다. 원문이 `82.15`, `40.86 : 1`처럼 적혀 있어도 같은
  값이다. 지원자·모집 수만 있으면 나눠서 만들지 않는다.
- 학과 이름이 바뀌었거나 모집단위가 합쳐져 2027 공고와 대응이 안 되는 결과는 넣지 않는다.

## 응시 후기 (`universities[].tips`)

`year`는 **그 후기가 다룬 응시 학년도**다(2026학년도 수시 = 2025년 가을 실기). 화면은 후기를
학년도별로 묶어 보여주고, 연도를 모르는 후기는 맨 뒤 "응시 연도를 밝히지 않은 후기"로 간다.

법적 선 — 남의 글이므로 아래를 지킨다.

- 공개 페이지만. 로그인·회원 전용(네이버 카페 등)·유료 글은 쓰지 않는다.
- 원문 문장을 옮기지 않고, 거기서 확인되는 사실(진행 방식·시간·대기·고사장·복장 지시·질문
  유형)만 우리 말로 1~2문장 다시 쓴다. 따옴표 직접 인용 금지. 출처 링크를 항상 붙인다.
- 응시자·합격생·심사위원 이름, 출신 고교처럼 특정 개인을 알아볼 수 있는 내용, 교수에 대한
  인상평은 넣지 않는다.
- 입학처의 수험생 유의사항처럼 대학이 낸 안내도 겪어 봐야 아는 운영 정보(입실 시각, 대기
  동선, 음원 제출 방식)는 `source_type: "official"` 후기로 넣었다.

## robots.txt로 막힌 곳

입학처가 robots.txt로 자동 수집을 막아 둔 곳도 **수집한다**(2026-08-04에 저장소 소유자가 정함). 근거는 대상이
대학이 학생에게 보여주려고 공개한 모집요강이고, 로그인·결제 뒤에 있는 자료가 아니라는 점이다.

수집할 때 지키는 선:
- 필요한 문서만 받는다(모집요강·전형시행계획·입시결과). 사이트 전체를 훑지 않는다
- 같은 도메인에 연속 요청을 몰아치지 않는다
- 로그인이 필요한 페이지는 건드리지 않는다
- 합격자 명단처럼 개인정보가 있는 페이지는 받지 않는다
- 받은 원문 PDF는 `~/Desktop/Project/입시요강-2027/`에 남겨 근거를 추적할 수 있게 한다
  (저장소에는 넣지 않는다 — 요강 하나가 100MB를 넘는 경우가 있다)

## 참고 영상 (`universities[].resources`)

**링크만 담는다. 영상 설명이나 후기 본문은 옮기지 않는다** - 남의 저작물이다.

`source_type`은 반드시 붙인다. 입시학원 홍보 영상이 많고, 제목만
보면 대학 공식 자료처럼 읽히는 것도 있다(예: "[중앙대] 중앙대학교 연극학과 신입생의
솔직한 인터뷰" - 실제로는 RAON ACTORS 채널). 구분 없이 늘어놓으면 입시생이 광고를
정보로 읽는다.

| 값 | 뜻 |
|---|---|
| `official` | 대학·학교 방송국 공식 채널 |
| `school` | 고등학교 채널 |
| `academy` | 입시학원 |
| `personal` | 개인 |

**"합격생"은 본인 주장이고 우리가 검증한 것이 아니다.** 화면에도 그렇게 적는다.
링크는 YouTube oEmbed로 살아 있는지, 채널명이 무엇인지 확인한 뒤 넣는다.

## 갱신

시즌 시작 전(보통 4~5월 전형계획, 8~9월 모집요강)에 원문을 다시 읽고 갱신한다.
`verified_at`이 오래된 항목은 화면에서 "확인 필요"로 표시할 수 있다.
