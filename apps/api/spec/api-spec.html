acting-api 문서

API 스펙과 DB ERD를 한 파일에서 봅니다.

연기 피드백 파이프라인 게이트웨이 — 영상 분석, 코칭 대화, 리포트를 단일 API로 제공합니다.

Base URL EC2 배포 후 확정 · 로컬 http://127.0.0.1:8000 자동 문서 /docs · /redoc 저장소 PostgreSQL (DATABASE_URL 필수)

개요 및 공통 규칙

별도 백엔드 없이 클라이언트(앱)가 이 FastAPI 서버를 직접 호출하는 구조입니다. 인증·약관·업로드와 분석·코칭·리포트를 JWT 소유권 검증 아래 /v2 경로로 제공합니다.

POST /v2/auth/login→ POST /v2/uploads/intents→ POST /v2/practice-sessions→ /v2/coach × N→ POST /v2/reports

모든 /v2 요청은 Authorization: Bearer <access_token> 헤더 필수 (auth 계열 제외). access token은 30분(HS256), refresh token은 14일 — refresh_tokens 테이블에서 회전 관리하며 회전 시마다 수명이 갱신됩니다. 리소스는 항상 토큰의 사용자 기준으로 조회하므로 user_id를 요청에 싣지 않습니다.

공통 오류

상태의미응답
401access token 누락·만료·서명 불일치{"detail": "invalid or expired token"}
404다른 사용자의 리소스 (존재 여부 노출 방지를 위해 403 대신 404){"detail": "<resource> not found"}
429사용자별 분당 한도(60회/분) 초과{"detail": "rate limit exceeded"}

멱등성 — X-Request-Id

AI 호출이 포함된 쓰기 요청(/v2/practice-sessions, /v2/coach/*, /v2/reports)에 클라이언트가 UUID를 담아 보내면 external_operations의 UNIQUE (user_id, request_id)로 중복 실행을 막고, 완료된 요청은 저장된 response_payload를 재반환합니다. 네트워크 재시도 시 영상 재분석·토큰 재소모가 없습니다.

주요 엔드포인트 상세

POST/v2/auth/login

클라이언트가 구글·카카오·애플 SDK로 받은 OIDC id_token을 서버가 검증하고 자체 JWT를 발급합니다. (provider, provider_uid)가 처음이면 users와 user_identities를 생성합니다. 같은 이메일의 기존 계정이 있으면 검증된 이메일(email_verified)일 때만 기존 계정에 identity를 자동 연결하고, 미검증이면 409로 거절합니다.

요청 — JSON

필드타입필수설명
providerstr필수google | kakao | apple
id_tokenstr필수공급자가 발급한 OIDC id_token

응답 200

{
  "access_token": "<JWT>",
  "refresh_token": "<opaque>",
  "token_type": "Bearer",
  "expires_in": 1800,
  "user": { "id": "33333333-3333-4333-8333-333333333333", "email": "actor@example.com", "status": "active" },
  "pending_consents": [
    { "document_id": "...", "type": "terms", "version": "2026-07", "required": true }
  ]
}
pending_consents가 비어 있지 않으면 클라이언트는 동의 화면을 먼저 띄우고 POST /v2/consents로 기록합니다. POST /v2/auth/refresh는 {"refresh_token": "..."}을 받아 새 토큰 쌍을 발급하며, 사용된 토큰은 replaced_by_id로 연결됩니다 (재사용 감지 시 해당 사용자 토큰 전체 회수).

오류

상태원인
401id_token 검증 실패 (서명·만료·audience 불일치)
403정지된 계정 (users.status != active)
409같은 이메일의 기존 계정 존재 + 미검증 이메일 — {"detail": "account_exists_with_different_provider"}
POST/v2/uploads/intents

영상을 서버를 거치지 않고 스토리지에 직접 올리도록 presigned URL을 발급합니다. 최대 100MB 영상을 API 서버가 받지 않으므로 서버 메모리·타임아웃 부담이 사라집니다.

요청 — JSON

필드타입필수설명

size_bytesint필수최대 100MB
duration_msint선택클라이언트가 아는 경우 전달

{
  "intent_id": "44444444-4444-4444-8444-444444444444",
  "upload_url": "https://storage.example.com/...&X-Signature=...",
  "method": "PUT",
  "object_key": "uploads/2026/07/44444444.mp4",

업로드 완료 후 POST /v2/uploads/intents/{intent_id}/complete를 호출하면 서버가 스토리지에서 실제 존재·크기를 검증하고 finalized로 확정합니다. 만료(expires_at 경과)·미업로드 상태에서 호출하면 409.

POST/v2/practice-sessions

확정된 업로드로 연습 세션을 만들고 장면 분석을 백그라운드로 시작합니다. 응답을 기다리지 않고 202를 즉시 반환하며, 분석 결과는 세션 상세 조회로 확인합니다.

요청 — JSON

필드타입필수설명
upload_intent_idUUID 문자열필수finalized 상태의 인텐트
situationtext필수상황
character_contexttext필수인물설정
subtexttext필수서브텍스트

응답 202

{
  "session_id": "55555555-5555-4555-8555-555555555555",
  "status": "analyzing"
}
GET /v2/practice-sessions/{session_id}가 세션 상태와 서명된 재생 URL(upload_intents의 object_key로 서명)을 반환하고, 분석이 끝나면(status: "analyzed") SceneSummary + summary_id가 summary 필드에 포함됩니다. 분석 실패 시 status: "failed"와 error_code를 노출하며, 같은 세션에 재요청하면 영상 재업로드 없이 재분석합니다(재분석은 summaries 1:N).

오류

상태원인
409인텐트가 finalized가 아니거나 이미 다른 세션에 사용됨 (upload_intent_id UNIQUE)
POST/v2/coach/* · /v2/reports

코칭 대화(start·reply)와 리포트 생성·이력 조회입니다. 상세 요청·응답 스키마는 API.md 참고.

항목동작
인증Authorization: Bearer
소유권summary·session이 토큰 사용자 소유가 아니면 404
리포트 생성POST /v2/reports — 응답은 report + report_count (user_id는 토큰으로 자명)
리포트 이력GET /v2/reports — 토큰의 사용자 기준, 경로 파라미터 없음
멱등성X-Request-Id 지원 — 처리 중 재요청 409, 성공 재요청은 저장된 응답 재반환

PostgreSQL 13개 테이블. user 귀속은 reports → coach_sessions → summaries → practice_sessions → users FK 사슬로 도출하며, 파생 가능한 값은 저장하지 않습니다.

스키마 — 13개 테이블

클라이언트가 직접 호출하는 단일 FastAPI 서버의 단일 PostgreSQL 스키마입니다. 서버가 하나이므로 서버 간 논리 참조 없이 전부 실제 FK로 연결되며, 파일 메타는 upload_intents가 단일 원천입니다.

관계

  

    
users1 : Nuser_identities한 사용자가 여러 소셜 로그인 연결 — UNIQUE (provider, provider_uid)

    
users1 : Nrefresh_tokens기기·세션마다 토큰 하나, 회전 시 replaced_by_id 연결

    
consent_documents1 : Nuser_consents불변 이벤트 로그 — 현재 동의 상태는 (user, document) 최신 행

    
users1 : Npractice_sessions사용자가 여러 연습 세션 소유 — user_id NOT NULL

    
upload_intents1 : 1practice_sessions인텐트 1건당 세션 1건, 세션당 영상 하나 — upload_intent_id UNIQUE, 파일 메타는 조인으로 도출

    
practice_sessions1 : Nsummaries재분석 허용 시 1:N — UNIQUE 제약 없음, ON DELETE CASCADE

    
summaries1 : Nanomaliessort_order로 서버 계산 순서 보존, ON DELETE CASCADE

    
summaries1 : Ncoach_sessions같은 요약으로 여러 번 코칭 — summary_id NOT NULL

    
coach_sessions1 : Ncoach_turns대화 순서 보장 — UNIQUE (session_id, turn_index), ON DELETE CASCADE

    
coach_sessions1 : 1reports세션당 리포트 1건 — reports.session_id UNIQUE NOT NULL

    
practice_sessions1 : Nexternal_operationsAI 호출 멱등성 — UNIQUE (user_id, request_id)로 중복 요청 차단

  






  
설계 결정

  

    
파생 값 저장 금지 — user 귀속은 reports → coach_sessions → summaries → practice_sessions → users FK 사슬로 도출하고, question_count·report_count 같은 값은 COUNT로 대체합니다.

    
external_operations — Gemini 외부 호출의 멱등성(UNIQUE user_id+request_id)·lease·시도 상한(3회, 초과 시 max_attempts_exceeded)을 관리합니다. 완료된 호출은 response_payload를 재반환해 재시도를 흡수합니다.
