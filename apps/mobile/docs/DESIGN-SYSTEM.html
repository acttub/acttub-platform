앱 디자인 시스템

앱 화면의 색·글자·모서리·간격 토큰과 공통 부품 규칙입니다. 부품의 그림은 디자인 시스템 pen 파일 (acttub/pen acttub-design-system.pen)에 있고, 이 문서는 그 규칙을 글로 옮긴 것입니다. 화면별 디자인은 같은 저장소의 acttub-app-screens.pen 에 있습니다.

정본 관계

  • pen(acttub/pen acttub-design-system.pen)은 그림 원본이고, 이 HTML 은 규칙 글입니다. pen 의 구역은 0~5 번입니다.
  • pen 을 바꾸면 이 파일도 같이 바꿉니다.
  • 값이 다르면 코드가 지금 동작입니다. 코드에 아직 없는 pen 값은 「다음 변경 예정」으로 표시합니다.
  • 이 파일의 토큰 표와 constants/palette.ts·constants/tokens.ts 가 다르면 tests/design-system.test.mjs 가 실패합니다.

앱 코드는 이 기준으로 옮기는 중입니다. 새로 만들거나 고치는 화면은 이 문서의 값과 부품을 씁니다. 요청받은 화면 밖의 코드를 이 기준에 맞추려고 함께 고치지 않습니다.

의도된 차이

아래는 불일치처럼 보여도 일부러 다르게 만든 것입니다. 하나로 합치거나 맞추지 않고 그대로 유지합니다.

  • 탭바는 플랫폼마다 다르다. iOS 는 화면 위에 뜬 글래스 알약(좌우 20, 높이 64), 글자 없는 아이콘 26, 고른 탭은 회색 반투명 알약이 칸을 거의 채운다. 안드로이드는 바닥에 붙은 막대(위 1px border)이고, 고르지 않은 탭은 아이콘 22만 칸 가운데에 있다. 고르면 아이콘이 9 위로 올라가며 아래에 탭 이름(micro, blue-deep)이 0.18초 동안 나타난다(SOMA-923). 두 플랫폼 모두 고르지 않은 탭 아이콘은 icon-faint이고, 홈 아이콘은 pen 의 lucide house를 그림으로 옮겨 쓴다(SOMA-942). 구현은 components/ui/tab-bar.tsx 의 IOS 분기다.
  • 첫 사용자 화면은 흐름이 다르다. 첫 사용자는 탭바를 숨기고 탭 화면에 홈 꺾쇠·설정을 두며, 홈 구성·안내·예시·첫 완료 축하 문구가 다르다(lib/practice/first-time.ts). 버튼·머리·목록 행·색·글자 같은 부품 모양은 단계와 상관없이 같다.
  • 상태 화면 버튼은 가운데에 둔다. 화면 전체 오류·빈 상태의 버튼은 아래 고정 바가 아니라 문구 바로 아래 가운데다.
  • 빈 상태는 오류보다 한 단계 낮다. 오류는 마스코트 120 + title1, 빈 상태는 마스코트 96 + title2.
  • 글자 버튼은 두 톤이다. 보조 선택지는 text-sub, 링크·강조는 blue-deep. 리딩 완료의 「다시 읽기(blue-deep) · 다른 대본으로(text-sub)」가 그 예다.
  • 챌린지 「나도 이 대사 연기하기」는 알약 버튼이다. 챌린지 홈의 이번 주 카드와 챌린지 카드 안 버튼은 높이 48 · r-full, 가운데 영상 아이콘 + 글자(headline), 오른쪽 끝에 동그라미 화살표(32). 다른 버튼은 모서리 16 그대로다.
  • 회원 탈퇴만 주 버튼이 위다. 아래 고정 바는 보통 주 버튼이 맨 아래지만, 탈퇴는 되돌릴 수 없어서 「탈퇴하기」를 위에, 「그대로 쓸게요」를 맨 아래(엄지가 닿는 자리)에 둔다.
  • 연속 연습 축하 숫자만 64다. 연속 연습 축하 화면의 일수 숫자는 64 / 72 · 700 흰 글자로 크게 둔다. 다른 숫자는 글자 크기 표를 따른다.
  • 기본 얼굴은 24색 밖이다. 사진이 없는 사람의 기본 얼굴(components/ui/default-avatar.tsx)은 자기 8색을 쓴다. 알림함은 모든 알림에 민트 하나를 쓴다. 사람 얼굴(챌린지 참여자·참여작·댓글·차단 목록·프로필)은 화면마다 따로 그리지 않고 이 파일의 UserAvatar(프로필 사진이 있으면 사진, 없으면 기본 얼굴)를 쓰며, 색은 늘 user_id 로 골라 같은 사람은 어디서나 같은 색이다. 탈퇴한 사람은 사진 없이 회색이다.
  • 그 뒤 리딩 완료만 마스코트가 위에 있다. 아래 내용(코칭 권유·안내·평가)이 많아서다. 다른 완료 화면의 마스코트는 상태 막대 아래 96 자리다.
  • 홈 위 배경은 옅어지는 파랑 띠다. 위에서 아래로 #E4EEFC→#F7FAFE 로 옅어지는 띠와 창문 빛 그림, 연한 바탕 #F7FAFE (SOMA-923). iOS 당김(바운스) 자리도 #E4EEFC 로 채운다. 이 색은 24색에 없어 홈 화면 파일(app/(tabs)/index.tsx) 안에만 두고, 띠 안의 인사·카드·글자는 토큰이다. 다음 변경 예정: pen 값은 #E4EEFC→#FFFFFF 이고, 코드는 아직 위 값이다.
  • 리딩 입구 위 배경은 흰색까지 옅어지는 그라데이션이다. 대본 없는 리딩 탭의 위 띠는 #E4EEFC→#FFFFFF 세로 그라데이션이고, 아래 모서리가 둥글지 않으며 약 310pt 에서 흰색이 된다. 이 색은 24색에 없어 app/(tabs)/reading.tsx 안에만 둔다. 원칙 1 의 그라데이션 금지에 대한 예외이고 새 화면으로 번지지 않는다.
  • 리딩 「이전에 하던 대본부터」·챌린지 「오늘의 챌린지」 카드는 진한 파랑이다. 바탕 #0A61FB(토큰 blue 보다 선명), 위 알약 (리딩은 흰 20%, 챌린지는 남색 45% + 노란 번개), 오른쪽 아래 액티(책 위·슬레이트), 아래 흰 알약 버튼(높이 48, r-full) — 10/29 시안. 24색 밖 색은 constants/hero-card.ts 에만 두고 이 두 카드에만 쓴다.
  • 설정 Pro 카드는 그라데이션이다. pen S15.3 의 옅은 파랑→보라 카드와 왕관 타일(components/settings-pro-card.tsx)이다. 그라데이션 색은 24색에 없어 그 파일 안에만 두고, 나머지 색·글자·모서리는 토큰이다.
  • 가입 질문 말풍선만 안쪽 사방 16이다. 제목 headline, 안내 body2 로 디자인 시스템의 마스코트 안내 글자를 따른다 (MascotBubble 의 question). 홈·코칭·리딩 입구 말풍선은 그대로다.
  • 가입 첫 인사(반가워요)만 가운데 정렬이다. 액티·인사는 화면 맨 위와 [시작하기] 버튼 사이의 가운데에 둔다.
  • 생년월일 휠의 고르는 칸은 1.5px 테두리다. blue-soft 바탕에 blue 테두리로 카드(1px)보다 진하게 둔다.
  • 로그인 넓은 버튼은 높이 62다. 브랜드 로그인 버튼이라 버튼 높이(48)보다 크게 둔다. 카카오·네이버 로고는 각 사 공식 이미지다.

원칙

  1. 조용한 연습실, 평가표 아님. 점수 원형·레이더 차트, 좋음/나쁨을 암시하는 색, 그라데이션·글로우·보라 AI 팔레트를 쓰지 않는다(PRD 「디자인」). 그라데이션은 「의도된 차이」에 적은 곳만 예외다.
  2. 한 역할에 한 부품. 오류·빈 상태·머리·버튼·다이얼로그는 아래 부품 하나로 그린다. 같은 행동은 어느 화면에서나 같은 부품이다.
  3. 값은 토큰으로만. 색·글자·모서리·간격은 아래 토큰만 쓴다. hex·소수점 글자 크기를 화면에 직접 적지 않는다.
  4. 네 상태를 다 그린다. 데이터를 받는 화면은 불러오는 중·비었음·실패·채움을 모두 그린다. 받기 전 숫자는 0 대신 Skeleton.
  5. 흐름은 달라도 부품은 같다. 위 「의도된 차이」의 첫 사용자 항목.
  6. 화면 가장자리를 지킨다. 주 행동은 아래 고정 바(BottomCTA)에 두고 안전영역·키보드 위로 올린다. 그림자를 준 요소에 clip (overflow: hidden)을 주지 않는다. 배지·이름은 잘리지 않게 폭을 늘린다. 상태 화면만 예외.
  7. 필요한 정보만 보인다. 다음 행동을 정하는 데 쓰지 않는 정보(내부 상태·개수·시간·설명 문장)는 두지 않는다. 오류는 할 수 있는 것(다시 시도·연결 확인·나중에 하기)만 말하고, 오류 코드·번역 키·역할 코드는 보이지 않는다.

  • 작은 글자는 바탕과 대비 4.5 이상. 메타 글자는 text-meta, icon-faint 는 아이콘에만.

부품

화면은 components/ui 의 공용 부품으로 그립니다. 같은 역할의 부품을 화면 안에 새로 만들지 않습니다.

부품규칙
버튼높이 48·40·32, 모서리 16(32 는 12), 글자 headline(48)·body2-bold(40·32). 주 버튼 색은 blue 하나, 삭제만 danger. 처리 중 글자는 「~하는 중…」. 글자 버튼은 위 두 톤.
화면 머리(NavHeader)하위 화면은 높이 44, 왼쪽 뒤로 꺾쇠(44 터치), 가운데 제목 headline. 오른쪽은 할 일이 있을 때만 아이콘·글자 버튼 하나, 없으면 빈칸으로 두어 제목이 가운데에 머문다. 탭 첫 화면만 큰 왼쪽 제목(display).
단계 머리(StepHeader)NavHeader 와 같은 높이·꺾쇠에 n/N(caption)과 아래 진행 막대. 뒤로만 있는 머리는 제목 없는 NavHeader.
칩·스위치·고르기 카드선택은 blue-soft 바탕 + 1.5px blue 테두리 + blue-deep 글자. 꺼짐은 흰 바탕 + 1px border. 목록을 거르는 필터 칩도 같다. 스위치는 OS 기본 토글에 색만 지정한다(켜짐 blue, 꺼짐 text-disabled). pen 견본 크기는 참고용이다.

화면 틀

  • 상태 화면(StatusScreen): 화면 전체가 오류·빈 상태·로딩이면 이 틀 하나. 세 틀 모두 머리에 그 화면 이름을 둔다. 오류는 마스코트 120 + title1 + 설명(body2, 할 수 있는 것 한 줄) + 「다시 시도」 하나. 빈 상태는 마스코트 96 + title2. 로딩은 행 뼈대. 버튼 없는 오류 화면, 빨간 글 한 줄 화면을 만들지 않는다.
  • 완료 화면(DoneScreen): 첫 완료와 그 뒤 완료가 같은 꼴이다 — 머리 없음 · 마스코트 120(상태 막대 아래 96) · 제목(첫 완료는 축하 문구) · 대본 이름 · 요약 · 다음 행동(내용 안) · 아래 고정 「홈으로 가기」 하나. 리딩의 다음 행동은 「↻ 다시 읽기 · 다른 대본으로」 글자 버튼 줄(아이콘 16 + body2-bold), 챌린지는 공유·코칭·다른 참여작 목록 줄. 코칭 권유와 리딩 평가는 그 뒤 리딩 완료에만 둔다.
