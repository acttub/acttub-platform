# 리딩 파서 공통 검증 자료

웹(`apps/web/src/lib/reading/script/parse.ts`)과 앱(`apps/mobile/lib/reading/parse.ts`)은 같은 파서를 쓴다.
같은 입력에 같은 결과가 나오는지 이 자료로 고정한다(reading.script 「검증 방법」). 웹 갈래가 만들고 앱 갈래는 읽기만 한다.

## 모양

- `NN-slug.txt` — 대본 샘플. 모두 이 저장소를 위해 지은 창작 글이라 저작권 문제가 없다.
- `NN-slug.json` — 같은 이름의 샘플을 `parseScript(raw)`(옵션 없음)에 넣은 기대 결과.

```json
{
  "title": "옥상, 밤",            // 제목이 없으면 null (JSON 에 undefined 가 없어서다)
  "roles": ["윤서", "태오"],       // 등장 순서
  "lines": [
    { "type": "direction", "text": "옥상 난간." },
    { "type": "dialogue", "role": "윤서", "text": "여기 있을 줄 알았어." },
    { "type": "scene", "text": "제1막" }
  ]
}
```

줄의 `type`은 대사 `dialogue`(배역 `role` 있음)·지문 `direction`·장면 `scene` 셋이다. 서버 API 의 `kind` 와 같은 값이다.

## 확인하는 방법

- 웹: `node --test tests/reading-script-fixtures.test.mjs` (`pnpm --filter web test` 에 들어 있다).
- 앱: 같은 파일을 읽어 `parseScript(raw)` 의 결과를 `{ title: parsed.title ?? null, roles, lines }` 로 만들어 `deepEqual` 한다.
- 파서 규칙을 바꿨으면 웹에서 `UPDATE_READING_FIXTURES=1 node --test tests/reading-script-fixtures.test.mjs` 로 기대 결과를 다시 쓰고,
  바뀐 json 을 눈으로 확인한 뒤 앱 파서에도 같은 규칙을 넣는다.

## 샘플이 보는 것

| 파일 | 형식·규칙 |
|---|---|
| 01 | 콜론 형식, 괄호 지문 한 줄, 대사 안 괄호는 대사에 남음 |
| 02 | 전각 콜론·공백 콜론, 이름 없는 다음 줄은 앞 대사에 이어 붙음 |
| 03 | 블록 형식, 제목 조건(첫 줄 30자 이하 + 빈 줄), `[암전]` |
| 04 | 공백 형식(콜론·블록이 없을 때만), `이름, 행동` 은 지문 |
| 05 | 등장인물 목록이 배역의 기준, 목록 밖 이름(2줄)은 지문, `제1막` 장면, 제목 |
| 06 | 장면 표기: `제1막`·`S#2`·`1막 2장`·`제 3 장`, 장면은 대사 번호에 들어가지 않음 |
| 07 | 영어 막·장(`Act 1`·`SCENE 2`·`ACT I, SCENE 3`), 화자 자리·홀로 선 영어 무대어(`PAUSE:`·`BEAT`)는 배역이 아님 |
| 08 | `[이름] 대사` 꼴, `[장] 제1장` 구조 표시는 장면 |
| 09 | 한글 파일 마크업 `<<0>>`·`<<것>>`, 쪽 표시 `- 2 -` |
| 10 | 자간 띄운 이름 `사    장 :` |
| 11 | PDF 줄 파편(홀로 선 조사 `이`)은 앞 대사에 이어 붙음 |
| 12 | 배역이 하나뿐인 대본(독백) |
| 13 | 첫 줄이 31자면 제목이 아니라 지문 |
| 14 | 첫 줄 뒤에 빈 줄이 없으면 제목이 아님 |
| 15 | 등장인물 목록의 `1. 이름 ------ 설명`·`/` 나열, `박사` ↔ `로다 박사` 어긋난 표기 |
| 16 | 반각·전각 괄호·대괄호 지문, 홀로 선 `사이.` |
| 17 | 조사 붙은 이름(`촐레가`)은 지문의 첫 어절 |
| 18 | 목록 밖 이름이 8줄이고 전체 발화의 1% 이상이면 배역 |
| 19 | `프롤로그`·`에필로그`, 설명 붙은 장면 `S#1. 거실, 낮`·`1장 - 옥상` |
| 20 | 웹·앱에 내장된 예시 대본 |
