# 이슈 트래커: Jira `SOMA`

Jira `SOMA`가 이슈의 정본입니다. **사람이 이슈를 만들고 본문을 쓰며**, 에이전트는 초안과
자기 실행 계획을 준비합니다. 이 경계의 이유와 되돌릴 조건은 [ADR-022](../ADR.md)입니다.

| 이름 | 위치 | 독자 | 내용 |
|---|---|---|---|
| 이슈 | Jira `SOMA` | 사람 | 배경 / 원하는 상태 / 완료 조건 |
| 계획 | `.scratch/<이슈키>.md` | 다음 세션의 에이전트 | 조사, 결정, 단계, 검증, 이월 |

둘을 뭉뚱그려 “티켓”이라 부르지 않고 **이슈**와 **계획**으로 구분합니다.

## 새 이슈를 제안할 때

1. 제안할 이슈 후보 수를 먼저 셉니다. 5건을 넘으면 제목과 우선순위 목록만 보여 승인받은 뒤
   초안을 작성합니다.
2. 승인된 후보마다 아래 세 절만 있는 초안을 작성합니다. 근거·조사 기록·설계는 계획에 두고,
   이슈에는 필요할 때 참고 경로 한 줄만 붙입니다.
   - 배경
   - 원하는 상태
   - 완료 조건(체크리스트)
3. 사람이 Jira에 이슈를 만든 뒤 알려 준 키를 사용합니다. 키나 본문을 비슷한 제목으로
   추측하지 않습니다.

**완료 기준:** 사용자가 실제 키를 알려 주었고, 그전에는 브랜치나 계획 파일을 키 추정값으로
만들지 않았습니다.

## 기존 이슈를 착수할 때

1. 사용자가 준 키 또는 현재 브랜치·PR에 포함된 `SOMA-123` 형식의 키를 확인합니다. 확인할
   수 없으면 사용자에게 묻습니다.
2. `.scratch/<이슈키>.md`를 경로로 직접 엽니다. `.scratch/`는 추적되지 않아 `git grep`에
   나타나지 않습니다.
3. 계획이 없고 Jira 본문도 제공되지 않았다면 필요한 배경·원하는 상태·완료 조건을
   사용자에게 요청합니다.
4. 브랜치의 시작점·merge 방식·릴리스 흐름은
   [BRANCHING-STRATEGY.md](../BRANCHING-STRATEGY.md)를 따릅니다. 작업·hotfix 브랜치와 PR에는
   대문자 이슈 키를 넣고, 커밋 메시지에는 넣지 않습니다.

**완료 기준:** 착수한 키와 계획 파일명이 같고, 계획의 모든 단계와 선행 관계가 현재 코드와
다시 대조됐습니다.

## 계획을 유지할 때

- 이슈 하나에 `.scratch/<이슈키>.md` 하나만 둡니다. 형식과 길이는 작업에 맞게 정합니다.
- 단계가 여러 커밋으로 나뉘면 선행 관계와 각 단계의 검증을 계획에 기록합니다.
- 계획에 적힌 파일 수·대상 수·마이그레이션 번호는 착수 직전에 현재 트리에서 다시 셉니다.
- 완료 뒤에도 계획 파일을 옮기거나 지우지 않습니다. 저장소에 남아야 하는 내용만 정본으로
  승격합니다.

## 작업을 끝낼 때

1. 앞으로 지킬 규칙은 맞는 저장소 정본으로 옮깁니다.
   - 되돌리기 어려운 결정 → `docs/ADR.md`
   - 에이전트가 지킬 절차 → 해당 `CLAUDE.md` 또는 포인터가 가리키는 문서
   - 제품 도메인 용어 → `CONTEXT.md`
2. 새 버그와 미처리 이월은 세 절짜리 Jira 초안으로 정리해 사람에게 넘깁니다.
3. 상태 전이, 이슈 삭제, 기존 본문 교체는 요청하지 않습니다. GitHub 연동과 사람의 판단에
   맡기고, 추가 정보는 코멘트 초안으로 전달합니다.

**완료 기준:** 계획에 남은 항목을 `규칙 / 새 버그 / 종료`로 전수 분류했고, 저장소 밖 계획에만
남아 사라질 규칙이나 이월이 없습니다.

## GitHub Issues와 트리아지

GitHub Issues는 외부 제보용 인박스입니다. 참고 자료로 읽을 수 있지만 실행 계획은 Jira와
`.scratch/`에 둡니다. 정식 작업으로 옮길 때는 Jira 이슈 초안을 사람에게 넘기고 GitHub 쪽에는
이동 안내 코멘트 초안을 준비합니다. 라벨 판단은 [triage-labels.md](triage-labels.md)를 따릅니다.

외부 PR은 트리아지 큐로 쓰지 않습니다.

## Wayfinding을 Jira에 적용할 때

- **map**은 사람이 만든 Jira Epic 하나이며, Notes / Decisions-so-far / Fog는
  `.scratch/<에픽키>.md`에 둡니다.
- **child**는 그 파일의 항목이고 종류(`research` / `prototype` / `grilling` / `task`)와
  blocking 선행 관계를 함께 기록합니다.
- 담당자와 Epic 상태는 사람이 정합니다. 에이전트는 다음 후보를 제안하고, 해결된 결정은
  Decisions-so-far에 한 줄로 남깁니다.

## ADR-022를 되돌릴 때만

사람이 ADR-022의 되돌릴 조건이 충족됐다고 판단해 Jira 읽기 연결을 복원하기로 결정한 경우에만
아래 절차를 사용합니다. 연결 복원은 이슈 생성 권한을 에이전트에 주는 결정이 아닙니다.

```bash
claude mcp add --scope user --transport http atlassian https://mcp.atlassian.com/v1/mcp/authv2
```

인증은 세션에서 `/mcp` → `atlassian` → 브라우저 OAuth로 진행하고,
`claude mcp get atlassian`의 실제 연결 상태를 확인합니다.
