# 도메인 문서

Acttub의 세 앱은 제품 도메인 언어를 공유합니다. 용어집은 루트 `CONTEXT.md`, 결정 기록은 단일
파일 `docs/ADR.md`가 정본입니다.

## 읽는 순서

1. 제품 개념을 이름 붙이거나 바꿀 때 `CONTEXT.md`에서 현재 어휘와 피하는 동의어를 읽습니다.
2. 되돌리기 어려운 결정을 다룰 때 `docs/ADR.md`에서 닿는 항목을 찾습니다.
3. ADR을 인용하거나 바꾸기 전에 그 항목의 헤더부터 다음 ADR 헤더 직전까지 읽습니다. 헤더
   바로 아래 개정 블록이 기존 결정을 뒤집거나 좁힐 수 있습니다.
4. 앱 구현 규칙은 해당 `apps/<app>/CLAUDE.md`와 그 문서가 가리키는 정본을 이어서 읽습니다.

**완료 기준:** 출력에서 쓰는 도메인 어휘와 결정이 현재 용어집 및 개정된 ADR과 충돌하지
않습니다.

## 용어를 사용할 때

- 이슈 제목, 설계, 코드 이름, 테스트 이름은 `CONTEXT.md`의 어휘를 그대로 씁니다.
- 필요한 개념이 없으면 프로젝트가 실제로 쓰는 개념인지 먼저 재검토합니다. 새 개념이라면
  임의의 동의어를 퍼뜨리지 않고 도메인 모델링 후보로 드러냅니다.
- 기존 ADR과 다른 제안은 충돌하는 ADR 번호와 달라져야 하는 이유를 함께 제시합니다.

## 정본을 바꿀 때

- 용어가 확정되면 `CONTEXT.md`의 기존 항목과 충돌·중복을 확인한 뒤 한 정의로 반영합니다.
- 새 ADR은 `docs/ADR.md` 끝의 다음 번호로 추가하고 **결정 / 이유 / 트레이드오프** 구조를
  유지합니다.
- 기존 결정을 바꾸면 원문을 조용히 덮지 않고 해당 ADR에 개정 사실과 새 판단 범위를
  드러냅니다.

**완료 기준:** 새 의미는 정본 한 곳에만 정의되고, 그 의미를 사용하는 문서와 코드가 같은
어휘를 씁니다.
