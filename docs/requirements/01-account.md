# 계정

[쓰는 법과 공통 규칙](00-common.md)을 먼저 읽는다.

## account.login 로그인·자동 가입
- 도입: 1.0.0
- 화면: A0, A0.1
- 테이블: users, user_identities, refresh_tokens, consent_documents, user_consents

### 기능
구글·애플·카카오·네이버 간편 로그인만 제공하며 로그인은 앱에만 있다. 웹은 로그인 없이 게스트로
쓴다. (account.guest) 별도 회원가입 화면은 없다. 처음 로그인한 사람은 같은 흐름 안에서 동의 화면을
거치고, 동의를 제출하는 순간 계정이 만들어진다. 다음부터는 같은 계정으로 들어온다. 이미 있는 계정도
아직 결정하지 않은 동의 문서가 있으면 로그인 응답에 실리고, 필수·선택 동의를 모두 결정할 때까지
보호 기능은 막힌다.

### 의도
가입 절차가 있으면 첫 화면에서 이탈한다. 배우가 촬영까지 가는 길을 버튼 하나로 줄인다. 국내
사용자 대부분이 쓰는 카카오·네이버를 더해 구글·애플 계정이 없는 사람도 막히지 않게 한다.

### 목적
어떤 제공자로 들어와도 한 사람은 한 계정이고, 두 번째 로그인부터는 자기 연습·노트·기억이 그대로
보인다.

### 규칙·제약
- 계정을 찾는 순서가 계약이다. ① 제공자와 제공자 ID로 찾는다. ② 없으면 제공자가 검증했다고
  알린 이메일로 기존 계정을 찾아 그 계정에 새 신원을 붙인다. ③ 그것도 없으면 새 계정을 만든다.
  이메일은 신원이 아니라 부가 정보다. 제공자에서 이메일을 바꿔도 같은 계정이다.
- 검증 안 된 이메일이 기존 계정과 겹치면 로그인을 막고 이미 쓰는 방식으로 안내한다. 검증 안 된
  주소만 대고 남의 계정에 들어가는 것을 막기 위해서다.
- 제공자별 이메일 검증 근거: 구글·애플은 ID 토큰의 email_verified. 카카오는 ID 토큰에 검증
  여부가 없어 사용자 정보 API의 is_email_verified로 확인한다. 네이버는 검증 표시가 없다. 주소가
  @naver.com이면 그 계정의 메일함이므로 검증된 것으로 보고, 외부 메일이면 검증되지 않은 것으로
  본다. 네이버가 준 표시가 아니라 계정 구조에 따른 우리 판단이다.
- 이메일은 앞뒤 공백을 떼고 소문자로 맞춘다. 검증된 이메일만 저장한다. 이메일 없는 계정도
  정상이며 그때 email은 빈 문자열이 아니라 NULL이다. 탈퇴로 지운 이메일도 NULL이다.
- 클라이언트는 제공자가 발급한 ID 토큰을 서버에 넘기고, 서버가 제공자 공개키로 검증한다. 네
  제공자 모두 OpenID Connect ID 토큰을 발급한다. 카카오·네이버는 개발자 콘솔에서 OIDC를 켜야
  한다. 애플 로그인 요청에는 authorization code를 함께 보낸다. 서버는 이를 애플 토큰으로 바꿔
  user_identities에 암호화해 저장하고, 탈퇴 때 폐기 API에 쓴다.
- provider 허용값은 google, apple, kakao, naver, 웹 게스트용 guest, 개발용 development다.
- users.status 허용값은 active와 deactivated다. 계정 정지는 1.0.0에 없다.
- 제공자 제공 범위: iOS는 넷 다. 안드로이드는 애플을 뺀 셋. 웹에는 로그인이 없다.
- iOS와 안드로이드 앱은 제공자마다 같은 애플리케이션 등록을 쓴다. 네이버와 카카오의 사용자 ID는
  애플리케이션 단위로 발급되므로 등록을 나누면 같은 사람이 다른 신원이 된다.
- 디자인의 로그인 화면(A0)에는 구글·애플 버튼만 있어 카카오·네이버 버튼을 더해야 한다.
- 카카오·네이버는 검수 승인 뒤에만 운영에서 켠다. 승인 전에는 등록한 테스트 계정만 로그인된다. 운영
  배포 체크리스트에 넣는다.
- 같은 신원으로 동시에 두 요청이 오면 하나만 계정을 만들고 다른 하나는 그 계정을 쓴다.
- 로그인 요청은 IP별로 분당 60회까지다. 넘으면 429.
- 계정 행은 가입 제출이 통과한 순간 만든다. 제출은 필수 문서 셋의 동의와 선택 문서의 결정을 모두
  담는다. 그 전에는 제공자 신원과 이메일을 저장하지 않고, 동의 화면을 위한 짧은 가입 토큰만
  발급한다. 동의 화면에서 나가면 아무것도 남지 않는다. 동의 없이 개인정보를 갖고 있지 않기 위해서다.
- 가입 토큰은 30분 유효하다. 만료하면 로그인 버튼부터 다시 시작한다.
- 동의 화면의 저장 버튼은 필수 문서 셋에 동의하고 선택 문서마다 동의·거절 중 하나를 고른 뒤에야
  켜진다. 선택 문서 줄은 기본값 없이 동의·거절 두 버튼이다. 그래서 선택 미결정은 새 판을 발행할
  때만 생긴다. 서버도 가입 제출에 현재 판 모든 문서의 결정이 담기지 않으면 422로 거절한다. 버튼
  문구는 "동의하고 계속하기"다. 디자인의 "결정 저장하기"를 바꾼다.
- 동의 게이트는 요청마다 DB의 동의 상태로 판정한다. 로그인을 다시 하거나 토큰을 갱신해도 결정하지
  않은 문서가 하나라도 있으면 보호 기능은 막힌다. 필수 문서는 동의만 할 수 있고 화면에 거절이
  없다. 선택 문서는 동의와 거절 중 하나를 고르며, 거절도 결정이다. 갱신 응답에는 동의 목록이
  없으므로 앱은 시작할 때 미결정 동의를 조회한다. 동의 다음에는 프로필 입력이 같은 게이트로
  이어진다. (account.profile)
- 게이트에 막힌 요청은 403이다. 동의 미결정이면 사유 consent_required와 미결정 문서 목록을, 프로필
  미완이면 사유 profile_required를 함께 준다. 탈퇴한 계정의 403(account_deactivated)과는 사유로
  구분한다.
- 폰에 마지막 로그인 제공자를 기억해 두고 로그인 화면에서 그 버튼을 강조한다. 앱을 지우면 기억도
  사라진다. 서버는 관여하지 않는다.
- 로그인 때 제공자가 검증된 이메일을 주면 users.email을 그 값으로 갱신한다. 다른 계정이 이미 쓰는
  주소면 그대로 둔다.
- 액세스 토큰은 30분, 리프레시 토큰은 30일이다. 갱신할 때마다 리프레시 토큰을 새로 주고 옛 것은
  소진된다. 소진된 토큰이 다시 오면 탈취로 보고 그 회원의 세션을 전부 끊는다.
- 액세스 토큰이 만료되면 앱이 리프레시로 한 번 갱신하고 요청을 다시 보낸다. 서버가 리프레시를
  거부하면 기기의 토큰을 지우고 로그인 화면으로 보낸다. 네트워크 오류는 로그아웃 사유가 아니다.
- 30일 동안 앱을 한 번도 열지 않으면 다시 로그인해야 한다.
- 만료되거나 폐기된 지 30일이 지난 refresh_tokens 행은 하루 한 번 지운다. 그 전까지는 소진된
  토큰의 재사용 탐지와 문제 추적에 쓴다.

### 예외
- 제공자 토큰이 잘못됐거나 만료됐으면 401. 지원하지 않는 제공자는 400. 제공자 설정이 없으면 503.
- 이메일 겹침은 409. 화면 문구는 "이미 OO로 가입한 이메일이에요".
- 애플 '이메일 가리기'로 가입한 사람이 나중에 다른 제공자로 들어오면 계정이 둘이 된다. 1.0.0은
  이를 받아들인다.
- 애플로만 가입한 사람은 안드로이드에서 로그인할 수 없다. 1.0.0은 이를 받아들인다.
- 카카오·네이버는 이메일을 선택 동의로 받으므로 사용자가 동의하지 않을 수 있다. 그 계정은 이메일
  없이 만들어지고, 나중에 다른 제공자로 들어와도 이어지지 않는다.
- 제공자가 준 이름은 이름 칸을 미리 채우는 값으로만 쓰고, 이름은 가입 게이트의 프로필 입력 화면에서
  직접 받는다. 애플은 이름을 첫 로그인 한 번만 주므로 앱이 들고 있다가 프로필 화면까지 넘긴다. 동의
  화면에서 나가면 그 이름도 사라지고 이름 칸은 빈 채로 시작한다. (account.profile)
- 첫 로그인의 동의 화면에서 나가면 계정이 만들어지지 않는다. 다시 로그인하면 동의 화면부터
  시작한다. 이미 있는 계정에 새 필수 문서가 생기면 동의할 때까지 보호 기능만 막히고 계정은
  그대로다. 동의하지 않았다는 이유로 계정을 지우지 않는다.
- 탈퇴한 계정으로 다시 로그인하면 새 계정이 된다. 이전 연습·노트·기억은 보이지 않고 이전 계정에 관해
  아무것도 묻지 않는다.
- 제공자 쪽에서 연결을 끊거나 제공자 회원을 탈퇴하면 그 신원만 지운다. 네이버는 연결 끊기
  콜백으로 알려 준다. 계정은 남으므로 검증된 이메일이 있으면 다른 제공자로 이어질 수 있다. 마지막
  신원이 끊기고 검증된 이메일도 없으면 아무도 닿을 수 없는 계정으로 남는다. 1.0.0은 이를 받아들인다.
- 탈취 탐지의 부작용: 앱이 갱신 중에 죽어 새 토큰을 저장하지 못하고 옛 토큰으로 다시 시도한 정상
  회원도 세션이 전부 끊긴다. 보안을 위해 감수하며, 다시 로그인하면 된다.
- 기기마다 리프레시 토큰이 따로 있어 한 기기의 로그아웃이나 만료는 다른 기기에 영향이 없다. 탈취
  탐지로 전부 끊길 때만 예외다.

### 검증 방법
- 제공자 넷 각각 첫 로그인: 응답에 동의 문서와 가입 토큰이 실리고 users·user_identities 행은 아직
  없다. 동의를 제출하면 행이 하나씩 생기고 액세스·리프레시 토큰이 발급된다. 두 번째 로그인: 행이
  늘지 않고 같은 계정이다.
- 구글로 만든 계정과 같은 검증된 이메일로 애플 로그인: 같은 계정으로 들어가고 user_identities 행이
  하나 더 생긴다. users 행은 늘지 않는다.
- 구글로 만든 계정과 같은 @naver.com 주소로 네이버 로그인: 위와 같다.
- 외부 메일로 바꾼 네이버 계정이 기존 계정과 같은 주소로 로그인: 409와 안내 문구. 계정은 늘지
  않는다.
- 이메일 동의 없이 카카오로 로그인해 동의를 제출하면: users.email이 NULL인 계정이 생긴다.
- 탈퇴 뒤 같은 제공자로 로그인: 동의 화면부터 나온다. 동의를 제출하면 새 users 행이 생기고 이전
  데이터가 보이지 않는다.
- 잘못된 토큰은 401, 지원하지 않는 provider는 400. 한 IP에서 1분에 61번째 로그인: 429.
- 선택 문서의 새 판에 아직 답하지 않은 상태에서 연습 API 호출: 403과 미결정 문서 목록이 온다. 거절을
  고르면 허용된다.
- 필수 문서에 거절을 보내면: 422. 화면에는 거절 버튼이 없다.
- 첫 로그인의 동의 화면에서 나간 뒤 DB: users·user_identities 행이 없다. 다시 로그인하면 동의
  화면이 나온다.
- 기존 계정에 필수 문서의 새 판이 발행된 뒤 로그인: 로그인은 되고 연습 API는 403과 미결정 문서
  목록이다. 동의하면 같은 토큰으로 허용된다.
- 미결정 동의가 있는 채로 토큰을 갱신한 뒤 연습 API 호출: 여전히 403이다. 모두 결정하면(선택 문서는
  거절해도 된다) 같은 토큰으로 허용된다.
- iOS에서 만든 계정으로 안드로이드에서 같은 제공자로 로그인: 구글·카카오·네이버 각각 같은 계정이다.
- 카카오로 로그인한 뒤 로그아웃하고 앱을 다시 열면: 카카오 버튼이 강조돼 있다.
- 제공자에서 이메일을 바꾼 뒤 로그인: 같은 계정이고 users.email이 새 주소다. 새 주소를 다른 계정이
  쓰고 있으면 옛 주소가 남는다.
- 만료된 액세스 토큰으로 보호 API 호출: 갱신 뒤 요청이 성공하고 새 리프레시 토큰이 온다. 옛
  리프레시 토큰으로 다시 갱신: 401이고 그 사용자의 다른 기기도 다음 갱신 때(최대 30분 안) 로그인
  화면으로 돌아간다.
- 리프레시 토큰이 만료되거나 폐기된 상태에서 앱을 열거나 API 호출: 기기의 토큰이 지워지고 로그인
  화면이 뜬다.
- 갱신 요청이 네트워크 오류로 실패: 로그아웃되지 않고 오류가 표시되며 다음 요청에서 다시 갱신한다.
- 만료된 지 31일 된 refresh_tokens 행: 정리가 돈 뒤 없다. 29일 된 행: 남아 있다.
- 같은 신원으로 가입 제출 둘을 동시에: users 행이 하나이고 둘 다 같은 계정의 토큰을 받는다.
- 발급 31분 뒤 가입 제출: 401이고 행이 없다. 선택 문서 결정을 빼고 제출: 422.
- 네이버 연결 끊기 콜백 수신: 그 신원 행만 없고 users 행은 그대로다.

### 범위 밖
- 설정에서 로그인 방식 연결. 로그인한 상태에서 두 번째 제공자로 인증해 같은 계정에 신원을 붙이는
  기능. 폰을 바꿔 마지막 로그인 방식 기억이 사라진 경우와 애플 이메일 가리기로 갈린 계정까지
  해결한다. 후속.
- 안드로이드의 애플 로그인.
- 웹 로그인. (account.guest)
- 가입 유입 경로 추적. users의 signup_* 아홉 컬럼은 아무 코드도 쓰지 않으므로 1.0.0에서 지우고
  테이블도 만들지 않는다.

## account.consent 동의 조회·변경
- 도입: 1.0.0
- 화면: A4 설정(동의 목록), D3·W3(동의 문서 공개 페이지). 웹 게스트의 동의 시트는 미설계
- 테이블: consent_documents, user_consents

### 기능
설정에서 내가 결정한 동의 문서를 보고, 선택 문서는 언제든 동의와 거절을 바꾼다. 필수 문서는 내용만
본다. 웹에서는 누구나 동의 문서의 현재 판을 읽을 수 있다. 문서의 새 판을 내면 기존 회원은 게이트에서
다시 결정한다. (account.login)

### 의도
선택 동의는 언제든 철회할 수 있어야 한다. 탈퇴 후 영상 보관 동의도 회원인 동안은 여기서 바꾼다.
동의 문서는 가입 전에도 읽을 수 있어야 하고, 앱 스토어 심사도 공개 주소를 요구한다.

### 목적
배우가 무엇에 동의했는지 한 화면에서 보고, 마음이 바뀌면 그 자리에서 바꾸며, 바뀐 결정이 바로
적용된다.

### 데이터
| 문서 | type | 필수 |
|---|---|---|
| 서비스 이용약관 | terms | 필수 |
| 개인정보 수집·이용 동의 | privacy | 필수 |
| AI 분석 동의 | ai_analysis | 필수 |
| 탈퇴 후 영상·녹음 보관·활용 | retention | 선택 |

필수 셋의 type은 현재 코드와 같다. privacy 문서는 수집 항목·목적·보유 기간을 적은 개인정보 수집·이용
동의다. 개인정보 처리방침은 동의를 받는 문서가 아니라 고지라서 결정 대상에 넣지 않고 공개 페이지에
함께 싣는다. 현재 코드와 디자인은 privacy 문서의 제목이 "개인정보처리방침"이라 고쳐 새 판을 낸다.
광고성 정보 수신 문서는 1.0.0에 두지 않는다. 광고성 발송이 없는데
동의만 받으면 2년마다 수신 의사를 확인할 의무만 생긴다. 디자인의 동의 화면(A0.1)에는 필수 셋만
있어 선택 문서 줄을 더해야 한다.

### 규칙·제약
- 결정 값은 granted, declined, revoked 셋이다. 가입 때와 설정에서 고른 동의는 granted, 거절은
  declined이고, 탈퇴 뒤 운영자가 처리한 철회만 revoked다.
- type마다 현재 판이 하나다. 새 판은 version을 올려 발행하고 옛 판 행은 남긴다. 결정은 판 단위로
  기록한다(user_consents는 추가만 하고 고치지 않는다). 현재 결정은 그 판에 대한 마지막 행이다.
- 새 판이 나오면 옛 판의 결정은 옛 판에만 유효하고 새 판은 미결정이 된다. 필수·선택 모두 같아서
  선택 문서의 새 판도 게이트에 나온다. 거절해도 결정이므로 통과한다.
- 필수 문서는 설정에서 내용만 보고 바꿀 수 없다. 필수 동의를 거두는 길은 탈퇴뿐이며 화면에 그렇게
  적는다.
- 선택 문서는 설정에서 동의와 거절을 오간다. 바꾸는 즉시 저장하고, 되돌리려면 다시 바꾼다. 선택
  문서는 회원에게만 묻고, 게스트는 기능마다 필요한 필수 문서만 그 기능을 처음 쓸 때
  결정한다. (account.guest)
- 탈퇴 후 영상 보관 동의를 거절로 바꾸면 회원인 동안은 아무 일도 없고, 탈퇴할 때 현재 판의 결정을
  읽어 파기 여부를 정한다. 현재 판이 미결정이면 거절로 보고 파기한다. (account.withdraw) 그래서
  탈퇴해도 user_consents 행은 남긴다.
- 새 판 때문에 뜬 동의 화면에는 "동의하지 않으면 탈퇴할 수 있어요" 링크를 두어 탈퇴 화면(A5)으로
  보낸다. 필수 문서에 거절 버튼이 없고 설정은 동의 화면 뒤에 있으므로 떠나는 길이 이것뿐이다. 가입
  중의 동의 화면은 나가면 아무것도 남지 않으므로 이 링크가 없다.
- 설정 화면은 문서마다 제목, 판, 시행일, 내 결정과 결정 시각을 보여 준다.
- 공개 페이지(D3·W3)는 누구에게나 모든 동의 문서의 현재 판 전문을 보여 주고 결정 버튼이 없다. 옛
  판은 보이지 않는다. 이 주소는 언제나 열람용이고 게스트의 결정은 기능 안의 시트에서
  받는다. (account.guest)
- 문서 발행은 배포에 든 파일로 한다. 서버가 시작할 때 파일의 판이 DB보다 새로우면 새 판 행을 만든다.
  관리 화면은 없다. 같은 판의 본문만 고치면 DB 본문을 덮어쓰고 재동의는 없다. 뜻이 바뀌는 수정은
  판을 올리며, 그 판단은 사람이 한다.
- 웹과 앱은 현재 판을 API로 받는다. 클라이언트에 판 번호를 박아 두지 않는다.
- 동의 조회와 제출은 게이트 밖이다. (공통 규칙)

### 예외
- 현재 판이 아닌 문서 id로 결정을 보내면 409. 화면은 목록을 다시 받아 현재 판을 보여 준다.
- 필수 문서에 거절이나 철회를 보내면 422. (account.login과 같다)
- 없는 문서 id는 404.
- 지금 결정과 같은 결정을 다시 보내면 행을 늘리지 않고 200.
- 탈퇴한 계정의 동의 기록은 남는다. users 행처럼 사람과 이어지지 않는다.

### 검증 방법
- 설정을 열면: 필수 셋과 선택 하나가 각각 현재 판, 시행일, 내 결정, 결정 시각으로 보인다.
- 선택 문서를 거절로 바꾸고 다시 열면: 거절됨이고 user_consents에 declined 행이 하나 늘었다.
  보호 API는 그대로 된다.
- 필수 문서에 거절을 보내면: 422이고 설정 화면에는 바꾸는 버튼이 없다.
- 선택 문서의 새 판을 발행한 뒤 로그인: 그 문서만 미결정으로 게이트에 나오고 다른 문서의 결정은
  그대로다. 거절을 고르면 통과한다.
- 옛 판 id로 결정을 보내면: 409.
- 같은 결정을 두 번 보내면: 둘 다 200이고 user_consents 행은 하나만 는다.
- 웹의 동의 문서 주소: 게스트 토큰이 있든 없든 현재 판 전문만 보이고 결정 버튼이 없다.
- 영상 보관을 동의에서 거절로 바꾼 뒤 탈퇴: 영상 객체가 없다. 거절에서 동의로 바꾼 뒤 탈퇴: 영상
  객체가 남는다.
- 탈퇴 뒤 DB: 그 회원의 user_consents 행이 남아 있다.
- 보관 문서의 새 판이 미결정인 채 탈퇴: 옛 판에 동의했어도 영상 객체가 없다.
- 필수 문서의 새 판이 미결정인 회원이 동의 화면의 탈퇴 링크로 들어가 탈퇴: 된다.
- 배포 파일의 판이 DB보다 새로운 채로 서버 시작: 새 판 행이 생긴다. 같은 판이면 행이 늘지 않는다.
- 같은 판의 본문만 고쳐 배포: 판이 그대로고 재동의 게이트가 뜨지 않는다.

## account.profile 프로필
- 도입: 1.0.0
- 화면: A0.2, A4 프로필
- 테이블: user_profiles, user_profile_directions, users, user_identities, user_consents, refresh_tokens, push_tokens

### 기능
이름, 성별, 나이, 추구하는 방향(복수 선택), 연기 경력, 최종 목표 여섯을 모두 입력받는다. 전부
필수다. 처음 로그인했거나 이 중 하나라도 비어 있으면 입력 화면을 보여 주고, 다 채울 때까지 보호
기능을 쓸 수 없다. 동의와 같은 게이트이며 동의를 모두 결정한 다음에 이어진다. 채운 뒤에는
설정에서 같은 항목을 고칠 수 있다.

### 의도
코치가 배우를 알고 시작해야 한다. 성별·나이·방향·경력·목표는 매 연습마다 묻지 않고 한 번 받아
프로필에 두며, 코치 대화와 노트가 이것을 읽는다. 1.0.0 이전 회원은 옛 닉네임(users.nickname)만
있어서, 빠진 항목을 첫 로그인 때 같은 화면으로 받는다.

### 목적
첫 연습부터 코치가 배우의 방향과 경력에 맞춰 말하고, 배우는 같은 것을 두 번 입력하지 않는다.

### 데이터
| 항목 | 형식 | 필수 |
|---|---|---|
| 이름 | 실명 또는 활동명 텍스트 | 필수 |
| 성별 | 여성 · 남성 · 선택 안 함 | 필수 |
| 나이 | 생년월일로 저장하고 만 나이는 계산해서 보여 준다. 만 14세 미만은 가입할 수 없다 | 필수 |
| 추구하는 방향 | 매체(TV·영화) · 무대(연극·뮤지컬) 중 복수 선택 | 하나 이상 |
| 연기 경력 | 입문 전 · 입시생 · 1년 미만 · 1–3년 · 3–5년 · 5년 이상 | 필수 |
| 최종 목표 | 취미 · 공연·오디션 · 전문 배우 | 필수 |

값 목록은 pen의 A0.2 화면 선택지다. "선택 안 함"도 하나의 값이라 필수를 만족한다. 추구하는 방향은
user_profile_directions(user_id, direction)에 고른 값마다 한 행씩 둔다. 디자인의 나이
칸은 출생연도인데 이 문서는 생년월일로 정했으므로 디자인을 맞춰야 한다.

### 규칙·제약
- 만 14세 미만 생년월일이 가입 게이트에서 오면 422를 돌려주고 그 계정을 즉시 파기한다. 아직 연습이
  없으므로 users·user_identities·user_consents·refresh_tokens·push_tokens 행까지 지운다. 탈퇴와 달리 행을
  남기지 않는다. 앱은 안내 문구를 보여 주고 로그인 화면으로 돌아간다. 법정대리인 동의가 필요한
  나이라 1.0.0은 받지 않는다. 설정에서 고친 생년월일이 만 14세 미만이면 422로 거절만 하고 계정은
  그대로다. 파기한 뒤 같은 사람이 다른 생년월일로 다시 가입하는 것은 막을 근거가 남지 않으며
  받아들인다.
- 이미 연습이 있는 1.0.0 이전 회원이 같은 게이트에서 만 14세 미만을 넣으면 행을 지우지 않고 탈퇴와
  같은 절차로 닫는다. 보관 동의가 있어도 영상·녹음은 파기한다. 아동의 동의는 법정대리인 없이 효력이
  없기 때문이다. (account.withdraw)
- 여섯 항목 모두 설정에서 언제든 고칠 수 있다. 고칠 때도 필수 규칙은 같아서 비워서 저장할 수 없다.
  고친 값은 바로 저장되고 다음 코치 대화부터 반영된다.
- 게이트 순서는 동의 → 프로필이다. 개인정보를 받기 전에 수집 동의가 끝나 있어야 한다.
- 개인정보 수집·이용 동의 문서(privacy)의 필수 항목은 이 여섯 항목과 같다. 문서에는 항목마다 코칭에
  쓰이는 이유를 한 줄씩 적는다. 필수로 받을 수 있는 것은 서비스 제공에 실제로 쓰이는 항목뿐이고, 그
  입증은 우리 몫이다. 탈퇴 후 영상 보관은 선택으로 남긴다. 광고성 정보 수신 문서는 1.0.0에
  없다. (account.consent)
- 항목을 늘리거나 선택을 필수로 바꾸면 동의 문서를 새 판으로 낸다. 기존 회원은 게이트에서 다시
  결정한다.
- 게이트는 요청마다 DB의 프로필 상태로 판정한다. 필수 항목이 하나라도 비어 있으면 토큰을
  갱신해도 보호 기능은 막힌다.
- 제공자가 준 이름은 이름 칸을 미리 채우는 값으로만 쓴다. 저장되는 것은 배우가 확인한 값이다.
- 성별·나이는 프로필이 정본이다. 배우 기억(actor_memories)에는 두지 않는다. (ERD 결정)
- 이름은 공개 이름이다. 챌린지 참여작과 댓글의 작성자 이름으로 보이며, 입력 칸에 "다른 사람에게
  보이는 이름이에요"를 적는다. 이름을 바꾸면 이미 올린 참여작·댓글도 현재 이름으로 보인다. 참여작·댓글
  행에 이름을 복사해 두지 않는다. 이름 말고는 본인만 본다. 예외는 공유 링크를 켠 포트폴리오 공개
  페이지로, 사진·성별·만 나이가 함께 보인다. (account.portfolio)
- 사진과 소개는 선택 항목이며 설정에서만 받는다. 가입 게이트의 입력 화면에는 없다. 사진은 1장, 10MB,
  이미지 파일만 받고 정사각 자르기는 앱이 한다.
- 디자인에는 여섯 항목을 고치는 진입점이 없어 설정이나 프로필 탭에 더해야 한다. A4 프로필의
  "포트폴리오 편집"은 다른 기능이다. (account.portfolio)

### 예외
- 입력 도중 앱을 닫으면 다음에 앱을 열 때 입력 화면을 처음부터 다시 시작한다. 여섯 항목을 한 번에
  저장하고 부분 저장은 하지 않는다.
- 값 목록에 없는 값이 오면 422로 거절한다.
- 탈퇴하면 이름·사진·소개를 지우고 나머지는 가명처리해 남긴다. (account.withdraw)

### 검증 방법
- 첫 로그인 뒤 동의를 모두 결정하면 프로필 화면이 나오고, 필수 항목을 다 채우기 전 연습 API
  호출: 403과 사유 profile_required가 온다. 다 채우면 같은 토큰으로 허용된다.
- 1.0.0 이전 회원이 로그인: 프로필 화면이 나오고 옛 닉네임이 이름 칸에 채워져 있다.
- 추구하는 방향을 둘 이상 선택해 저장: 둘 다 저장되고 다시 열면 둘 다 선택돼 있다.
- 생년월일을 저장한 뒤 조회: 만 나이가 오늘 기준으로 계산돼 온다. 생일 전날과 당일에 한 살 차이가
  난다.
- 오늘 만 14세가 되는 생년월일: 저장된다. 하루 뒤 생일인 생년월일: 422와 안내 문구가 나오고 DB에 그
  계정의 행이 없다. 다시 로그인하면 동의 화면부터 시작한다.
- 설정에서 생년월일을 만 14세 미만으로 고치면: 422이고 계정과 옛 값은 그대로다.
- 연습이 있는 1.0.0 이전 회원이 게이트에서 만 14세 미만을 넣으면: 422이고 계정이 deactivated가 되며
  보관 동의와 무관하게 영상 객체가 없다.
- 설정에서 여섯 항목을 각각 고치고 화면을 다시 열면 고친 값이 보인다. 항목을 비워서 저장하면 422다.
- 설정에서 경력을 고친 뒤 새 코치 대화를 시작하면: 코치에 넘기는 프로필 입력에 고친 값이 들어 있다.
- 설정에서 11MB 사진이나 이미지가 아닌 파일을 올리면: 422. 사진과 소개 없이 게이트 통과: 된다.
- 애플로 첫 로그인: 이름 칸에 애플이 준 이름이 채워져 있고, 지우고 다른 이름을 저장할 수 있다.
- 이름을 저장한 뒤 챌린지에 참여작을 올리면: 작성자가 프로필 이름으로 보인다. 이름을 바꾸면 그
  참여작의 작성자도 바뀐다.
- 개인정보 수집·이용 동의 문서 본문의 필수 항목을 프로필 API의 필수 항목과 대조하면: 여섯 항목이
  같고 문서에 없는 필수 항목이 없다.

## account.portfolio 포트폴리오
- 도입: 1.0.0
- 결정 기록: ADR-030
- 화면: A4 프로필(포트폴리오 편집). 편집 화면과 공개 페이지는 미설계
- 테이블: portfolios, portfolio_credits, portfolio_photos (ERD에 추가), user_profiles

### 기능
배우가 오디션에 낼 포트폴리오를 직접 적어 두고 공유 링크로 보여 준다. 가입 때 받는 프로필 여섯
항목(account.profile)과는 다른 것이다. 항목은 소개글, 경력 여러 개, 사진 여러 장이고, 링크는
배우가 켠 동안만 열린다.

### 의도
배우는 오디션마다 소개 자료를 새로 써서 보낸다. 한 번 적어 두면 링크 하나로 낼 수 있다. 디자인의
프로필 탭이 "배우 정보와 경력을 추가해 주세요"로 이 자리를 잡아 두었다.

### 목적
배우가 링크 하나로 자기 경력과 사진을 보여 주고, 내용을 고치면 링크를 다시 보내지 않아도 최신이
보인다.

### 데이터
| 항목 | 형식 | 필수 |
|---|---|---|
| 소개글 | 여러 줄 텍스트 | 선택 |
| 경력 | 작품명, 역할, 연도, 종류(영화·드라마·연극·뮤지컬·광고·기타) 여러 개 | 선택 |
| 사진 | 최대 10장, 순서 있음 | 선택 |
| 공유 링크 | 켬·끔, 주소의 난수 slug | |

항목은 셋뿐이다. 신체 정보·특기는 받지 않는다. 공개 페이지에는 프로필의 이름·사진·성별·만 나이를
가져와 함께 보이고, 추구하는 방향·경력 구간·목표는 보이지 않는다. 성별이 "선택 안 함"이면 성별 칸을
뺀다.

### 규칙·제약
- 포트폴리오는 회원당 하나이며 처음 편집할 때 만든다. 전부 선택 항목이라 빈 채로도 저장된다.
- 항목마다 따로 저장한다. 경력과 사진은 추가·수정·삭제·순서 바꾸기가 된다.
- 사진은 이미지 파일만 받고 장당 10MB, 10장까지다. 사진 객체는 영상과 같은 저장소에 두되 videos와
  별개다. 프로필 사진(account.profile)과도 별개다.
- 공유 링크는 기본 꺼짐이다. 처음 켤 때 난수 slug가 생기고 웹의 공개 페이지가 로그인 없이 열린다.
  끄면 404이고 다시 켜면 같은 주소가 다시 열린다. 주소를 바꾸려면 "새 링크 만들기"를 누르며, 그때
  옛 주소는 404가 된다. 편집은 앱에서만 한다.
- 공개 페이지는 검색 엔진에 노출하지 않는다(noindex). 링크를 아는 사람만 본다.
- 공개 페이지는 연습·분석·챌린지 등 다른 자료를 보이지 않는다.
- 탈퇴하면 포트폴리오·경력·사진을 행째 지우고 사진 객체도 지우며 링크는 404다. (account.withdraw)
- 게스트는 포트폴리오가 없다.

### 예외
- 링크가 꺼졌거나 없는 slug, 탈퇴한 사람의 slug: 모두 같은 404.
- 사진 장수나 크기 상한을 넘기면 422.
- 링크를 켠 채 프로필의 이름·사진을 바꾸면 공개 페이지도 바뀐다.

### 검증 방법
- 편집 화면에서 경력 둘과 사진 셋을 저장하고 다시 열면 그대로 보인다. 순서를 바꿔 저장하면 순서가
  유지된다.
- 링크를 켜고 브라우저에서 주소를 열면: 이름·프로필 사진·성별·만 나이·소개글·경력·포트폴리오 사진이
  보이고 연습·분석은 없다.
- 링크를 끄고 같은 주소: 404. 다시 켜면 같은 주소가 열린다. "새 링크 만들기"를 누르면 다른 주소가
  나오고 옛 주소는 404다.
- 링크를 켠 상태에서 탈퇴: 같은 주소가 404이고 portfolios·portfolio_credits·portfolio_photos
  행과 사진 객체가 없다.
- 열한 번째 사진 추가: 422. 10MB를 넘는 사진 추가: 422.
- 공개 페이지 주소를 열면: 응답에 noindex 메타가 있다.
- 성별이 "선택 안 함"인 회원의 공개 페이지: 성별 칸이 없다.
- 게스트 토큰으로 포트폴리오 API: 403.

### 열린 질문
- 편집 화면과 공개 페이지가 pen에 없다.

### 범위 밖
- PDF 내보내기. 공개 페이지와 같은 내용을 파일 하나로 내는 기능이며 후속에서 요구사항을 정한다.

## account.notification 알림 설정·발송
- 도입: 1.0.0
- 화면: A4 설정
- 테이블: user_profiles, push_tokens

### 기능
알림은 세 종류다. 서버가 보내는 푸시 둘(분석 완료, 챌린지 활동)과 폰이 스스로 울리는 알람(밤 10시
연습 리마인드). 설정에 토글이 셋 있다. 분석 완료 푸시, 챌린지 알림, 저녁 리마인드. 토글은 프로필에
저장해 폰을 바꿔도 유지된다. 알림은 앱에만 있고 웹에는 없다.

### 의도
분석은 몇 분 걸려서 배우가 앱을 닫는다. 끝났을 때 불러야 대화로 이어진다. 연습이 뜸한 날 저녁에
한 번 살짝 부르면 돌아온다. 리마인드는 서버 없이 폰이 하도록 두어 인터넷과 서버 상태에 기대지
않는다.

### 목적
분석이 끝난 순간 배우가 알고, 연습 안 한 날 저녁에 한 번 떠올리며, 끄고 싶으면 한 번에 꺼진다.

### 규칙·제약
- 푸시 토큰은 폰이 알림 권한을 허용하면 등록한다. 한 사람에 폰 여러 대, 1:N이다.
- 토글 셋의 기본값은 모두 켜짐이다. 알림 권한을 허용한 사람은 설정을 건드리지 않아도 바로 받는다.
- 토큰을 지우는 때: 로그아웃, 탈퇴, 푸시 토글 둘을 다 끔, 발송 결과가 "등록되지 않은 기기"일 때.
  잘못된 토큰이 쌓이지 않게 한다. 토글 하나만 꺼져 있으면 토큰은 두고 서버가 보내기 전에 프로필의
  토글을 읽어 거른다. 둘 중 하나를 다시 켜면 앱이 이 폰의 토큰을 다시 등록한다.
- 분석 완료 푸시는 분석이 끝나는 순간 그 사람의 토큰 전부에 한 번 보낸다. 토큰이 없으면 조용히
  건너뛴다. 서버는 Expo에만 맡기고 애플·구글에 직접 보내지 않는다.
- 챌린지 알림은 내 참여작의 좋아요·댓글과 참여한 챌린지의 마감이다. 어떤 사건에 언제 보내고 어떻게
  묶는지, 알림함 화면과 notifications 테이블은 challenge.notification에서 정한다. 이 절은 토글과
  토큰만 맡는다.
- 저녁 리마인드는 폰이 앞으로 30일치 밤 10시 알람을 맞춘다. 그날 연습하면 그날 알람을 끄고, 앱을
  열 때마다 30일치를 다시 맞춘다. 30일 동안 앱을 안 열면 알람도 멈춘다. 서버와 토큰은 쓰지 않는다.
  iOS는 앱마다 예약 알림을 64개까지만 두므로 30일치가 그 안에 든다.
- 리마인드 토글을 끄면 알람을 전부 취소한다. 켜면 다시 30일치를 맞춘다.
- 디자인의 설정 화면(A4)은 토글 하나에 "저녁 8시"라 토글 셋, 밤 10시로 맞춰야 한다.
- OS 알림 권한이 꺼져 있으면 토글을 켜도 알림이 오지 않는다. 화면은 권한 설정으로 안내한다.
- 광고성 알림은 1.0.0 범위 밖이다. 넣으려면 별도 수신 동의와 밤 9시 이후 전송 제한이 필요하다.
  밤 10시 리마인드는 서비스 알림이라 이 제한 밖이지만, 문구에 이벤트나 홍보를 섞으면 광고성이
  되어 시간 제한에 걸린다. 리마인드 문구는 연습 권유만 담는다.

### 예외
- 발송에 실패해도 분석 완료 처리는 그대로 끝난다. 알림은 부가 기능이다.
- 로그아웃 때 토큰 삭제가 실패해도 로그아웃은 계속한다. 그동안 그 폰에 옛 계정의 알림이 올 수 있고,
  앱은 다음 실행 때 삭제를 다시 시도한다. 다음 사람이 이 폰으로 로그인하면 그 사람의 토큰으로 바뀐다.
- 탈퇴하면 토큰을 지우고 알람도 취소한다.
- 폰의 시간대가 바뀌면 알람은 폰 시각 기준 밤 10시다.

### 검증 방법
- 폰 두 대에 로그인하고 분석이 끝나면: 둘 다 알림이 온다.
- 분석 완료 토글을 끄면: 분석이 끝나도 알림이 없다. 켜면 다시 온다. 챌린지 알림 토글까지 끄면 서버에
  이 폰의 토큰이 없다.
- 챌린지 알림 토글을 끄면: 내 참여작에 좋아요가 와도 알림이 없고 분석 완료는 온다.
- 푸시 토글 둘을 끈 뒤 하나를 켜면: push_tokens 행이 다시 생기고 알림이 온다.
- Expo 발송이 실패해도: 분석 상태가 완료이고 결과가 조회된다. 토큰 없는 회원의 분석 완료: 오류 없이
  끝난다.
- 오늘 연습하면: 오늘 밤 10시 알람이 없고 내일 밤 10시는 있다.
- 30일 동안 앱을 안 열면: 31일째 저녁에 알람이 없다.
- 리마인드 토글을 끄면: 예약된 알람이 0개다.
- 로그아웃 뒤 다른 계정으로 로그인하고 첫 계정의 분석이 끝나면: 이 폰에 알림이 오지 않는다.
- Expo가 "등록되지 않은 기기"로 답하면: 그 토큰 행이 지워진다.
- 알림 권한이 꺼진 폰에서 토글을 켜면: 권한 설정 안내가 뜬다.
- 가입 직후 설정을 열면: 토글 셋이 모두 켜져 있다.

## account.logout 로그아웃
- 도입: 1.0.0
- 화면: A4 설정
- 테이블: refresh_tokens, push_tokens

### 기능
설정에서 로그아웃하면 이 기기의 세션만 끝낸다. 서버는 이 기기의 리프레시 토큰을 폐기하고 이 기기의
푸시 토큰을 지운다. 앱은 저장된 토큰을 지우고 로그인 화면으로 보낸다. 다른 기기의 세션은 그대로다.

### 의도
남의 폰이나 공용 기기에서 쓴 뒤 내 계정을 닫을 수 있어야 한다. 다른 기기까지 끊으면 폰과 태블릿을
같이 쓰는 사람이 매번 다시 로그인하게 된다. 전체 끊기는 토큰 탈취 탐지가 맡는다. (account.login)

### 목적
로그아웃한 기기에서는 다시 로그인하기 전까지 내 계정의 어떤 것도 보이지 않고 알림도 오지 않으며,
다른 기기는 영향이 없다.

### 규칙·제약
- 서버는 요청에 실린 리프레시 토큰 하나만 폐기한다. 같은 사용자의 다른 토큰은 건드리지 않는다.
- 순서는 푸시 토큰 삭제 → 리프레시 토큰 폐기 → 제공자 세션 정리(구글·카카오·네이버 SDK의 로그아웃
  호출. 애플은 없다) → 기기 토큰 삭제다. 앞 단계가
  실패해도 뒤 단계는 진행한다.
- 액세스 토큰은 만료(최대 30분)까지 살아 있다. 기기에서 지우므로 쓰이지 않고, 서버는 따로 막지
  않는다. 탈취된 액세스 토큰이 최대 30분 사는 것은 받아들인다.
- 기기에서는 토큰과 계정 캐시(이름, 동의 상태)를 지운다. 마지막 로그인 제공자 기억은 남긴다.
  대본을 비롯한 배우의 자료는 모두 서버에 있으므로 기기에서 잃는 것은 없다. 기기 자료를 전부
  지우는 것은 탈퇴다. (account.withdraw)
- 저녁 리마인드 알람은 전부 취소한다. 다시 로그인하면 다시 맞춘다. (account.notification)
- 로그아웃은 게이트 밖이다. 동의가 미결정이거나 프로필이 비어 있어도 할 수 있다. (공통 규칙)
- 웹에는 로그아웃이 없다. 게스트는 브라우저 저장소를 지우면 끝난다. (account.guest)

### 예외
- 서버 폐기 요청이 실패(네트워크·5xx)해도 기기의 토큰은 지우고 로그인 화면으로 간다. 서버의
  리프레시 토큰은 만료(30일)까지 남는다.
- 이미 폐기됐거나 모르는 리프레시 토큰으로 로그아웃: 같은 204. 멱등이다.
- 푸시 토큰 삭제가 실패해도 로그아웃은 계속한다. 그동안 옛 계정의 알림이 올 수 있으며 앱이 다음 실행
  때 삭제를 다시 시도한다. (account.notification)
- 서버 폐기까지 끝난 뒤 앱이 죽었으면 다음 갱신이 거부되어 로그인 화면으로 간다. 폐기 전에 죽었으면
  로그인된 채로 남는다. (account.login)

### 검증 방법
- 폰 두 대에 로그인하고 한 대에서 로그아웃: 그 폰은 로그인 화면이고 저장된 토큰이 없다. 다른 폰은
  계속 쓸 수 있고 토큰 갱신도 된다.
- 로그아웃 뒤 DB: 그 기기의 refresh_tokens 행에 revoked_at이 있고 다른 기기 행은 그대로다. 그
  기기의 push_tokens 행이 없다.
- 로그아웃 뒤 옛 리프레시 토큰으로 갱신: 401.
- 로그아웃 뒤 그 계정의 분석이 끝나면: 그 폰에 알림이 오지 않는다.
- 비행기 모드에서 로그아웃: 로그인 화면으로 가고 기기 토큰이 없다. 서버 행은 만료까지 남는다. 네트워크가
  돌아온 뒤 앱을 열면: 서버에 그 폰의 푸시 토큰이 없다.
- 같은 리프레시 토큰으로 로그아웃을 두 번: 둘 다 204.
- 로그아웃 뒤 예약된 리마인드 알람: 0개.
- 로그아웃 뒤 앱을 다시 열면: 마지막 제공자 버튼이 강조돼 있다. 다시 로그인하면 대본과 연습이
  그대로 보인다.
- 동의를 아직 결정하지 않은 상태에서 로그아웃: 204다.

## account.guest 웹 체험과 앱으로 옮기기
- 도입: 1.0.0
- 결정 기록: ADR-028
- 화면: 게스트 시작 안내, 기능별 동의 시트, 이관 코드, 옮긴 뒤 안내, 앱의 코드 입력과 기억 선택 팝업(모두 미설계)
- 테이블: users, user_identities, refresh_tokens, user_consents, consent_documents, guest_transfer_codes(ERD에 추가), practices, videos, scripts, reading_sessions, line_memorization, ai_jobs, actor_memories

### 기능
웹에는 로그인이 없다. 처음 보호 기능을 쓰려 하면 서버가 게스트 계정을 만들고 브라우저에 토큰을
준다. 동의는 시작할 때 받지 않고, 기능을 처음 쓰는 순간 그 기능에 필요한 문서만 시트로 받는다.
게스트는 웹의 연습·리딩 기능을 바로 쓰고 자료는 그 게스트 계정에 쌓인다. 웹이 보여 주는
이관 코드를 앱에서 로그인한 계정에 넣으면 게스트의 자료가 그 계정으로 옮겨지고 게스트 계정은
닫힌다.

### 의도
웹은 설치 없이 바로 써 보는 자리다. 로그인이 첫 화면을 막으면 체험이 끊긴다. 그런데 분석은
서버에서 돌고 영상은 서버에 있어야 하므로, 주인 없는 자료 대신 게스트라는 주인을 둔다. 옮기기는
복사가 아니라 주인 바꾸기라 영상·분석·대화가 그대로 따라간다.

### 목적
배우가 웹에서 바로 촬영·분석까지 해 보고, 앱을 깔아 로그인한 뒤 코드 하나로 그 연습을 이어 본다.

### 규칙·제약
- 게스트 계정은 보통의 users 행이고, user_identities에 provider=guest, provider_uid=서버가 만든
  난수로 신원을 둔다. 게스트 여부는 신원이 guest뿐인 것으로 판정하며 users에 컬럼을 늘리지 않는다.
- 게스트는 랜딩·동의 문서 페이지·입시 정보 같은 공개 화면에는 필요 없다. 처음 보호 기능(연습 시작, 대본 등록)을
  쓰려 할 때 만든다.
- 브라우저는 게스트의 리프레시 토큰을 저장한다. 토큰 구조와 갱신·만료는 account.login과 같다.
  브라우저 저장소를 지우면 게스트에 다시 닿을 수 없다. 화면은 "앱으로 옮기기 전에는 이 브라우저에서만
  볼 수 있어요"를 보여 준다.
- 동의는 기능별이다. 보호 기능마다 필요한 문서를 정해 두고, 게스트가 그 기능을 처음 쓰려 할 때 아직
  결정하지 않은 문서만 시트로 받는다. 시트는 문서 제목과 "보기"만 두고 전문은 시트 위에 띄운다(pen의
  약관 접힘 동작 메모). 선택 문서는 묻지 않고 프로필 게이트는 면제한다. (공통 규칙)
- 게스트의 첫 동의 시트에는 "만 14세 이상이에요" 확인 줄을 둔다. 확인하지 않으면 동의 버튼이 켜지지
  않고, 서버도 확인 없는 동의 제출을 422로 거절한다. 확인 시각은 게스트의 users 행에 남긴다. 게스트는
  생년월일을 내지 않으므로 이것이 만 14세 미만을 거르는 유일한 장치다. 회원은 생년월일로 거르므로 이
  줄이 없다. (account.profile)

  | 기능 | 필요한 문서 |
  |---|---|
  | 연습(촬영·업로드·분석·코치 대화·노트) | 이용약관, 개인정보 수집·이용 동의, AI 분석 동의 |
  | 리딩(대본 등록·리딩·녹음) | 이용약관, 개인정보 수집·이용 동의 (결정 필요: 녹음을 AI로 대조하면 AI 분석 동의도) |
  | 랜딩, 동의 문서 페이지, 입시 정보 | 없음 |

- 서버는 요청마다 그 기능의 문서가 결정됐는지 본다. 빠진 문서가 있으면 403과 빠진 문서 목록을
  돌려주고, 웹은 그 목록으로 시트를 띄운 뒤 같은 요청을 다시 보낸다. 회원(앱)은 가입 때 문서를 모두
  결정하므로 이 시트가 뜰 일이 없다.
- 게스트는 연습·리딩을 쓴다. 챌린지는 보기와 참여 모두 회원만이고 앱에만 있다.
- 남용 제한: 게스트 만들기는 IP당 시간당 10개, 게스트의 분석 요청은 게스트당 하루 3회다.
- 이관 코드는 웹이 요청하면 서버가 6자리 숫자를 만들어 해시로 저장한다. 10분 유효, 한 번 쓰면 끝,
  새로 요청하면 이전 코드는 무효다. 게스트마다 살아 있는 코드는 하나다.
- 옮기기: 앱에서 로그인한 회원이 코드를 넣으면 서버는 user_id 컬럼이 있는 게스트의 모든 자료
  행(videos, practices, scripts, reading_sessions, line_memorization, ai_jobs 등)의 user_id를 회원으로
  바꾼다. 분석·대화·노트·녹음은 그 행에 매달려 함께 따라간다. 동의 기록은 게스트 행에 남긴다. 배우 기억은 회원 것이 없으면
  옮기고, 둘 다 있으면 앱이 팝업으로 어느 쪽을 둘지 묻는다. 기본은 회원 것이며 고른 쪽만 남는다.
- 옮기기는 한 트랜잭션이다. 끝나면 게스트 계정을 deactivated로 닫고 신원 행과 게스트 토큰을 지운다.
  웹은 "옮겼어요" 안내와 새로 시작 버튼을 보여 준다.
- 회원 계정은 여러 게스트를 차례로 받을 수 있다. 게스트 하나는 한 번만 옮겨진다.
- 옮긴 연습은 회원의 연습 목록에 시간순으로 섞여 보이고 따로 표시하지 않는다.
- 옮기지 않은 게스트는 마지막 활동 30일 뒤 탈퇴와 같은 절차로 파기한다. (account.withdraw) 게스트는
  챌린지를 쓰지 않으므로 다른 사람의 화면에 얽힌 행이 없다. 연습·분석·대화 행은 탈퇴와 같이 사람과
  끊어 남긴다. 게스트 신원은 해시 없이 행째 지운다.
- 게스트 토큰은 웹에서만 쓴다. 앱이 게스트를 만드는 길은 없다.

### 예외
- 코드가 틀리거나 만료·사용됐으면 같은 404. 화면 문구는 "코드가 맞지 않거나 만료됐어요". 틀린
  시도는 회원당 분당 5회로 제한한다.
- 게스트 토큰이 만료(30일)되면 그 게스트에 다시 닿을 수 없고 자료는 파기 일정대로 사라진다.
- 옮기기 도중 실패하면 아무것도 옮겨지지 않고 코드는 살아 있다.
- 게스트가 분석 중일 때 옮기면 진행 중 작업도 따라가고, 완료 알림은 회원의 폰으로 간다.
- 회원이 웹을 열어도 게스트다. 회원 자료는 웹에서 보이지 않는다. 1.0.0은 이를 받아들인다. 현재
  웹으로 로그인해 쓰던 사람은 배포 뒤 웹 세션이 끝나고 자료는 계정에 그대로 있다.

### 검증 방법
- 새 브라우저로 웹 랜딩과 동의 문서 페이지를 열면: users 행이 생기지 않는다. 연습 시작을 누르면: users 행과
  provider=guest 신원이 생기고 브라우저에 리프레시 토큰이 있다. 로그인 화면은 없다.
- 새 게스트가 연습 시작을 누르면: 시트에 이용약관, 개인정보 수집·이용 동의, AI 분석 동의 셋이 나온다.
  시트를 닫고
  분석 요청: 403과 빠진 문서 셋. 셋에 동의하면 프로필 입력 없이 허용된다.
- 그 뒤 리딩을 시작하면: 시트가 뜨지 않는다. 반대로 새 게스트가 리딩부터 시작하면: 시트에 둘만
  나오고, 이어서 연습을 시작하면 AI 분석 동의 하나만 나온다.
- 확인 줄을 누르지 않으면: 동의 버튼이 꺼져 있다. 확인 없이 동의 API를 부르면: 422. 확인하고 동의하면:
  users.age_confirmed_at이 찬다.
- 시트에서 "보기"를 누르면: 전문이 시트 위에 뜨고 뒤 화면은 스크롤되지 않는다.
- 게스트로 연습 하나를 끝내고 코드를 받아 앱에서 입력: 회원의 연습 목록에 그 연습이 영상·분석·
  대화·노트와 함께 보인다. DB에서 videos·practices·ai_jobs 행의 user_id가 회원이고 게스트 users 행은
  deactivated다.
- 같은 코드를 다시 입력: 404. 발급 11분 뒤 입력: 404. 새 코드를 받은 뒤 옛 코드: 404.
- 틀린 코드를 1분 안에 6번: 여섯 번째는 429.
- 브라우저 저장소를 지우고 다시 열면: 새 게스트가 생기고 이전 연습은 보이지 않는다.
- 마지막 활동 31일 지난 게스트: 파기 뒤 영상 객체가 없고 users 행은 deactivated다.
- 한 IP에서 한 시간에 게스트 11개: 열한 번째는 429. 한 게스트가 하루 4번째 분석: 429.
- 게스트 토큰으로 챌린지 목록·참여 API: 403.
- 기억이 있는 회원 계정에 기억이 있는 게스트를 옮기면: 팝업이 뜬다. 웹 것을 고르면 회원의 옛 기억이
  지워지고 게스트 기억이 회원 것이 된다. 회원 것을 고르면 게스트 기억은 버려진다.
- 옮긴 뒤 웹을 새로 고치면: "옮겼어요" 안내와 새로 시작 버튼이 보이고 옛 게스트 토큰은 401이다.
- 게스트로 대본을 올리고 리딩 회차를 하나 끝낸 뒤 옮기면: 회원의 대본 목록에 그 대본과 회차·녹음이
  보인다.
- 옮기기를 중간에 실패시키면: 어느 행의 user_id도 바뀌지 않고 같은 코드로 다시 성공한다.
- 분석 중에 옮기면: 완료 푸시가 회원의 폰에 온다. 한 회원이 게스트 둘을 차례로 옮기면: 둘 다 목록에
  보인다.

### 범위 밖
- 웹 로그인. 회원도 웹에서는 게스트이고 회원 자료는 앱에서만 본다.
- 앱에서 웹으로 옮기기.

### 열린 질문
- 웹 화면 넷(게스트 시작 안내, 기능별 동의 시트, 이관 코드, 옮긴 뒤 안내)과 앱 화면 둘(코드 입력, 기억
  선택 팝업)이 pen에 없다.

## account.withdraw 탈퇴
- 도입: 1.0.0
- 결정 기록: ADR-029
- 화면: A5
- 테이블: users, user_profiles, user_identities, refresh_tokens, push_tokens, actor_memories, videos, reading_recordings, challenge_entries, ai_jobs, portfolios, portfolio_credits, portfolio_photos, guest_transfer_codes, user_consents, user_profile_directions, entry_comments, entry_likes

### 기능
설정에서 탈퇴하면 계정을 쓸 수 없게 하고, 바로 알아보게 하는 정보는 파기하며, 나머지는 사람과
끊어 남긴다. 연습 기록과 다른 사람의 화면에 얽힌 행은 지우지 않는다. 같은 제공자로 다시 로그인하면
처음 가입과 똑같이 새 계정이 만들어지고, 이전 계정의 데이터는 새 계정으로 옮기지 않는다. 제공자 연결
해제를 포함한다.

### 의도
챌린지 댓글과 집계처럼 다른 사람의 화면에 얽힌 행을 지우면 남의 댓글 흐름과 집계가 깨진다. 행은
남기고 사람만 지운다. 재가입을 처음처럼 단순하게 두어 돌아오는 길을 막지 않는다.

### 목적
탈퇴한 사람의 신원·연락처·얼굴이 서비스에 남지 않고, 다른 사용자의 화면은 그대로다. 돌아오면
새 계정으로 처음부터 시작한다.

### 규칙·제약
- 파기 대상(바로 알아보게 하는 것): users의 이메일, 프로필의 이름·사진·소개, 신원(user_identities의
  provider_uid와 애플 토큰), 리프레시·푸시 토큰, 살아 있는 이관 코드, 포트폴리오·경력·사진. 소개는
  자유 글이라 실명이 들어갈 수 있어 지운다. 신원 행은 아래 해시만 남긴다. 파기와 상태 전환은 한
  트랜잭션이다.
- 제공자 연결 해제: 애플은 로그인 때 저장해 둔 토큰으로 서버가 폐기한다(App Store 필수). 카카오는
  어드민 키로 서버가 연결을 끊는다(카카오 정책 필수). 구글과 네이버는 서버가 ID 토큰만 받으므로 앱이
  탈퇴 요청 직전에 SDK의 연결 해제를 부른다. 앱의 해제가 실패해도 탈퇴는 진행한다.
- 서버 해제에 필요한 값(애플 토큰, 카카오 대상 ID)은 파기 전에 비동기 작업 장부(ai_jobs)의 재시도
  작업에 암호화해 옮긴다. 해제가 성공하거나 7일이 지나면 그 작업과 값을 지운다. 처리방침에 적는다.
- 신원 해시: 탈퇴할 때 신원마다 서버 비밀키로 만든 HMAC(provider, provider_uid)을
  user_identities.uid_hash에 채우고 provider_uid는 비운다. 행은 탈퇴 3년 뒤 지운다. 해시만으로는
  사람을 알아보지 못하고 같은 제공자 계정이 다시 오는지만 안다. 처리방침에 적는다.
- 같은 제공자 계정으로 다시 로그인하면 새 계정이다. 서버는 해시로 옛 계정을 찾지 않고, 옛
  연습·노트·기억·영상을 옮기지 않으며, 이전 계정에 관해 아무것도 묻거나 보여 주지 않는다. 해시는 아래
  철회 요청에서만 쓴다.
- 보관 동의의 철회 창구는 개인정보 처리방침의 연락처다. 요청자가 같은 제공자로 로그인해 둔 계정의
  신원과 옛 계정의 해시를 운영자가 대조해 본인을 확인한 뒤 영상·녹음을 파기하고 동의를 철회로
  기록한다. 앱 안에 철회 화면은 없고 운영 도구도 만들지 않는다. 요청이 드물 것이므로 개발자가 DB에서
  직접 처리하는 절차를 운영 문서로 남긴다.
- 가명처리해 남기는 것: 성별·연령대·추구하는 방향·경력·목표와 배우 기억. 생년월일은 5세 단위
  연령대로 뭉개고 원래 값은 지운다. 알림 토글은 끈다. 통계·연구 목적이며 처리방침에 적는다.
- 사람과 끊어 남기는 것: users 행(상태 deactivated, 탈퇴 시각), 연습·분석·대화·노트 행, 받아쓰기
  텍스트, 챌린지 참여 기록과 좋아요·댓글. 남은 행은 어느 사람과도 이어지지 않는다.
- 영상 파일과 녹음: 얼굴과 목소리는 가명처리가 안 되므로 기본은 파기한다. "탈퇴 후 영상·녹음
  보관·활용" 선택 동의를 한 사람 것만 탈퇴 후 3년 동안 남기고, 기간이 끝나거나 동의를 철회하면
  파기한다. 더 쓰려면 재동의를 받는다. 동의 문서에 적는 목적은 서비스 개선과 AI 모델 학습 둘 다다.
- 챌린지 참여작은 탈퇴 즉시 비공개로 바꿔 목록에서 내린다. 행은 지우지 않는다.
- 진행 중인 비동기 작업(분석·기억 갱신)은 취소한다.
- 앱은 서버 파기가 성공한 뒤 이 기기에 저장된 계정 자료(토큰, 캐시, 내려받은 파일)를 전부 지운다.
- 이미 발급된 액세스 토큰은 만료까지 살아 있으므로 요청마다 상태를 확인해 403으로 막는다. 탈퇴 API만
  예외로 탈퇴한 계정의 토큰을 받아 멱등하게 처리한다. 탈퇴 도중 앱이 죽어 다시 누른 경우를 위해서다.
- 재가입은 즉시 가능하고 유예 기간은 없다. 복구 요청은 받지 않는다. 실수 탈퇴는 화면의 두 번 확인으로
  막는다. 탈퇴 화면은 "연습·노트는 돌아오지 않아요"를 확인받는다.
- 백업 덤프에는 파기 전 데이터가 30일 남는다. 개인정보 처리방침에 적는다.
- 탈퇴 화면(A5)의 안내는 이렇게 맞춘다. 지워지는 것: 이메일·이름·사진·소개, 포트폴리오와 공유 링크,
  소셜 로그인 연결, 영상과 녹음(보관에 동의했으면 3년 뒤), 이 기기의 자료. 남는 것: 연습 기록은 나와
  끊겨 남고, 챌린지 참여작은 비공개로 내려가며, 댓글은 "탈퇴한 사용자"로 남는다. 디자인의 현재 문구는
  커뮤니티 글 기준이라 챌린지 기준으로 바꾼다.

### 예외
- 제공자 연결 해제 호출이 실패해도 탈퇴는 완료한다. 서버 해제는 재시도 작업으로 7일 동안 다시
  시도한다. 애플 폐기는 필수라 7일 뒤에도 실패면 운영자에게 알린다.
- 탈퇴 직후 같은 제공자로 로그인: 새 계정이다. 3년이 지나 해시가 지워진 뒤에는 철회 요청의 본인
  확인을 할 수 없는데, 그때는 보관하던 영상도 이미 파기된 뒤다.
- 이미 탈퇴한 계정에 다시 탈퇴 요청: 최초 탈퇴 시각을 유지하고 파기만 다시 돈다.

### 검증 방법
- 탈퇴 뒤 DB: users 행은 남고 email이 NULL이고 status가 deactivated다. user_identities 행은
  provider_uid가 비고 uid_hash가 있으며, 리프레시 토큰은 전부 폐기, 푸시 토큰은 없다. actor_memories
  행은 남고, 그 user_id가 가리키는 users 행에는 이메일·이름·신원 값이 없다. portfolios 행이 없다.
- 탈퇴 뒤 옛 액세스 토큰으로 API 호출: 403.
- 탈퇴 뒤 같은 제공자로 로그인: 동의 화면이 처음처럼 나오고, 제출하면 새 users 행이 생기며 프로필
  게이트가 이어진다. 연습 목록은 비어 있다.
- 탈퇴한 사람의 챌린지 댓글: 남아 있고 작성자가 "탈퇴한 사용자"로 보인다.
- 탈퇴한 사람의 챌린지 참여작: 비공개로 바뀌어 목록에 없고 행은 남아 있다.
- 애플로 탈퇴 뒤 iPhone 설정의 "Apple로 로그인" 목록에서 Acttub이 사라진다. 카카오·구글·네이버도
  각 제공자의 연결된 서비스 목록에서 사라진다.
- 카카오 연결 끊기 호출이 실패해도: 탈퇴는 200이고 재시도 작업이 한 건 있다. 7일 뒤: 그 작업과
  암호화한 값이 없다.
- 탈퇴한 계정의 액세스 토큰으로 탈퇴를 다시 요청: 200이고 탈퇴 시각이 처음 값 그대로다. 같은 토큰으로
  다른 API: 403.
- 분석이 진행 중일 때 탈퇴: 작업이 취소되고 결과가 저장되지 않는다.
- 영상 보관 동의를 한 사람이 탈퇴: 영상 객체가 남고, 탈퇴 3년 뒤 파기된다. 동의하지 않은 사람이
  탈퇴: 영상 객체가 없다.
- 보관에 동의하지 않은 사람이 탈퇴: reading_recordings의 녹음 객체가 없다.
- 탈퇴한 사람의 프로필 속성 조회: 이름·사진·소개는 없고 성별·연령대·방향·경력·목표만 남아 있다.
- 영상 보관에 동의하고 탈퇴한 뒤 같은 제공자로 가입: 이전 계정에 관한 팝업이나 안내가 없다.
- 처리방침 연락처로 철회를 요청하고 같은 제공자로 로그인해 둔 뒤 운영 절차 문서대로 처리하면: 옛 영상 객체가
  없고 옛 계정의 보관 동의에 revoked 행이 는다.
- 탈퇴 3년 뒤: user_identities 행과 보관하던 영상 객체가 없다.
- 탈퇴 뒤 폰의 앱 저장소: 계정 자료 키가 하나도 없다.

### 열린 질문
- 처리방침 검토 때 법무 확인. 가명처리 보관과 동의 기반 보관의 문구, 그리고 사람과 끊어 남기는 자유
  글(배우 기억·대화·받아쓰기)에 식별 정보가 섞일 수 있다는 점.
