# 계정

[쓰는 법과 공통 규칙](00-common.md)을 먼저 읽는다.

## account.login 로그인·자동 가입
- 화면: A0, A0.1
- 테이블: users, user_identities, refresh_tokens, consent_documents, user_consents

### 기능
구글·애플·카카오·네이버 간편 로그인만 제공한다. 별도 회원가입 화면은 없다. 처음 로그인한 사람은
같은 흐름 안에서 동의 화면을 거치고, 동의를 제출하는 순간 계정이 만들어진다. 다음부터는 같은
계정으로 들어온다. 이미 있는 계정도 아직 결정하지 않은 동의 문서가 있으면 로그인 응답에 실리고,
필수·선택 동의를 모두 결정할 때까지 보호 기능은 막힌다.

### 의도
가입 절차가 있으면 첫 화면에서 이탈한다. 배우가 촬영까지 가는 길을 버튼 하나로 줄인다. 국내
사용자 대부분이 쓰는 카카오·네이버를 더해 구글·애플 계정이 없는 사람도 막히지 않게 한다.

### 목적
어떤 제공자로 들어와도 한 사람은 한 계정이고, 두 번째 로그인부터는 자기 연습·노트·기억이 그대로
보인다.

### 규칙·제약
- 계정을 찾는 순서가 계약이다. ① 제공자와 제공자 ID로 찾는다. ② 없으면 제공자가 검증했다고
  알린 이메일로 기존 계정을 찾아 그 계정에 새 신원을 붙인다. ③ 그것도 없으면 새 계정을 만든다.
  이메일은 신원이 아니라 부가 정보다. 제공자에서 이메일을 바꿔도 같은 계정이다.
- 검증 안 된 이메일이 기존 계정과 겹치면 로그인을 막고 이미 쓰는 방식으로 안내한다. 검증 안 된
  주소만 대고 남의 계정에 들어가는 것을 막기 위해서다.
- 제공자별 이메일 검증 근거: 구글·애플은 ID 토큰의 email_verified. 카카오는 ID 토큰에 검증
  여부가 없어 사용자 정보 API의 is_email_verified로 확인한다. 네이버는 검증 표시가 없다. 주소가
  @naver.com이면 그 계정의 메일함이므로 검증된 것으로 보고, 외부 메일이면 검증되지 않은 것으로
  본다. 네이버가 준 표시가 아니라 계정 구조에 따른 우리 판단이다.
- 이메일은 앞뒤 공백을 떼고 소문자로 맞춘다. 검증된 이메일만 저장한다. 이메일 없는 계정도
  정상이다.
- 클라이언트는 제공자가 발급한 ID 토큰을 서버에 넘기고, 서버가 제공자 공개키로 검증한다. 네
  제공자 모두 OpenID Connect ID 토큰을 발급한다. 카카오·네이버는 개발자 콘솔에서 OIDC를 켜야
  한다. 애플 로그인 요청에는 authorization code를 함께 보낸다. 서버는 이를 애플 토큰으로 바꿔
  user_identities에 암호화해 저장하고, 탈퇴 때 폐기 API에 쓴다.
- provider 허용값은 google, apple, kakao, naver와 개발용 development다.
- 제공자 제공 범위: iOS와 웹은 넷 다. 안드로이드는 애플을 뺀 셋.
- 앱과 웹은 제공자마다 같은 애플리케이션 등록을 쓴다. 네이버와 카카오의 사용자 ID는 애플리케이션
  단위로 발급되므로 등록을 나누면 같은 사람이 다른 신원이 된다. 애플은 같은 팀이면 앱과 웹의 ID가
  같다.
- 같은 신원으로 동시에 두 요청이 오면 하나만 계정을 만들고 다른 하나는 그 계정을 쓴다.
- 계정 행은 필수 동의를 모두 받은 순간 만든다. 그 전에는 제공자 신원과 이메일을 저장하지 않고, 동의
  화면을 위한 짧은 가입 토큰만 발급한다. 동의 화면에서 나가면 아무것도 남지 않는다. 동의 없이
  개인정보를 갖고 있지 않기 위해서다.
- 동의 게이트는 요청마다 DB의 동의 상태로 판정한다. 로그인을 다시 하거나 토큰을 갱신해도 결정하지
  않은 문서가 하나라도 있으면 보호 기능은 막힌다. 필수 문서는 동의만 할 수 있고 화면에 거절이
  없다. 선택 문서는 동의와 거절 중 하나를 고르며, 거절도 결정이다.
  갱신 응답에는 동의 목록이 없으므로 앱은 시작할 때 미결정 동의를 조회한다. 동의 다음에는
  프로필 입력이 같은 게이트로 이어진다. (account.profile)
- 폰에 마지막 로그인 제공자를 기억해 두고 로그인 화면에서 그 버튼을 강조한다. 앱을 지우면 기억도
  사라진다. 서버는 관여하지 않는다.
- 로그인 때 제공자가 검증된 이메일을 주면 users.email을 그 값으로 갱신한다. 다른 계정이 이미 쓰는
  주소면 그대로 둔다.
- 액세스 토큰은 30분, 리프레시 토큰은 30일이다. 갱신할 때마다 리프레시 토큰을 새로 주고 옛 것은
  소진된다. 소진된 토큰이 다시 오면 탈취로 보고 그 사용자의 세션을 전부 끊는다.
- 액세스 토큰이 만료되면 앱이 리프레시로 한 번 갱신하고 요청을 다시 보낸다. 서버가 리프레시를
  거부하면 기기의 토큰을 지우고 로그인 화면으로 보낸다. 네트워크 오류는 로그아웃 사유가 아니다.
- 30일 동안 앱을 한 번도 열지 않으면 다시 로그인해야 한다.

### 예외
- 제공자 토큰이 잘못됐거나 만료됐으면 401. 지원하지 않는 제공자는 400. 제공자 설정이 없으면 503.
- 이메일 겹침은 409. 화면 문구는 "이미 OO로 가입한 이메일이에요".
- 애플 '이메일 가리기'로 가입한 사람이 나중에 다른 제공자로 들어오면 계정이 둘이 된다. 1.0.0은
  이를 받아들인다.
- 애플로만 가입한 사람은 안드로이드에서 로그인할 수 없다. 1.0.0은 이를 받아들인다.
- 카카오·네이버는 이메일을 선택 동의로 받으므로 사용자가 동의하지 않을 수 있다. 그 계정은 이메일
  없이 만들어지고, 나중에 다른 제공자로 들어와도 이어지지 않는다.
- 제공자가 준 이름은 미리 채우는 값으로만 쓰고, 표시 이름은 프로필 설정에서 직접 입력받는다.
  애플은 이름을 첫 로그인 한 번만 주므로 그때 받은 값을 프로필 화면까지 넘긴다. (account.profile)
- 첫 로그인의 동의 화면에서 나가면 계정이 만들어지지 않는다. 다시 로그인하면 동의 화면부터
  시작한다. 이미 있는 계정에 새 필수 문서가 생기면 동의할 때까지 보호 기능만 막히고 계정은
  그대로다. 동의하지 않았다는 이유로 계정을 지우지 않는다.
- 탈퇴한 계정으로 다시 로그인하면 새 계정이 된다. 이전 연습·노트·기억은 보이지 않는다.
- 제공자 쪽에서 연결을 끊거나 제공자 회원을 탈퇴하면 그 신원만 지운다. 네이버는 연결 끊기
  콜백으로 알려 준다. 계정은 남으므로 검증된 이메일이 있으면 다른 제공자로 이어질 수 있다.
- 소진된 리프레시 토큰이 다시 오면 탈취로 보고 그 사용자의 세션을 전부 끊는다. 앱이 갱신 중에
  죽어 새 토큰을 저장하지 못하고 옛 토큰으로 다시 시도한 정상 사용자도 같은 일을 겪는다. 보안을
  위해 감수하는 부작용이며, 다시 로그인하면 된다.
- 기기마다 리프레시 토큰이 따로 있어 여러 기기를 함께 써도 서로 영향이 없다.

### 검증 방법
- 제공자 넷 각각 첫 로그인: 응답에 동의 문서와 가입 토큰이 실리고 users·user_identities 행은 아직
  없다. 동의를 제출하면 행이 하나씩 생기고 액세스·refresh 토큰이 발급된다. 두 번째 로그인: 행이
  늘지 않고 같은 계정이다.
- 구글로 만든 계정과 같은 검증된 이메일로 애플 로그인: 같은 계정으로 들어가고 user_identities 행이
  하나 더 생긴다. users 행은 늘지 않는다.
- 구글로 만든 계정과 같은 @naver.com 주소로 네이버 로그인: 위와 같다.
- 외부 메일로 바꾼 네이버 계정이 기존 계정과 같은 주소로 로그인: 409와 안내 문구. 계정은 늘지
  않는다.
- 이메일 동의 없이 카카오 로그인: email이 비어 있는 계정이 생기고 로그인은 성공한다.
- 탈퇴 뒤 같은 제공자로 로그인: 새 users 행이 생기고 이전 데이터가 보이지 않는다.
- 잘못된 토큰은 401, 지원하지 않는 provider는 400.
- 동의 문서 중 아직 답하지 않은 것이 있는 상태에서 연습 API 호출: 차단된다.
- 필수 문서에 모두 동의했지만 선택 문서에 아직 답하지 않은 상태에서 연습 API 호출: 차단된다.
  선택 문서에 거절을 고르면 허용된다.
- 필수 문서에 거절을 보내면: 422. 화면에는 거절 버튼이 없다.
- 첫 로그인의 동의 화면에서 나간 뒤 DB: users·user_identities 행이 없다. 다시 로그인하면 동의
  화면이 나온다.
- 기존 계정에 새 필수 문서 버전이 발행된 뒤 로그인: 로그인은 되고 연습 API는 차단, 동의하면
  같은 토큰으로 허용된다.
- 미결정 동의가 있는 채로 토큰을 갱신한 뒤 연습 API 호출: 차단된다. 모두 결정하면(선택 문서는
  거절해도 된다) 같은 토큰으로 허용된다.
- 앱에서 만든 계정으로 웹에서 같은 제공자로 로그인: 제공자 넷 각각 같은 계정이다.
- 카카오로 로그인한 뒤 로그아웃하고 앱을 다시 열면: 카카오 버튼이 강조돼 있다.
- 제공자에서 이메일을 바꾼 뒤 로그인: 같은 계정이고 users.email이 새 주소다. 새 주소를 다른 계정이
  쓰고 있으면 옛 주소가 남는다.
- 만료된 액세스 토큰으로 보호 API 호출: 갱신 뒤 요청이 성공하고 새 리프레시 토큰이 온다. 옛
  리프레시 토큰으로 다시 갱신: 401이고 그 사용자의 다른 기기도 다음 갱신 때(최대 30분 안) 로그인
  화면으로 돌아간다.
- 리프레시 토큰이 만료되거나 폐기된 상태에서 앱을 열거나 API 호출: 기기의 토큰이 지워지고 로그인
  화면이 뜬다.
- 갱신 요청이 네트워크 오류로 실패: 로그아웃되지 않고 오류가 표시되며 다음 요청에서 다시 갱신한다.
- 운영 전 확인: 카카오·네이버는 검수 승인 뒤에만 운영에서 켠다. 승인 전에는 등록한 테스트
  계정만 로그인된다. 운영 배포 체크리스트에 넣는다.

### 범위 밖
- 설정에서 로그인 방식 연결. 로그인한 상태에서 두 번째 제공자로 인증해 같은 계정에 신원을 붙이는
  기능. 폰을 바꿔 마지막 로그인 방식 기억이 사라진 경우와 애플 이메일 가리기로 갈린 계정까지
  해결한다. 후속.
- 안드로이드의 애플 로그인.

## account.profile 프로필
- 화면: A0.2, A4 프로필
- 테이블: user_profiles

### 기능
이름, 성별, 나이, 추구하는 방향(복수 선택), 연기 경력, 최종 목표 여섯을 모두 입력받는다. 전부
필수다. 처음 로그인했거나 이 중 하나라도 비어 있으면 입력 화면을 보여 주고, 다 채울 때까지 보호
기능을 쓸 수 없다. 동의와 같은 게이트이며 동의를 모두 결정한 다음에 이어진다. 채운 뒤에는
설정에서 같은 항목을 고칠 수 있다.

### 의도
코치가 배우를 알고 시작해야 한다. 성별·나이·방향·경력·목표는 매 연습마다 묻지 않고 한 번 받아
프로필에 두며, 코치 대화와 노트가 이것을 읽는다. 1.0.0 이전 가입자는 닉네임만 있어서, 빠진
항목을 첫 로그인 때 같은 화면으로 받는다.

### 목적
첫 연습부터 코치가 배우의 방향과 경력에 맞춰 말하고, 배우는 같은 것을 두 번 입력하지 않는다.

### 데이터
| 항목 | 형식 | 필수 |
|---|---|---|
| 이름 | 실명 또는 활동명 텍스트 | 필수 |
| 성별 | 여성 · 남성 · 선택 안 함 | 필수 |
| 나이 | 생년월일로 저장하고 만 나이는 계산해서 보여 준다. 만 14세 미만은 가입할 수 없다 | 필수 |
| 추구하는 방향 | 매체(TV·영화) · 무대(연극·뮤지컬) 중 복수 선택 | 하나 이상 |
| 연기 경력 | 입문 전 · 입시생 · 1년 미만 · 1–3년 · 3–5년 · 5년 이상 | 필수 |
| 최종 목표 | 취미 · 공연·오디션 · 전문 배우 | 필수 |

값 목록은 pen의 A0.2 화면 선택지다. "선택 안 함"도 하나의 값이라 필수를 만족한다. 디자인의 나이
칸은 출생연도인데 이 문서는 생년월일로 정했으므로 디자인을 맞춰야 한다.

### 규칙·제약
- 만 14세 미만은 프로필을 저장할 수 없고 가입이 끝나지 않는다. 법정대리인 동의가 필요한 나이라
  1.0.0은 받지 않는다. 생년월일은 나중에 고칠 수 있되 고친 값도 같은 기준을 지난다.
- 여섯 항목 모두 설정에서 언제든 고칠 수 있다. 고칠 때도 필수 규칙은 같아서 비워서 저장할 수 없다.
  고친 값은 바로 저장되고 다음 코치 대화부터 반영된다.
- 게이트 순서는 동의 → 프로필이다. 개인정보를 받기 전에 수집 동의가 끝나 있어야 한다.
- 개인정보 수집·이용 동의 문서의 필수 항목은 이 여섯 항목과 같다. 문서에는 항목마다 코칭에 쓰이는
  이유를 한 줄씩 적는다. 필수로 받을 수 있는 것은 서비스 제공에 실제로 쓰이는 항목뿐이고, 그
  입증은 우리 몫이다. 광고성 정보 수신과 탈퇴 후 영상 보관은 선택으로 남긴다.
- 항목을 늘리거나 선택을 필수로 바꾸면 동의 문서를 새 버전으로 낸다. 기존 사용자는 동의 게이트로
  다시 받는다.
- 게이트는 요청마다 DB의 프로필 상태로 판정한다. 필수 항목이 하나라도 비어 있으면 토큰을
  갱신해도 보호 기능은 막힌다.
- 제공자가 준 이름은 이름 칸을 미리 채우는 값으로만 쓴다. 저장되는 것은 배우가 확인한 값이다.
- 성별·나이는 프로필이 정본이다. 배우 기억(actor_memories)에는 두지 않는다. (ERD 결정)
- 프로필은 본인만 본다. 챌린지 등 공개 화면에 보이는 항목은 그 기능에서 따로 정한다.
- 사진과 소개는 선택 항목이며 설정에서만 받는다. 가입 게이트의 입력 화면에는 없다.

### 예외
- 입력 도중 앱을 닫으면 다음 로그인 때 입력 화면을 처음부터 다시 시작한다. 여섯 항목을 한 번에
  저장하고 부분 저장은 하지 않는다.
- 값 목록에 없는 값이 오면 422로 거절한다.
- 탈퇴하면 프로필 행은 삭제한다. (공통 규칙)

### 검증 방법
- 첫 로그인 뒤 동의를 모두 결정하면 프로필 화면이 나오고, 필수 항목을 다 채우기 전 연습 API
  호출: 차단된다. 다 채우면 같은 토큰으로 허용된다.
- 1.0.0 이전 가입자가 로그인: 프로필 화면이 나오고 닉네임이 이름 칸에 채워져 있다.
- 추구하는 방향을 둘 이상 선택해 저장: 둘 다 저장되고 다시 열면 둘 다 선택돼 있다.
- 생년월일을 저장한 뒤 조회: 만 나이가 오늘 기준으로 계산돼 온다. 생일 전날과 당일에 한 살 차이가
  난다.
- 오늘 만 14세가 되는 생년월일: 저장된다. 하루 뒤 생일인 생년월일: 422와 안내 문구가 나오고 가입이
  끝나지 않는다.
- 설정에서 여섯 항목을 각각 고치고 화면을 다시 열면 고친 값이 보인다. 항목을 비워서 저장하면 422다.
- 설정에서 항목을 고치면 다음 코치 대화가 바뀐 값을 읽는다.
- 애플로 첫 로그인: 이름 칸에 애플이 준 이름이 채워져 있고, 지우고 다른 이름을 저장할 수 있다.
- 동의 문서의 필수 항목 목록과 프로필 화면의 필수 항목이 같다. 문서에 없는 항목을 화면이 필수로
  받지 않는다.

## account.notification 알림 설정·발송
- 화면: A4 설정
- 테이블: user_profiles, push_tokens

### 기능
알림은 두 종류다. 서버가 보내는 푸시(분석 완료)와 폰이 스스로 울리는 알람(밤 10시 연습 리마인드).
설정에 토글이 둘 있다. 분석 완료 푸시와 저녁 리마인드. 토글은 프로필에 저장해 폰을 바꿔도 유지된다.
앱에만 있고 웹에는 알림이 없다.

### 의도
분석은 몇 분 걸려서 배우가 앱을 닫는다. 끝났을 때 불러야 대화로 이어진다. 연습이 뜸한 날 저녁에
한 번 살짝 부르면 돌아온다. 리마인드는 서버 없이 폰이 하도록 두어 인터넷과 서버 상태에 기대지
않는다.

### 목적
분석이 끝난 순간 배우가 알고, 연습 안 한 날 저녁에 한 번 떠올리며, 끄고 싶으면 한 번에 꺼진다.

### 규칙·제약
- 푸시 토큰은 폰이 알림 권한을 허용하면 등록한다. 한 사람에 폰 여러 대, 1:N이다.
- 토큰을 지우는 때: 로그아웃, 탈퇴, 분석 완료 토글 끔, 발송 결과가 "등록되지 않은 기기"일 때.
  잘못된 토큰이 쌓이지 않게 한다.
- 분석 완료 푸시는 분석이 끝나는 순간 그 사람의 토큰 전부에 한 번 보낸다. 토큰이 없으면 조용히
  건너뛴다. 서버는 Expo에만 맡기고 애플·구글에 직접 보내지 않는다.
- 저녁 리마인드는 폰이 앞으로 30일치 밤 10시 알람을 맞춘다. 그날 연습하면 그날 알람을 끄고, 앱을
  열 때마다 30일치를 다시 맞춘다. 30일 동안 앱을 안 열면 알람도 멈춘다. 서버와 토큰은 쓰지 않는다.
  iOS는 앱마다 예약 알림을 64개까지만 두므로 30일치가 그 안에 든다.
- 리마인드 토글을 끄면 알람을 전부 취소한다. 켜면 다시 30일치를 맞춘다.
- OS 알림 권한이 꺼져 있으면 토글을 켜도 알림이 오지 않는다. 화면은 권한 설정으로 안내한다.
- 광고성 알림은 1.0.0 범위 밖이다. 넣으려면 별도 수신 동의와 밤 9시 이후 전송 제한이 필요하다.
  밤 10시 리마인드는 서비스 알림이라 이 제한 밖이지만, 문구에 이벤트나 홍보를 섞으면 광고성이
  되어 시간 제한에 걸린다. 리마인드 문구는 연습 권유만 담는다.

### 예외
- 발송에 실패해도 분석 완료 처리는 그대로 끝난다. 알림은 부가 기능이다.
- 로그아웃 때 토큰 삭제가 실패해도 로그아웃은 계속한다. 다음 사용자가 이 폰으로 로그인하면
  그 사람의 토큰으로 바뀐다.
- 탈퇴하면 토큰을 지우고 알람도 취소한다.
- 폰의 시간대가 바뀌면 알람은 폰 시각 기준 밤 10시다.

### 검증 방법
- 폰 두 대에 로그인하고 분석이 끝나면: 둘 다 알림이 온다.
- 분석 완료 토글을 끄면: 서버에 이 폰의 토큰이 없고 분석이 끝나도 알림이 없다. 켜면 다시 온다.
- 오늘 연습하면: 오늘 10시 알람이 없고 내일 10시는 있다.
- 30일 동안 앱을 안 열면: 31일째 저녁에 알람이 없다.
- 리마인드 토글을 끄면: 예약된 알람이 0개다.
- 로그아웃 뒤 다른 계정으로 로그인하고 첫 계정의 분석이 끝나면: 이 폰에 알림이 오지 않는다.
- Expo가 "등록되지 않은 기기"로 답하면: 그 토큰 행이 지워진다.
- 알림 권한이 꺼진 폰에서 토글을 켜면: 권한 설정 안내가 뜬다.

### 열린 질문
- 챌린지 알림(좋아요·댓글·마감)을 1.0.0에 넣을지. 넣으면 토글이 하나 늘고, 알림함 화면이 필요하면
  ERD에 없는 notifications 테이블이 는다. ERD 세션 결론은 "나중에".
- 리마인드 시각을 밤 10시 고정으로 둘지, 배우가 고르게 할지. 고르면 프로필에 시각 컬럼이 는다.

## account.withdraw 탈퇴
- 화면: A5
- 테이블: users, user_profiles, user_identities, refresh_tokens, push_tokens, actor_memories, videos, reading_recordings, challenge_entries, ai_jobs

### 기능
설정에서 탈퇴하면 계정을 쓸 수 없게 하고, 바로 알아보게 하는 정보는 파기하며, 나머지는 사람과
끊어 남긴다. 행은 지우지 않는다.
같은 제공자로 다시 로그인하면 처음 가입과 똑같이 새 계정이 만들어지고, 이전 계정의 데이터는 새
계정으로 옮기지 않는다. 제공자 연결 해제를 포함한다. 애플은 토큰 폐기가 App Store 필수, 카카오는
연결 끊기가 카카오 정책 필수, 네이버는 토큰 폐기 API. 규칙은 account.login 참고.

### 의도
커뮤니티 글과 챌린지 집계처럼 다른 사람의 화면에 얽힌 행을 지우면 남의 글타래가 깨진다. 행은
남기고 사람만 지운다. 재가입을 처음처럼 단순하게 두어 돌아오는 길을 막지 않는다.

### 목적
탈퇴한 사람의 신원·연락처·얼굴이 서비스에 남지 않고, 다른 사용자의 화면은 그대로다. 돌아오면
새 계정으로 처음부터 시작한다.

### 규칙·제약
- 파기 대상(바로 알아보게 하는 것): users의 이메일, 프로필의 이름·사진·소개, 신원(user_identities),
  refresh·push 토큰. 소개는 자유 글이라 실명이 들어갈 수 있어 지운다. 파기와 상태 전환은 한
  트랜잭션이다.
- 가명처리해 남기는 것: 성별·연령대·추구하는 방향·경력·목표와 배우 기억. 생년월일은 연령대로
  뭉개고 원래 값은 지운다. 알림 토글은 끈다. 통계·연구 목적이며 처리방침에 적는다.
- 사람과 끊어 남기는 것: users 행(상태 deactivated, 탈퇴 시각), 연습·분석·대화·노트 행, 받아쓰기
  텍스트, 커뮤니티 글, 챌린지 참여 기록과 좋아요·댓글. 남은 행은 어느 사람과도 이어지지 않는다.
- 영상 파일과 녹음: 얼굴과 목소리는 가명처리가 안 되므로 기본은 파기한다. "탈퇴 후 영상·녹음
  보관·활용" 선택 동의를 한 사람 것만 동의 문서에 적힌 기간 동안 남기고, 기간이 끝나거나 동의를
  철회하면 파기한다.
- 챌린지 참여작은 탈퇴 즉시 비공개로 바꿔 목록에서 내린다. 행은 지우지 않는다.
- 진행 중인 비동기 작업(분석·기억 갱신)은 취소한다.
- 이미 발급된 액세스 토큰은 만료까지 살아 있으므로 요청마다 상태를 확인해 403으로 막는다.
- 재가입은 즉시 가능하고 유예 기간은 없다. 복구 요청은 받지 않는다. (결정 필요)
- 백업 덤프에는 파기 전 데이터가 30일 남는다. 개인정보 처리방침에 적는다.

### 예외
- 제공자 연결 해제 호출이 실패해도 탈퇴는 완료한다. 실패는 기록해 두고 재시도한다. 애플 폐기는
  필수라 실패를 그대로 두지 않는다.
- 탈퇴 화면은 "이전 연습·노트는 돌아오지 않아요"를 확인받는다.
- 탈퇴 직후 같은 제공자로 로그인: 새 계정. 같은 사람인지 서버는 알지 못한다. 신고 누적이나 차단을
  재가입으로 피할 수 있다. 차단을 유지하려면 신원의 해시를 N일 보관해야 한다. (결정 필요)
- 이미 탈퇴한 계정에 다시 탈퇴 요청: 최초 탈퇴 시각을 유지하고 파기만 다시 돈다.

### 검증 방법
- 탈퇴 뒤 DB: users 행은 남고 email이 비고 status가 deactivated다. user_identities
  행이 없고, refresh 토큰은 전부 폐기, push 토큰은 없다. 배우 기억은 남되 users 행과 마찬가지로
  사람과 이어지지 않는다.
- 탈퇴 뒤 옛 액세스 토큰으로 API 호출: 403.
- 탈퇴 뒤 같은 제공자로 로그인: 새 users 행이 생기고, 동의·프로필 게이트가 처음처럼 나오며, 연습
  목록이 비어 있다.
- 탈퇴한 사람의 커뮤니티 글: 남아 있고 작성자가 "탈퇴한 사용자"로 보인다.
- 탈퇴한 사람의 챌린지 참여작: 비공개로 바뀌어 목록에 없고 행은 남아 있다.
- 애플로 탈퇴 뒤 iPhone 설정의 "Apple로 로그인" 목록에서 Acttub이 사라진다. 카카오의 연결된
  서비스 목록에서도 사라진다.
- 분석이 진행 중일 때 탈퇴: 작업이 취소되고 결과가 저장되지 않는다.
- 영상 보관 동의를 한 사람이 탈퇴: 영상 객체가 남고, 동의를 철회하면 파기된다. 동의하지 않은
  사람이 탈퇴: 영상 객체가 없다.
- 탈퇴한 사람의 프로필 속성 조회: 이름·사진·소개는 없고 성별·연령대·방향·경력·목표만 남아 있다.

### 열린 질문
- 선택 동의 문서 "탈퇴 후 영상·녹음 보관·활용" 추가. 목적(서비스 개선·모델 학습 중 무엇), 기간,
  철회 방법을 정한다. 거절해도 서비스는 그대로다.
- 처리방침 검토 때 법무 확인. 가명처리 보관과 동의 기반 보관의 문구.
