# 챌린지

[쓰는 법과 공통 규칙](00-common.md)을 먼저 읽는다.
챌린지는 대사 한 줄과 기간이다. 배우들이 같은 대사를 연기한 영상을 올리고, 서로의 영상을 보고 좋아요·댓글을 남기며, 좋아요순
랭킹을 본다. 제품에서의 자리는 리텐션이다(PRD 부가 기능). 회원·앱 전용이고 웹 게스트에게는 없다(account.guest). 한국어 사용자에게만
탭이 보인다(현행, 대사가 모두 한국어라). 서버 도메인은 이번에 처음 생기고 앱은 목업을 실제 API로 바꾼다. 영상은 연습과 같은 videos를
쓴다(practice.record). 연기를 채점하지 않는다는 원칙은 여기서도 같다. 랭킹은 사람들의 좋아요 수이고 AI 리포트는 관찰과 차이의
설명이며, 어느 것도 연기에 점수·등급을 매기지 않는다.

## 챌린지 자료의 삭제·탈퇴

| 대상 | 참여작 삭제(본인) | 챌린지 숨김(운영) | 탈퇴 |
|---|---|---|---|
| challenges | 그대로 | status hidden | host_user_id NULL(행 유지) |
| challenge_entries | status deleted(행 유지, 랭킹·피드·프로필에서 제외), 영상은 보관함에 남음 | 그대로(챌린지가 숨겨져 안 보임) | visibility private로(행 유지, 집계에서 제외) |
| entry_likes, entry_saves | 그 참여작의 행 삭제(집계 즉시 반영) | 그대로 | 남긴다(사람과 끊김, 집계 유지) |
| entry_comments | 그 참여작의 행 삭제 | 그대로 | 남기고 "탈퇴한 사용자"로 보임 |
| entry_reports | 그대로(운영 기록) | 그대로 | 그대로 |
| entry_ai_reports | 삭제 | 그대로 | 남긴다(본인만 보던 것, 접근 차단) |
| notifications | 그 참여작에 관한 것 삭제 | 그대로 | 행째 삭제 |

게스트는 챌린지를 쓰지 않으므로 이관에 챌린지 자료가 없다.

## challenge.create 개설
- 도입: 1.0.0
- 화면: A16.2(새 대사 등록, 스토리형 3단계), A16(대사 목록의 "직접 등록하기"), A16.1(검색 결과 없음의 등록 진입)
- 테이블: challenges

### 기능
회원이 연기하고 싶은 대사 한 줄과 작품·인물, 기간을 적어 챌린지를 만든다. 기획팀이 띄우는 "오늘의 챌린지"도 같은 행이며 주최자가
없다. 기간이 끝나면 영상은 남고 랭킹만 굳는다.

### 의도
ERD는 챌린지를 "대사 한 줄 + 기간"으로, 사용자 개설과 기획팀 개설을 한 테이블에 두기로 했다. 기간 선택지를 DB가 아니라 API 검증에
두어 기획이 바꿀 수 있게 한다.

### 목적
배우가 찾는 대사가 없으면 스스로 챌린지를 열어 다른 배우를 부른다.

### 규칙·제약
- 챌린지는 대사(200자, 필수), 작품(100자, 없으면 "창작"), 인물(50자, 선택), 장면 메모(200자, 선택), 기간, 주최자(host_user_id, 기획팀은
  NULL), starts_at·ends_at, 상태(active·ended·review·hidden)를 가진다. 기간은 선택지 1주·2주 가운데 고르고 서버가 시작 시각(개설 즉시)에서
  ends_at을 계산한다. 선택지는 API 검증 상수다.
- 사용자 개설은 A16.2의 세 단계(대사 → 작품·인물·메모 → 기간)로 받고 마지막에 한 요청으로 만든다. request_id 멱등((host_user_id,
  request_id) 유일). 회원은 하루 5개까지 열 수 있고 넘으면 429 daily_challenge_limit. 같은 사람이 같은 대사(공백 정리 뒤 같은 글)로
  활성 챌린지를 이미 열었으면 422 duplicate_challenge와 기존 id.
- 개설한 사람은 자동으로 참여하지 않는다. 개설 뒤 대사·작품·기간은 고칠 수 없고 챌린지를 지울 수도 없다(다른 사람의 참여작이 매달림).
  참여작이 하나도 없는 자기 챌린지는 24시간 안에 닫을 수 있다(status ended로).
- "오늘의 챌린지"는 기획팀이 관리 경로로 만들고 featured_on(날짜)을 붙인다. 하루에 하나이고 피드(A15)의 머리에 "오늘의 챌린지 · D-N"으로
  보인다. 기간이 끝나면 다음 featured가 없는 날은 가장 최근 것이 그대로 보인다.
- 상태 전이: active → ended(ends_at 지남, 매시 도는 일) / review(신고 누적으로 운영 검토) / hidden(운영 숨김). ended·hidden은 되돌리지
  않고 같은 대사를 다시 띄우려면 새 행이다. review는 운영이 active나 hidden으로 돌린다.
- 주최자가 탈퇴하면 host_user_id를 NULL로 돌리고 행은 남긴다(ON DELETE SET NULL 의미를 애플리케이션이 수행).
- 게스트 토큰: 403 member_only(공통).

### 예외
- 대사 201자·빈 대사: 422. 기간 선택지 밖 값: 422 invalid_duration.
- 같은 요청 id 재전송: 같은 챌린지 하나.
- 하루 6번째 개설: 429 daily_challenge_limit. 자정(한국 시간) 뒤: 된다.
- 참여작이 생긴 뒤 닫기: 422 challenge_has_entries.

### 검증 방법
- 대사·작품·인물·기간 1주로 개설: challenges 1행(host_user_id 나, status active, ends_at = starts_at + 7일, featured_on NULL).
- 기간 2주: ends_at = 14일. 선택지 밖 10일: 422 invalid_duration.
- 같은 요청 id 두 번: 행 하나. 같은 대사로 다시 개설(활성 중): 422 duplicate_challenge와 기존 id. 기존이 ended인 뒤: 새 행.
- 하루 6번째: 429. 대사 201자: 422. 작품 비움: "창작"으로 저장.
- 참여작 0개인 자기 챌린지를 20시간 뒤 닫기: status ended. 25시간 뒤: 422. 참여작 1개: 422 challenge_has_entries.
- ends_at 지난 뒤 매시 잡: status ended, 참여작·랭킹은 그대로 조회된다.
- 기획팀이 featured_on 오늘로 개설: 피드 머리에 "오늘의 챌린지 · D-N"이 그 챌린지다. 내일 featured가 없음: 같은 것이 보인다.
- 주최자 탈퇴: host_user_id NULL, 행·참여작 그대로.
- 게스트 토큰으로 개설: 403 member_only.

## challenge.browse 둘러보기·랭킹
- 도입: 1.0.0
- 화면: A14·A14.1·A14.2(시작 안내), A15(챌린지 피드), A16(대사 목록·내 챌린지), A16.1(대사 검색), A17(좋아요순 랭킹), A17.1(최신순), P03(프로필 챌린지 기록)
- 테이블: challenges, challenge_entries, entry_likes

### 기능
피드에서 오늘의 챌린지 참여작을 스토리처럼 넘겨 보고, 대사 목록에서 인기·최신·검색·내가 참여한 챌린지를 찾고, 대사 상세에서 좋아요순·
최신순 랭킹을 본다. 프로필의 챌린지 기록은 내 참여작 집계다.

### 의도
좋아요순 랭킹과 "현재 1위"는 집계로 낸다(ERD). 피드가 커지면 캐시 컬럼을 더한다. 처음 들어온 사람에게 세 장의 안내(A14)를 한 번 보여 준다.

### 목적
배우가 같은 대사를 다른 배우가 어떻게 연기했는지 보고, 자기 영상이 어디쯤인지 안다.

### 규칙·제약
- 피드(A15): 오늘의 챌린지의 공개 참여작을 좋아요순으로 세로 스와이프한다. 카드에 작성자 이름(프로필 이름), 올린 시각, "오늘의
  챌린지 · D-N", 대사, 1위 참여작에는 "현재 1위 · 좋아요 N", 캡션, 조회수, 댓글 수, 공유, "나도 이 대사 연기하기"가 있다. 20개씩 이어
  받는다. 오늘의 챌린지가 없으면 가장 최근 활성 챌린지의 참여작이다.
- 대사 목록(A16): 탭 "인기"(활성 챌린지를 참여작 수·좋아요 합으로), "최신"(개설순), "내 챌린지"(내가 참여한 챌린지). 카드에 대사, 작품·
  인물·메모, 참여작 수, 좋아요 합, 참여자 얼굴 셋과 +N, "나도 이 대사 연기하기". 오늘의 챌린지가 맨 위다. 검색(A16.1)은 대사·작품·인물과
  참여자 이름을 찾고, 없으면 "직접 등록하기"로 잇는다.
- 대사 상세(A17): 참여작 수·좋아요 합·D-N, 랭킹 좋아요순(순위 1·2·3…)과 최신순(NEW 표시). 좋아요가 같으면 먼저 올린 것이 위다. 종료된
  챌린지는 랭킹이 종료 시점으로 굳는다(그 뒤 좋아요는 받되 순위에 반영하지 않음).
- 조회수는 참여작 영상이 재생을 시작할 때 1 더한다. 본인 재생은 세지 않는다. 사용자당 하루 한 번으로 세는 것은 후속이다(ERD).
- 시작 안내(A14~A14.2)는 기기당 처음 챌린지 탭에 들어올 때 한 번이다. 플래그는 기기 저장소.
- 비공개 참여작, deleted 참여작, 신고로 숨긴 참여작, hidden·review 챌린지의 참여작은 어느 목록에도 없다. 본인의 비공개 참여작은 프로필
  (P03)에서만 보인다.
- 프로필 챌린지 기록(P03): "전체 N · 공개 N · 비공개 N", 참여작마다 작품·인물, 날짜, 조회·좋아요(비공개는 "비공개 저장").
- 다른 사람의 프로필 이름·사진만 보인다(account.profile). 탈퇴한 사람의 참여작은 목록에 없다.
- 게스트: 403 member_only.

### 예외
- 오늘의 챌린지에 참여작이 없음: 피드에 챌린지 카드와 "첫 번째로 참여해 보세요"만.
- 활성 챌린지가 하나도 없음: 대사 목록이 비어 있고 등록 안내.
- 검색어 2자 미만: 검색하지 않는다.
- 조회수 증가 요청이 실패해도 재생은 된다.

### 검증 방법
- 공개 참여작 셋(좋아요 5·3·3, 3짜리 둘 중 하나가 먼저)이 있는 챌린지의 좋아요순: 5, 먼저 올린 3, 나중 3 순이고 1위 카드에 "현재 1위 ·
  좋아요 5". 최신순: 올린 순 역순, 가장 최근에 NEW.
- 비공개 참여작 하나 추가: 랭킹·피드·대사 목록 수에 없다. 본인 P03: 공개 N·비공개 1.
- 인기 탭: 참여작 수·좋아요 합이 큰 챌린지가 위, 오늘의 챌린지가 맨 위. 최신 탭: 개설순.
- "니나"로 검색: 인물이 니나인 챌린지와 참여자 이름이 니나인 챌린지가 나온다. 결과 없음: "직접 등록하기".
- 내 챌린지 탭: 내가 참여한 챌린지만.
- 다른 사람이 재생 시작: 조회수 +1. 본인 재생: 그대로.
- ended 챌린지에 좋아요 추가: 좋아요 수는 늘고 순위는 종료 시점 그대로다.
- 신고로 숨긴 참여작·deleted 참여작·hidden 챌린지: 어느 목록에도 없다.
- 두 번째로 챌린지 탭 진입: 시작 안내가 없다.
- 게스트 토큰으로 피드: 403 member_only.

## challenge.entry 참여
- 도입: 1.0.0
- 화면: A18(촬영 대기·대사 표시), A18.1(올리기·갤러리에 공유), A18.2(비공개 저장), A18.3(업로드 완료), A2.1·A2.3(보관함에서 "챌린지에 올리기"), P03
- 테이블: challenge_entries, videos

### 기능
회원이 챌린지의 대사로 촬영한 영상(또는 보관함 영상)에 캡션을 붙여 공개로 올리거나 비공개로 저장한다. 공개 참여작은 피드·랭킹에 오르고,
비공개는 나만 본다. 어느 쪽이든 AI 리포트를 받는다.

### 의도
영상은 videos를 재사용해 보관함의 영상을 그대로 챌린지로 보낼 수 있다(ERD). "저장만 하기 · 비공개"는 비공개 행이다. 한 챌린지에 여러
번 참여할 수 있어 배우가 다시 찍어 올릴 수 있다.

### 목적
배우가 부담 없이 올리고, 비공개로도 리포트를 받는다.

### 규칙·제약
- 참여작은 challenge_id·user_id·video_id·caption(200자, 선택)·visibility(public·private)·status(visible·hidden_by_report·deleted)·view_count·
  created_at을 가진다. request_id 멱등((user_id, request_id) 유일).
- 영상은 확정된 videos 행이어야 한다(video_not_ready 422). 같은 영상을 같은 챌린지에 두 번 올릴 수 없다(422 duplicate_entry). 다른 영상으로
  같은 챌린지에 여러 번 참여할 수 있다. 하루 참여는 5개까지(429 daily_entry_limit, AI 리포트 비용 때문).
- 활성 챌린지에만 참여한다. ended·review·hidden이면 422 challenge_closed.
- 공개 ↔ 비공개 전환은 언제든 된다. 비공개로 바꾸면 랭킹·피드에서 빠지고 좋아요·댓글 행은 남는다(다시 공개하면 돌아온다).
- 참여작 삭제는 status deleted(행 유지)이고 좋아요·저장·댓글·AI 리포트·알림을 지운다. 영상은 보관함에 남는다. 삭제는 되돌리지 않는다.
- 완료 화면(A18.3): 공개면 "갤러리와 대사 랭킹에 바로 반영됐어요"와 "AI 리포트 받기", 비공개면 "비공개로 저장했어요".
- 촬영 대기(A18)에서 대사를 화면에 보여 주고 촬영은 practice.record와 같다(보관함에 먼저 저장된 뒤 참여작이 된다).
- 탈퇴하면 participant의 참여작은 visibility private로 바뀌고 목록에서 빠진다(account.withdraw).

### 예외
- 같은 요청 id 재전송: 같은 참여작. 같은 영상 재참여: 422 duplicate_entry.
- 하루 6번째 참여: 429 daily_entry_limit.
- ended 챌린지 참여: 422 challenge_closed.
- 미확정 영상: 422 video_not_ready.
- 참여작 삭제 뒤 같은 영상으로 다시 참여: 된다(새 행).
- 영상이 보관함에서 지워지려 하면 practice.library의 video_in_use로 막힌다(deleted 참여작은 참조로 세지 않는다).

### 검증 방법
- 보관함 영상으로 공개 참여: challenge_entries 1행(visibility public, status visible), 랭킹·피드에 보이고 ai_jobs challenge_report 1행.
- 비공개 저장: 목록에 없고 P03에 "비공개 저장", ai_jobs는 같이 생긴다.
- 같은 요청 id 두 번: 행 하나. 같은 영상 같은 챌린지: 422 duplicate_entry. 다른 영상: 두 번째 행.
- 하루 6번째: 429. ended 챌린지: 422 challenge_closed. 미확정 영상: 422 video_not_ready.
- 공개 → 비공개: 랭킹에서 빠지고 entry_likes 행은 남는다. 다시 공개: 좋아요 수 그대로 돌아온다.
- 삭제: status deleted, 그 참여작의 entry_likes·entry_saves·entry_comments·entry_ai_reports·notifications 행이 없고 videos 행은 있다. 보관함에서
  그 영상 삭제: video_in_use가 아니다(참조 없음).
- 탈퇴: 참여작 visibility private, 목록에 없음, 행 유지.

## challenge.react 좋아요·저장·댓글
- 도입: 1.0.0
- 화면: A15(피드 반응 메뉴), A15.3(댓글 모달), A15.5(저장한 영상), A4(프로필의 저장한 영상 진입)
- 테이블: entry_likes, entry_saves, entry_comments

### 기능
공개 참여작에 좋아요를 누르고, 참고할 영상을 저장해 모아 보고, 댓글을 남긴다. 좋아요는 랭킹의 기준이다.

### 의도
좋아요·저장은 (entry_id, user_id) 유일인 연결 표이고 토글은 멱등이다(ERD). 댓글은 작성자가 탈퇴해도 남고 이름만 "탈퇴한 사용자"로 바뀐다
(account.withdraw, 05-community의 보관 결정과 같다). 댓글 좋아요·답글은 1.0.0에 없다.

### 목적
배우가 다른 배우의 연기에 반응을 남기고, 참고할 영상을 모아 둔다.

### 규칙·제약
- 좋아요·저장은 공개(visible·public) 참여작에만 된다. 비공개·삭제·숨김 참여작에는 404다(공통 규칙). 본인 참여작에도 좋아요는 된다.
- 좋아요·저장 켜기·끄기는 PUT·DELETE로 멱등이다. 두 번 켜도 하나, 없는 것을 꺼도 200이다. 좋아요 수는 집계다.
- 저장한 영상(A15.5)은 내가 저장한 공개 참여작 목록(저장순)이며 "내 영상 N · 저장한 영상 N"을 보여 준다. 저장한 참여작이 비공개·삭제되면
  목록에서 빠지고 행은 남는다(다시 공개되면 돌아온다).
- 댓글은 300자, 공개 참여작에만, 하루 100개까지(429 daily_comment_limit). 수정은 없고 본인 삭제만 된다(행째). 목록은 오래된 순이고 20개씩
  이어 받는다. 작성자 이름은 프로필 이름이고 이름을 바꾸면 옛 댓글도 새 이름으로 보인다. 탈퇴한 작성자는 "탈퇴한 사용자".
- 참여작 작성자에게 좋아요·댓글 알림이 간다(challenge.notification).
- 게스트: 403 member_only.

### 예외
- 비공개 참여작에 좋아요: 404. 삭제된 참여작에 댓글: 404.
- 댓글 301자·빈 댓글: 422. 하루 101번째: 429.
- 다른 사람의 댓글 삭제: 404.
- 저장한 참여작이 삭제됨: 목록에서 빠진다.

### 검증 방법
- 좋아요 PUT 두 번: entry_likes 1행, 좋아요 수 1. DELETE: 0행, 다시 DELETE: 200.
- 본인 참여작 좋아요: 된다. 비공개 참여작: 404. 삭제된 참여작: 404.
- 저장 PUT: entry_saves 1행, A15.5 목록에 보인다. 그 참여작이 비공개로 바뀜: 목록에 없고 행은 있다. 다시 공개: 돌아온다.
- 댓글 작성: entry_comments 1행, 목록 오래된 순, 작성자 이름 = 프로필 이름. 이름 변경 뒤: 새 이름. 301자: 422. 하루 101번째: 429.
- 본인 댓글 삭제: 행 없음. 남의 댓글 삭제: 404.
- 작성자 탈퇴: 댓글 남고 "탈퇴한 사용자".
- 게스트 토큰: 403 member_only.

## challenge.report 신고
- 도입: 1.0.0
- 화면: A15.4(영상 신고 모달)
- 테이블: entry_reports, challenge_entries

### 기능
회원이 참여작을 사유와 함께 신고하면 즉시 목록에서 숨겨지고, 운영이 확인해 되돌리거나 그대로 둔다.

### 의도
1.0.0에는 사람 차단·계정 정지가 없고 신고만 있다(00-common 범위 밖). 앱 심사 지침 1.2가 요구하는 "신고 수단"과 "악성 콘텐츠 차단"은
신고 → 즉시 숨김 → 운영 확인으로 충족한다고 본다. 악성 사용자 차단은 사람 단위 user_blocks로 후속이다(05-community).

### 목적
배우가 부적절한 영상을 바로 안 보게 하고, 운영이 사후에 판단한다.

### 규칙·제약
- 사유는 copyright(저작권 침해 — 대사·영상 출처), inappropriate(부적절한 콘텐츠), spam(스팸·중복 업로드), duplicate(중복), other(기타, 200자 메모
  선택) 다섯이다. 화면(A15.4)은 스팸·중복을 한 줄로 보여 주되 서버 값은 둘을 구분한다.
- (entry_id, reporter_id) 유일이다. 같은 참여작을 두 번 신고하면 200이고 행은 하나다. 본인 참여작은 신고할 수 없다(422 self_report).
- 접수되면 참여작 status를 hidden_by_report로 바꾼다(목록·랭킹·피드에서 즉시 제외, 작성자 본인은 프로필에서 "확인 중"으로 본다). 운영이
  관리 경로로 확인해 visible로 되돌리거나 hidden으로 둔다(신고 status received → reviewed, 처리 메모).
- 한 챌린지의 참여작 신고가 24시간 안에 10건을 넘으면 챌린지를 review로 올린다(challenge.create).
- 신고자에게 처리 결과를 알리지 않는다. 신고 남용(하루 20건 초과)은 429 daily_report_limit.
- 작성자가 참여작을 지우면 신고 행은 남는다(운영 기록).

### 예외
- 본인 참여작 신고: 422 self_report. 하루 21번째: 429.
- 이미 숨겨진 참여작 신고: 200, 행 추가(다른 신고자).
- 운영이 visible로 되돌린 뒤 같은 사람이 다시 신고: 유일 제약에 걸려 200, 다시 숨기지 않는다(운영 결정 유지).

### 검증 방법
- 신고(inappropriate): entry_reports 1행(status received), 참여작 status hidden_by_report, 랭킹·피드에서 사라진다. 작성자 P03에 "확인 중".
- 같은 사람 재신고: 200, 행 하나. 다른 사람 신고: 2행.
- 본인 신고: 422 self_report. 하루 21번째: 429 daily_report_limit.
- 운영이 visible로 되돌림: 목록에 돌아오고 신고 status reviewed. 그 뒤 같은 사람 재신고: 숨기지 않는다.
- 한 챌린지에 24시간 안 신고 11건: challenges status review, 참여작 모두 목록에서 빠진다.
- 작성자가 신고된 참여작을 삭제: status deleted, entry_reports 행은 남는다.
- 게스트 토큰: 403 member_only.

## challenge.ai-report AI 리포트
- 도입: 1.0.0
- 화면: A18.1·A18.2(안내 문구), A18.3("AI 리포트 받기"), 리포트 화면(없음, 디자인에 반영할 것), P03
- 테이블: entry_ai_reports, ai_jobs

### 기능
참여작을 올리면 같은 대사의 다른 공개 참여작들과 나란히 놓고 내 영상의 관찰과 차이를 설명하는 리포트를 뒤에서 만들어 본인에게만 보여
준다. 공개·비공개 모두 받는다.

### 의도
"같은 대사 영상들과 비교한 AI 리포트"(A18.1)는 랭킹과 달리 사람의 반응이 아니라 관찰이다. 채점 금지 원칙에 따라 점수·순위·우열을 내지
않고, 내 영상에서 보이는 것(시선·호흡·속도·멈춤)과 다른 영상들에서 자주 보이는 선택을 사실로 견준다. 생성은 ai_jobs challenge_report로
뒤에서 돌린다(ERD).

### 목적
배우가 같은 대사를 남들은 어떻게 했는지, 내 것은 무엇이 다른지 관찰로 본다.

### 규칙·제약
- 참여작 등록 트랜잭션에서 ai_jobs(kind challenge_report) 하나를 만든다. 참여작과 1:1(entry_ai_reports)이고 status pending·ready·failed, 모델,
  결과 json, 완료 시각을 가진다.
- 비교 대상은 같은 챌린지의 공개 참여작 가운데 최근 10개(본인 것 제외)다. 없으면 내 영상만의 관찰 리포트다. 비교 대상의 영상은 리포트에
  식별 정보(이름·id) 없이 "다른 참여작들"로만 나온다.
- 내용은 관찰(내 영상에서 확인된 것, 시각과 함께), 견주기(다른 참여작들에서 자주 보인 선택과 내 선택의 차이, 우열 없이), 다음 시도 제안
  하나(없을 수 있음)이다. 점수·등급·순위·"잘했어요" 문구를 내지 않는다. 언어는 앱 표시 언어.
- 본인만 본다. 남의 리포트 id로 조회하면 404.
- 실패는 practice.analyze의 ai_jobs 규칙과 같다(즉시 실패 분류·재큐 최대 3회). 3회 실패면 failed이고 "다시 시도" 한 번을 준다(새 작업).
- 참여작을 지우면 리포트도 지운다. 탈퇴하면 남기고 접근을 막는다.
- 하루 참여 5개 한도가 리포트 비용의 상한이다(challenge.entry).

### 예외
- 비교 대상 0개: 내 영상 관찰만, "아직 비교할 영상이 없어요".
- 생성 중 참여작 삭제: 작업 취소, 리포트 없음.
- 3회 실패: failed, 다시 시도 뒤 새 작업.
- 영상이 파기된 참여작(탈퇴 보관 만료): 리포트 텍스트는 남고 영상 재생만 불가(본인은 이미 탈퇴).

### 검증 방법
- 참여작 등록: ai_jobs challenge_report 1행, 완료 뒤 entry_ai_reports 1행(status ready), 결과에 관찰·견주기·제안이 있고 점수·등급·순위·칭찬
  문구가 없다.
- 비교 대상 12개 공개 참여작: 최근 10개만 입력에 들어가고 결과에 다른 사람 이름·id가 없다. 0개: 관찰만.
- 비공개 참여작: 리포트가 같이 생긴다. 남의 리포트 조회: 404.
- 워커 실패 3회: failed, "다시 시도" → 새 ai_jobs 1행.
- 참여작 삭제: entry_ai_reports 행 없음, 진행 중 작업 취소.
- 탈퇴: 행 남고 API 접근 403.

## challenge.notification 챌린지 알림·알림함
- 도입: 1.0.0
- 화면: 알림함(없음, 디자인에 반영할 것), A4 설정의 챌린지 알림 토글(account.notification)
- 테이블: notifications(ERD에 추가), push_tokens, challenge_entries, challenges

토글과 토큰은 account.notification이 맡고, 이 기능은 어떤 사건에 언제 보내고 어떻게 묶는지와 알림함을 맡는다.

### 기능
내 참여작에 좋아요·댓글이 달리면, 오늘의 챌린지가 뜨면, 내가 참여한 챌린지가 끝나면 푸시로 알리고 알림함에 쌓는다. 챌린지 알림 토글을
끄면 푸시는 가지 않고 알림함에는 남는다.

### 의도
알림함(notifications)은 ERD 합의 뒤 계정 문서가 추가한 테이블이고 컬럼은 여기서 정한다. 좋아요는 몰려 오므로 묶고, 밤에는 보내지 않는다
(account.notification의 밤 10시).

### 목적
배우가 자기 영상에 온 반응을 놓치지 않고, 오늘의 대사를 안다.

### 규칙·제약
- 사건과 발송: ① 내 참여작에 좋아요 — 한 시간 단위로 묶어 "N명이 좋아해요"(첫 좋아요는 즉시, 그 뒤 같은 참여작은 한 시간에 한 번). ②
  내 참여작에 댓글 — 즉시, 댓글 앞 50자. ③ 오늘의 챌린지 등록 — 그날 정오 12시(한국 시간)에 챌린지 알림을 켠 회원 모두에게. ④ 내가 참여한
  챌린지 종료 — 종료 시각에 최종 순위(공개 참여작만)와 함께. ⑤ 내가 연 챌린지에 새 참여 — 하루에 한 번 묶어 저녁 6시. 본인 행동(내 참여작에
  내 좋아요)은 알리지 않는다.
- 밤 10시~아침 8시(한국 시간)에는 푸시를 보류하고 아침 8시에 묶어 보낸다. 알림함에는 즉시 쌓인다.
- notifications 컬럼: id, user_id, kind(entry_liked·entry_commented·challenge_featured·challenge_ended·challenge_new_entry), challenge_id, entry_id(NULL
  가능), actor_user_id(NULL 가능, 묶음이면 NULL), count(묶음 수), title, body, created_at, read_at, pushed_at. 90일 지난 행은 매일 지운다.
- 알림함은 최신순 20개씩, 항목을 누르면 참여작·챌린지로 간다. 개별·전체 읽음 처리. 읽지 않은 수는 탭 배지.
- 토글(user_profiles.notify_challenge)이 꺼져 있으면 pushed_at 없이 알림함에만 쌓는다. 푸시 토큰이 없으면 같다.
- 참여작이 삭제·비공개·숨김되면 그 참여작의 알림은 지운다(삭제)·유지한다(비공개·숨김, 누르면 "볼 수 없는 영상").
- 탈퇴하면 notifications를 행째 지운다. 탈퇴한 사람이 남긴 좋아요·댓글 알림은 actor 이름이 "탈퇴한 사용자".

### 예외
- 푸시 발송 실패(토큰 만료): 토큰을 지우고(account.notification) 알림함에는 남는다.
- 같은 참여작에 한 시간 안 좋아요 30개: 알림함 1행(count 30), 푸시는 첫 것 + 한 시간 뒤 묶음 하나.
- 밤 11시 댓글: 알림함 즉시, 푸시는 아침 8시.
- 오늘의 챌린지가 없는 날: ③ 알림 없음.

### 검증 방법
- 남이 내 참여작에 좋아요: notifications 1행(entry_liked, count 1), 푸시 1건. 한 시간 안 29개 더: 같은 행 count 30, 푸시는 한 시간 뒤 1건.
- 남의 댓글: entry_commented 1행, body에 앞 50자, 푸시 즉시. 내 참여작에 내 좋아요: 행 없음.
- 기획팀이 featured_on 오늘로 개설: 정오에 켠 회원 모두에게 challenge_featured 1행·푸시. 끈 회원: 행만.
- 내가 참여한 챌린지 종료: challenge_ended 1행, body에 최종 순위.
- 내 챌린지에 새 참여 셋: 저녁 6시에 count 3인 행 하나.
- 밤 11시 사건: created_at은 밤 11시, pushed_at은 아침 8시.
- 토글 끔: pushed_at NULL, 행 있음. 토큰 없음: 같다.
- 알림 항목 읽음: read_at. 전체 읽음: 모두 read_at. 배지 수 = read_at NULL 수.
- 91일 지난 행: 없다. 참여작 삭제: 그 알림 행 없음. 탈퇴: 행 없음. 탈퇴자가 남긴 좋아요 알림의 actor: "탈퇴한 사용자".
- 게스트 토큰으로 알림함: 403 member_only.
