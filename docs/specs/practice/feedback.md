# practice.feedback 이탈 설문

[공통 규칙](../common.md) · [영역 개요](README.md)

- 도입: 1.0.0
- 화면: A7(이탈 설문, coach·report 공통 시트), 웹 대응 화면(없음, 디자인에 반영할 것)
- 테이블: practice_feedback, practices

## 기능
코치 대화나 노트 화면에서 나가려 할 때 한 줄 소감을 묻는다. 보내거나 그냥 나갈 수 있고, 한 계정에 한 번만 묻는다. 소감은 서버에
먼저 저장하고 구글 시트로도 복제한다.

## 의도
지금 앱은 시트(Apps Script)로만 보내고 웹은 외부 폼을 띄운다. 서버에 없으니 "한 번만 묻기"를 기기마다 따로 판단하고 탈퇴 때 지울
수 없다. DB를 정본으로 두고 시트는 복제본이다(ERD).

## 목적
배우가 나가는 순간의 소감을 부담 없이 남기고, 운영은 시트에서 그대로 읽는다.

## 규칙·제약
- 대상은 coach·report 화면에서의 이탈이고, 계기는 x·leave·back 셋이다. 홈 의견·스토어 평점·노트 미니 평가는 이 기능이 아니다.
- 한 계정에 한 번만 묻는다. 자동 노출 직전에 서버가 계정의 노출 표식(users.exit_survey_asked_at)을 원자적으로 선점하고, 선점한 기기만
  시트를 띄운다(두 기기가 동시에 물어도 하나만). 건너뛰기도 practice_feedback에 body가 없는 행(dismissed)으로 남긴다. 오프라인에서는 새
  자동 노출을 하지 않고 이미 쓴 제출만 다시 보낸다. 웹의 "7일 뒤 다시" 규칙은 없앤다. 이관하면 게스트·회원 어느 쪽이든 물어봤으면 참이고
  설문 이력 행은 모두 회원으로 옮긴다.
- 본문은 공백 정리 뒤 1~100자(코드 포인트), 연락처(이메일·전화)는 각각 80자 선택이다. 연락처 없이도 보낼 수 있다.
- 행은 user_id·practice_id·화면(coach·report)·계기·본문·연락처·시각·sheet_synced_at을 가진다. 계정에 연결되며 화면 문구는 "답변은
  서비스 개선에만 써요 · 이름은 보이지 않아요"로 실제 수집 범위를 말한다("이름은 남지 않아요"는 고친다). (디자인에 반영할 것)
- 저장은 DB 커밋으로 끝난다. 시트 전송은 서버가 같은 설문 id와 변경 순번(sheet_seq)으로 보내고 실패하면 sheet_synced_at을 NULL로 두어
  매일 도는 일이 다시 보낸다. 시트는 설문 id로 한 줄만 두고 순번이 작은 전송은 무시한다(오래된 전송이 파기한 연락처를 되살리지 못한다).
  이 전송은 AI 작업이 아니라 ai_jobs에 넣지 않는다.
- 제출 실패가 나가기를 막지 않는다. 설문 결과로 대화·노트 상태가 바뀌지 않는다.
- 연락처는 접수 90일 뒤 DB에서 지우고 같은 설문 id·새 순번으로 시트에 다시 보내 시트의 연락처도 지운다(성공까지 재시도). 탈퇴 때도
  같다. 본문은 사람과 끊어 남긴다. 연락처 컬럼을 지워도 본문에 식별 정보가 있을 수 있다는 점은 법무 확인에 둔다.
- 웹은 외부 폼 대신 같은 시트 화면을 쓴다. (디자인에 반영할 것)

## 예외
- 오프라인 제출: 기기가 들고 있다가 다시 보낸다. 같은 설문 id라 행 하나.
- 시트 전송 실패: 접수는 유지, sheet_synced_at NULL, 다음 날 재전송.
- 이미 물어본 계정: 시트가 뜨지 않는다. 다른 기기에서도 같다. 두 기기가 동시에 자동 노출 조건: 선점한 하나만 뜬다.
- 101자: 422. 연락처 81자: 422.

## 검증 방법
- 대화에서 x로 나가며 보내기: 접수 성공 → practice_feedback 1행(screen coach, trigger x, body, user_id, practice_id), users.exit_survey_asked_at
  있음. 동기화 성공 → 시트에 같은 id 한 줄. report 화면에서 leave·back: 각각 그 값으로 저장된다.
- 그냥 나가기: body 없는 dismissed 행 1개. 그 뒤 다른 연습에서 나가기: 시트가 뜨지 않는다. 다른 기기 로그인: 뜨지 않는다. 두 기기 동시: 하나만.
- 시트 응답 유실 뒤 재전송: DB 행 하나, 시트 한 줄, sheet_synced_at 채워짐. 시트 실패: sheet_synced_at NULL, 다음 날 재전송으로 채워짐.
- 빈 본문(dismissed 아님): 422. 100자: 200. 101자: 422. 연락처 80자: 200. 81자: 422. 연락처 없이: 200.
- 오프라인 제출 뒤 연결: 같은 설문 id라 행 하나. 오프라인에서 자동 노출 조건: 시트가 뜨지 않는다.
- 91일 뒤: DB 연락처 NULL이고 시트의 같은 id 줄에도 연락처가 없다. 오래된 순번의 전송이 늦게 도착: 시트 연락처가 되살아나지 않는다.
- 탈퇴: 연락처 NULL(DB·시트), 본문은 남고 user_id는 deactivated 계정.
- 이관: 게스트가 물어봤으면 회원도 뜨지 않고 설문 행은 회원 것이 된다.
- 제출 API 실패 상태에서 나가기: 화면이 닫힌다.
- 웹에서 나가기: 같은 시트가 뜨고 외부 폼이 없다.
