# practice.resume 이어하기

[공통 규칙](../common.md) · [영역 개요](README.md)

- 도입: 1.0.0
- 화면: A1.2(연습 기록 상세의 "이어서 연습하기"), A8.1(장면 적기의 "이전 연습 이어서 하기"), A13(연습 마치기 → 다음), D8, WH
- 테이블: practices, videos

## 기능
끝난 연습에서 이어서 새 회차를 시작한다. 연습 기록(A1.2)의 "이어서 연습하기"는 같은 영상으로, 새 연습 화면(A8.1)의 "이전 연습
이어서 하기"는 새 영상으로 같은 묶음의 다음 회차를 만든다. 코치는 같은 묶음의 이전 대화와 노트를 참고 맥락으로 읽는다.

## 의도
PRD는 끝난 연습에서 새 연습을 시작하고 코치가 대화를 이어받는다고 한다. 현행 continued_from 체인은 묶음을 클라이언트가 정렬해
표현하고 진행 중 회차를 막지 못한다. root_id + ordinal과 진행 중 회차 하나 제약으로 서버가 묶음을 소유한다.

## 목적
배우가 같은 장면을 다시 찍거나 같은 영상으로 다시 물어보되, 같은 이야기를 처음부터 되묻지 않는다.

## 규칙·제약
- 두 진입점은 모두 같은 root_id에 다음 ordinal 행을 만든다. A1.2는 고른 회차의 video_id를 그대로 쓰고, A8.1은 새로 확정한
  영상을 쓴다. 웹의 버튼 문구도 영상을 다시 쓰는지 드러낸다.
- 묶음에 닫히지 않은 회차가 있으면 새 회차를 만들지 않고 409 practice_in_progress다(본문은 코드 하나, 공통 규칙). 화면은 묶음 조회에서
  진행 중 회차 id를 얻어 복귀시킨다.
- 회차마다 상황·인물·목표·막힘을 새로 확정한다. 앱에서 방금 끝낸 노트(A13)에서 이어갈 때만 이전 장면을 미리 채워 두고, 지난
  기록이나 웹에서 이어갈 때는 빈 준비 화면이다(PRD).
- 코치는 같은 묶음의 이전 대화·노트를 참고 맥락으로 읽고 이번 영상·의도의 증거로 쓰지 않는다(ADR-027). 무관한 최근 대화를 넣지
  않는다.
- 새 회차마다 분석은 한 번 돈다. 같은 영상이면 받아쓰기만 재사용한다. 게스트의 하루 3회를 한 번 쓴다. 웹은 시작 전에 이를 알린다.
- 차수는 묶음 잠금과 (root_id, ordinal) 유일로 발급한다. 이어하기 요청도 request_id·지문 규칙을 따른다(같은 id·같은 지문은 같은 회차).
  실패한 회차의 재시도는 다른 진행 중 회차가 없을 때만 된다.

## 예외
- 진행 중 회차가 있는 묶음에서 이어하기: 409 practice_in_progress. 회차 id는 묶음 조회에서 얻는다.
- 두 기기에서 서로 다른 요청 id로 동시에 이어하기: 차수 하나만 생기고 다른 요청은 409. 같은 요청 id 둘: 같은 회차.
- 영상이 파기된 회차에서 A1.2 이어하기: 422 video_not_ready(새 영상으로는 된다).
- 숨긴 묶음에서 이어하기: 되고, 묶음은 그대로 숨김이다.

## 검증 방법
- 1차가 closed인 묶음에서 A1.2 이어하기: practices에 ordinal 2 행, root_id·video_id가 1차와 같다. ai_jobs analyze 1행이 새로 생기고
  video_transcripts는 늘지 않는다.
- A8.1로 새 영상 이어하기: ordinal 2, video_id는 새 영상.
- 1차가 conversing인 채 이어하기: 409 practice_in_progress(본문은 코드만). 묶음 조회: 진행 중 회차 id가 있다.
- 서로 다른 요청 id로 동시 이어하기 둘: ordinal 2 하나, 다른 요청 409. 같은 요청 id 둘: 같은 회차 하나.
- 숨긴 묶음에서 이어하기: 새 회차가 생기고 묶음은 숨김 그대로. 파일만 파기한 영상의 회차에서 A1.2: 422 video_not_ready. A8.1 새 영상: 된다.
- 다른 묶음의 최근 대화: 새 회차의 코치 입력에 없다. 같은 묶음의 이전 노트: 참고 맥락으로 들어간다.
- 앱에서 A13의 다음 연습: 준비 화면에 이전 상황·인물·목표가 채워져 있다. 지난 기록에서 이어하기: 비어 있다.
- 게스트가 하루 3회를 쓴 뒤 이어하기: 429 guest_daily_analysis_limit.
