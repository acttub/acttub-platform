# practice.rating 앱 평가 요청

[공통 규칙](../common.md) · [영역 개요](README.md)

- 도입: 0.1.2
- 화면: 노트(report) "마치기", 대본 리딩 완주 화면, 설정 "앱 평가하기"
- 테이블: 없음 — 기기 저장(`acttub.appRating`)

## 기능
AI 코칭을 2번 마칠 때마다, 대본을 1번 끝까지 읽을 때마다 "Acttub 어떠셨어요?" 시트로 별점·리뷰를 부탁한다. "별점 남기기"는
OS 인앱 평점 창을 먼저 띄우고, OS가 창을 줄 수 없으면 스토어의 리뷰 쓰기 화면을 연다. 설정의 "앱 평가하기"는 언제든 스토어 리뷰
화면을 바로 연다.

## 의도
앱 안의 한줄평·이탈 설문·홈 평가 넛지를 걷고, 평가를 스토어 별점과 리뷰로 받는다(SOMA-494). 연습 5회 뒤 자동으로 부르던
OS 평점 창도 이 요청으로 바꾼다.

## 목적
배우는 코칭이나 대본 리딩을 끝낸 뒤에만 드물게 평가 부탁을 받고, 원하면 설정에서 언제든 평가를 남긴다.

## 입력·출력
없음 — 서버를 거치지 않는다. 기기 저장(`acttub.appRating`), OS 인앱 평점 창, 스토어 리뷰 화면만 쓴다.

## 상태
없음. 기기에 물은 횟수·마지막으로 물은 시각·센 연습 id만 둔다.

## 규칙·제약
- 같은 연습을 두 번 세지 않는다(최근 20개 연습 id). 튜토리얼 예시 대본의 완주는 세지 않는다.
- 최소 7일 간격, 최대 3번까지만 묻는다(iOS 인앱 평점 창의 1년 한도와 같다). "나중에"도 한 번 물은 것으로 센다.
- 스토어는 실제 평가 여부를 알려 주지 않으므로 "별점 남기기"를 누르면 다시 묻지 않는다.

## 예외
- OS가 인앱 평점 창을 줄 수 없으면: 스토어의 리뷰 쓰기 화면을 연다.
- 기기에 저장된 값이 깨졌으면: 처음 상태로 돌아간다. 조르는 쪽보다 한 번 더 묻는 쪽을 택한다.

## 검증 방법
- AI 코칭을 1번 마치면: 시트가 뜨지 않는다. 2번째를 마치면: 뜬다.
- 같은 연습의 마침이 두 번 들어오면: 한 번만 센다.
- 대본을 끝까지 읽으면: 시트가 뜬다. 튜토리얼 예시 대본을 끝까지 읽으면: 뜨지 않는다.
- "나중에"를 누른 뒤 7일 안에 대본을 끝까지 읽으면: 뜨지 않는다. 7일이 지난 뒤 끝까지 읽으면: 뜬다.
- 세 번 물은 뒤: 다시 뜨지 않는다.
- "별점 남기기"를 누른 뒤: 다시 뜨지 않는다.
- 설정의 "앱 평가하기": 스토어 리뷰 화면이 열린다.

## 범위 밖
- 실제로 평가했는지 확인하기. 스토어가 알려 주지 않는다. (규칙·제약)
- 웹. 평가 요청은 앱에만 있다.
