# 커뮤니티

- 진행: 후속 (0.1.0 제외)

[쓰는 법](../README.md)과 [공통 규칙](../common.md)을 먼저 읽는다.

2026-09-17 계정 요구사항 검토에서 커뮤니티(게시판)를 0.1.0에서 빼기로 했다. 후속에서 이을 수 있도록
그때까지 정해진 요구사항과 결정을 여기 둔다. 코드는 내렸고([0.1.0에서 한 것](#010에서-한-것)), 디자인(A3·A3.1·A3.2,
D11·D12·D15, WC·WC2·WC3)은 그대로 있다.

## 용어

| 용어 | 뜻 | 피할 말 |
|---|---|---|
| Community (커뮤니티) | 배우들이 글과 댓글을 주고받는 자리. 내리기 전 화면 제목은 웹이 "커뮤니티", 앱이 "게시판"이었다. 코드·문서·이슈에서는 이 이름을 쓴다. | 포럼, 게시판 |

## 보관하는 결정

- 작성자 이름은 챌린지와 같은 규칙의 공개 이름이다([account.profile](../account/profile.md#규칙제약)). 별도 닉네임은 없다.
- 탈퇴하면 글·댓글 행은 남기고 작성자는 [공통 규칙 「탈퇴·삭제」](../common.md#탈퇴삭제)대로 "탈퇴한 사용자"로 보인다.
  후속에서 커뮤니티를 되살리면 탈퇴 화면 안내에 이 문장을 다시 넣는다.
- 차단은 사람 단위 user_blocks로 바꿔 커뮤니티·챌린지가 함께 쓴다. 0.1.0의 챌린지가 이 표를 먼저
  만들었다(challenge.block, ADR-032). 커뮤니티를 되살릴 때 community_blocks의 자료를 옮길지는 그때 정한다.
- 웹 게스트(account.guest)는 읽기만 하고 글쓰기는 회원만이다.
- 익명 글, 분류별 목록, 좋아요·신고는 내리기 전 코드 구조(git 이력의 `feature/community`)를 따른다. 신고 사유는
  spam·abuse·sexual·privacy·other다.

## 0.1.0에서 한 것

- community_* 테이블 7개와 기존 글 데이터는 남기고 API·화면만 내렸다. community_blocks도
  그대로 두었다.

## 후속에서 정할 것

- 연습·리포트와 사람만 공유하고 데이터는 이어지지 않는다는 원칙을 유지할지. 0.1.0까지는 연습에서 한 일이
  커뮤니티로 흘러오지 않는다.
