# account.withdraw 탈퇴

[공통 규칙](../common.md) · [영역 개요](README.md)

- 도입: 0.1.0
- 결정 기록: ADR-029
- 화면: A5
- 테이블: users, user_profiles, user_identities, refresh_tokens, push_tokens, actor_memories, videos, reading_recordings, challenge_entries, ai_jobs, portfolios, portfolio_credits, portfolio_photos, guest_transfer_codes, user_consents, user_profile_directions, entry_comments, entry_likes, practice_feedback, account_cleanup_operations(ERD에 추가)

## 기능
설정에서 탈퇴하면 계정을 쓸 수 없게 하고, 바로 알아보게 하는 정보는 파기하며, 나머지는 사람과
끊어 남긴다. 연습 기록과 다른 사람의 화면에 얽힌 행은 지우지 않는다. 같은 제공자로 다시 로그인하면
처음 가입과 똑같이 새 계정이 만들어지고, 이전 계정의 데이터는 새 계정으로 옮기지 않는다. 제공자 연결
해제를 포함한다.

## 의도
챌린지 댓글과 집계처럼 다른 사람의 화면에 얽힌 행을 지우면 남의 댓글 흐름과 집계가 깨진다. 행은
남기고 사람만 지운다. 재가입을 처음처럼 단순하게 두어 돌아오는 길을 막지 않는다.

## 목적
탈퇴한 사람의 신원·연락처·얼굴이 서비스에 남지 않고, 다른 사용자의 화면은 그대로다. 돌아오면
새 계정으로 처음부터 시작한다.

## 입력·출력
| 입구 | 입력 | 출력 | 오류 |
|---|---|---|---|
| `DELETE /v2/me` | 헤더 `Authorization`. 게이트 밖이고 탈퇴한 계정과 게스트의 토큰도 받는다 | `WithdrawnResponse` 200. 처음이든 다시든 같고 시각은 최초 탈퇴 시각 | 401, 옮겨진 게스트 `guest_transferred` 403, 주체 한도 429 |
| `AccountCleanup#attempt` (탈퇴 커밋 직후) | 방금 올린 정리 장부 행 | 객체 삭제·제공자 해제를 한 번 시도 | 실패는 보고하고 장부에 남긴다. 탈퇴 응답은 200 그대로 |
| `AccountCleanupScheduler.run` (5분마다, `ACCOUNT_CLEANUP_INTERVAL_MS`) → `AccountCleanup#runDue`. 매일 도는 `AccountHousekeeping#runDaily`도 부른다 | 때가 된 account_cleanup_operations 행 | 성공하면 행 삭제, 실패하면 다음 시도를 늦춘다 | 7일 뒤의 처리는 「상태」의 정리 장부 표 |
| `AccountHousekeeping#runDaily` 탈퇴 3년 파기 (매일, 시각과 실패 처리는 [CONTRACT §6-12](../../../apps/api/CONTRACT.md#6-12-매일-도는-일)) | `deactivated_at`이 달력으로 3년 지났고 `retention_purged_at`이 빈 계정 | 신원 해시 행 삭제, 보관하던 영상·리딩 녹음의 삭제를 장부에 올림, `retention_purged_at` 기록 | 마치지 못한 계정은 다음 날 다시 고른다 |

## 상태
- 탈퇴 → users가 deactivated(`deactivated_at`), 3년 파기 → `retention_purged_at` (정본: [account.login](login.md#상태))
- 탈퇴 → 신원 행은 `provider_uid`를 비우고 `uid_hash`를 채운다(`ck_user_identities_uid_or_hash`). 3년 파기 → 행 없음.
  게스트 신원은 해시 없이 행째 지운다. (정본: [account.guest](guest.md#상태))
- 탈퇴 → 진행 중인 `ai_jobs`와 옛 연습 흐름의 `external_operations`는 `failed`/`account_deactivated` (정본:
  [공통 상태](../common.md#공통-상태)). 게스트 옮기기는 이 전이를 일으키지 않는다.

account_cleanup_operations(상태 컬럼 없음, 종류는 `ck_account_cleanup_operations_kind`의 object_delete·
apple_revoke·kakao_unlink·naver_revoke·reading_recording_delete):

| 상태 | 들어오는 전이(조건) | 일으키는 기능 |
|---|---|---|
| 대기(`next_attempt_at`) | 탈퇴 트랜잭션이 해제 값·객체 키를 옮김. 사진(프로필·포트폴리오)의 교체·삭제, 영상 삭제·파일만 파기·만료된 미확정 업로드, 리딩의 대본·회차·녹음 삭제도 객체 삭제를 올린다 | account.withdraw, account.profile, account.portfolio, practice.record, practice.library, reading.script, reading.session, reading.recording |
| 재시도(`attempt_count`, `last_error`) | 시도 실패. 다음 시도를 늦춘다(간격은 [CONTRACT §6-8](../../../apps/api/CONTRACT.md#6-8-탈퇴)) | account.withdraw |
| 기한 넘김(객체 삭제만, `expires_at` 지남) | 7일 동안 성공하지 못함. 성공할 때까지 계속 시도하고 7일마다 운영자에게 알린다(복구 대상) | account.withdraw |
| 행 없음 | 성공. 제공자 해제는 7일이 지나면 값과 함께 지운다(애플 폐기는 App Store 필수라 운영자에게 알린다) | account.withdraw |

불변 조건: 끝난 정리는 장부에 남지 않는다. 객체 삭제는 성공하기 전에는 대상 키를 지우지 않는다. 끝 상태는
행 없음이다.

- 서버 해제에 필요한 값(애플 토큰, 카카오 대상 ID, 네이버 토큰)과 지울 영상·녹음 객체의 목록은 파기
  전에 정리 장부에 암호화해 옮긴다. 해제 값을 최대 7일, 객체 키를 삭제가 성공할 때까지 들고 있는 것(위 표)을
  처리방침에 적는다.

## 규칙·제약
- 파기 대상(바로 알아보게 하는 것): users의 이메일, 프로필의 이름·사진·소개, 신원(user_identities의
  provider_uid와 애플 토큰), 리프레시·푸시 토큰, 살아 있는 이관 코드, 포트폴리오·경력·사진. 소개는
  자유 글이라 실명이 들어갈 수 있어 지운다. 신원 행은 아래 해시만 남긴다. 사진(프로필·포트폴리오) 객체는
  보관 동의와 무관하게 지운다.
- 제공자 연결 해제: 애플은 로그인 때 저장해 둔 토큰으로 서버가 폐기한다(App Store 필수). 카카오는
  어드민 키로 서버가 연결을 끊는다(카카오 정책 필수). 네이버는 로그인 때 저장해 둔 토큰으로 서버가
  연결을 해제한다. 구글은 서버가 ID 토큰만 받으므로 앱이 탈퇴 요청 직전에 SDK의 연결 해제를 부른다.
  앱의 해제가 실패해도 탈퇴는 진행한다.
- 신원 해시: 탈퇴할 때 신원마다 서버 비밀키로 만든 해시(계산식은 [CONTRACT §6-8](../../../apps/api/CONTRACT.md#6-8-탈퇴))를
  user_identities.uid_hash에 채우고 provider_uid는 비운다. 행은 탈퇴 3년 뒤 지운다. 3년은 한국 시간
  달력의 3년이다. 해시만으로는 사람을 알아보지 못하고 같은 제공자 계정이 다시 오는지만 안다. 처리방침에 적는다.
- 같은 제공자 계정으로 다시 로그인하면 새 계정이다. 서버는 해시로 옛 계정을 찾지 않고, 옛
  연습·노트·기억·영상을 옮기지 않으며, 이전 계정에 관해 아무것도 묻거나 보여 주지 않는다. 해시는 아래
  철회 요청에서만 쓴다.
- 보관 동의의 철회 창구는 개인정보 처리방침의 연락처다. 요청자가 같은 제공자로 로그인해 둔 계정의
  신원과 옛 계정의 해시를 운영자가 대조해 본인을 확인한 뒤 영상·녹음을 파기하고 동의를 철회로
  기록한다. 앱 안에 철회 화면은 없고 운영 도구도 만들지 않는다. 요청이 드물 것이므로 개발자가 DB에서
  직접 처리하는 절차를 운영 문서([RETENTION-REVOCATION](../../deploy/RETENTION-REVOCATION.md))로 남긴다.
- 가명처리해 남기는 것: 성별·연령대·추구하는 방향·경력·목표와 배우 기억. 생년월일은 5세 단위
  연령대로 뭉개고 원래 값은 지운다. 알림 토글은 끈다. 통계·연구 목적이며 처리방침에 적는다.
- 사람과 끊어 남기는 것: users 행(상태 deactivated, 탈퇴 시각). 남은 행은 어느 사람과도 이어지지 않는다.
  연습·리딩·챌린지 자료를 탈퇴 때 지울지 남길지는 영역 표가 정본이다:
  [연습](../practice/README.md#연습-자료의-이관삭제탈퇴), [리딩](../reading/README.md#리딩-자료의-이관삭제탈퇴),
  [챌린지](../challenge/README.md#챌린지-자료의-삭제탈퇴).
- 영상 파일과 녹음(리딩 녹음의 전사 포함): 얼굴과 목소리는 가명처리가 안 되므로 기본은 파기한다. "탈퇴 후
  영상·녹음 보관·활용" 선택 동의를 한 사람 것만 탈퇴 후 3년 동안 남기고, 기간이 끝나거나 동의를 철회하면
  파기한다. 동의했는지는 탈퇴할 때 그 문서의 현재 판에 대한 결정으로 가르고, 현재 판이 미결정이면 거절로 보고
  파기한다. 더 쓰려면 재동의를 받는다. 동의 문서에 적는 목적은 서비스 개선과 AI 모델 학습 둘 다다.
- 앱은 서버 파기가 성공한 뒤 이 기기에 저장된 계정 자료(토큰, 캐시, 내려받은 파일)를 전부 지운다.
- 재가입은 즉시 가능하고 유예 기간은 없다. 복구 요청은 받지 않는다. 실수 탈퇴는 화면의 두 번 확인으로
  막는다. 탈퇴 화면은 "연습·노트는 돌아오지 않아요"를 확인받는다.
- 백업 덤프에는 파기 전 데이터가 30일 남는다([DEPLOY-HOME §5](../../deploy/DEPLOY-HOME.md#5-자동-백업과-복원-검증)).
  개인정보 처리방침에 적는다.
- 탈퇴 화면(A5)의 안내는 이렇게 맞춘다. 지워지는 것: 이메일·이름·사진·소개, 포트폴리오와 공유 링크,
  소셜 로그인 연결, 영상과 녹음(보관에 동의했으면 3년 뒤), 대본과 리딩 기록(회차·암기 상태), 이 기기의 자료. 남는 것: 연습 기록은 나와
  끊겨 남고, 챌린지 참여작은 비공개로 내려가며, 댓글은 "탈퇴한 사용자"로 남는다. 디자인의 현재 문구는
  커뮤니티 글 기준이라 챌린지 기준으로 바꾼다.

## 예외
- 제공자 연결 해제나 객체 삭제가 실패해도 탈퇴는 완료한다(200). 다시 시도하는 기간과 운영자 알림은 「상태」의
  정리 장부 표를 따른다.
- 다른 기기에서 탈퇴가 끝난 뒤 늦게 온 쓰기는 [공통 규칙](../common.md#탈퇴와-겹친-쓰기)을 따른다.
- 탈퇴 직후 같은 제공자로 로그인: 새 계정이다. 3년이 지나 해시가 지워진 뒤에는 철회 요청의 본인
  확인을 할 수 없는데, 그때는 보관하던 영상도 이미 파기된 뒤다.
- 이미 탈퇴한 계정에 다시 탈퇴 요청: 최초 탈퇴 시각을 유지하고 파기만 다시 돈다.

## 검증 방법
- 탈퇴 뒤 DB: users 행은 남고 email이 NULL이고 status가 deactivated다. user_identities 행은
  provider_uid가 비고 uid_hash가 있으며, 리프레시 토큰은 전부 폐기, 푸시 토큰은 없다. actor_memories
  행은 남고, 그 user_id가 가리키는 users 행에는 이메일·이름·신원 값이 없다. portfolios 행이 없다.
- 탈퇴 뒤 옛 액세스 토큰으로 API 호출: 403.
- 탈퇴 뒤 같은 제공자로 로그인: 동의 화면이 처음처럼 나오고, 제출하면 새 users 행이 생기며 프로필
  게이트가 이어진다. 연습 목록은 비어 있다.
- 탈퇴한 사람의 챌린지 댓글: 남아 있고 작성자가 "탈퇴한 사용자"로 보인다.
- 탈퇴한 사람의 챌린지 참여작: 비공개로 바뀌어 목록에 없고 행은 남아 있다. 주최한 챌린지의 host_user_id: NULL. entry_saves·user_blocks·
  notifications 행: 없다. 진행 중이던 챌린지 리포트 작업: `failed`/`account_deactivated`.
- 애플로 탈퇴 뒤 iPhone 설정의 "Apple로 로그인" 목록에서 Acttub이 사라진다. 카카오·구글·네이버도
  각 제공자의 연결된 서비스 목록에서 사라진다.
- 카카오 연결 끊기 호출이 실패해도: 탈퇴는 200이고 재시도 작업이 한 건 있다. 7일 뒤: 그 작업과
  암호화한 값이 없다.
- 탈퇴한 계정의 액세스 토큰으로 탈퇴를 다시 요청: 200이고 탈퇴 시각이 처음 값 그대로다. 같은 토큰으로
  다른 API: 403.
- 분석이 진행 중일 때 탈퇴: 작업이 `failed`/`account_deactivated`이고 결과가 저장되지 않는다.
- 게스트 토큰으로 탈퇴 요청: 200이고 게스트 users 행이 deactivated이며 영상 객체가 없다.
- 영상 보관 동의를 한 사람이 탈퇴: 영상 객체가 남고, 탈퇴 3년 뒤 파기된다. 동의하지 않은 사람이
  탈퇴: 영상 객체가 없다.
- 보관 문서의 새 판이 미결정인 채 탈퇴: 옛 판에 동의했어도 영상 객체가 없다.
- 보관에 동의하지 않은 사람이 탈퇴: reading_recordings의 녹음 객체가 없다.
- 탈퇴한 사람의 프로필 속성 조회: 이름·사진·소개는 없고 성별·연령대·방향·경력·목표만 남아 있다.
- 영상 보관에 동의하고 탈퇴한 뒤 같은 제공자로 가입: 이전 계정에 관한 팝업이나 안내가 없다.
- 처리방침 연락처로 철회를 요청하고 같은 제공자로 로그인해 둔 뒤 운영 절차 문서대로 처리하면: 옛 영상 객체가
  없고 옛 계정의 보관 동의에 revoked 행이 는다.
- 탈퇴 3년 뒤: user_identities 행과 보관하던 영상 객체가 없다.
- 탈퇴 뒤 폰의 앱 저장소: 계정 자료 키가 하나도 없다.

## 범위 밖
- 탈퇴 유예 기간과 계정 복구 요청.
- 앱 안의 보관 동의 철회 화면과 철회 운영 도구.
- 탈퇴 정리 장부와 연습 영역 비동기 작업 장부의 통합. 후속.
