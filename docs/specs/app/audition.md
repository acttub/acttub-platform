# app.audition 오디션 공고 모아보기

[공통 규칙](../common.md) · [영역 개요](README.md)

- 도입: 0.1.4
- 결정 기록: ADR-034
- 화면: (pen 없음 — 앱 기존 컴포넌트로 먼저 만든다)
- 테이블: audition_postings

## 기능
여러 공개 출처에 흩어진 배우 오디션 공고를 서버가 하루 두 번 모아, 앱에서 분야·마감으로 훑어보고 원문으로 지원하러
가게 한다. 앱(모바일)과 웹 두 곳에서 같은 목록을 보인다. 화면은 공고의 사실 항목(제목·분야·출연료 문구·접수 기간·게시일)만 보여 주고, 지원은 항상 원문에서 한다.

## 의도
배우 지망생은 제작사·극단·캐스팅 플랫폼·커뮤니티 게시판을 매일 따로 돌며 공고를 찾는다. 프로필 목표에 「공연·오디션」
(`acting_goal=audition`)이 있을 만큼 우리 사용자의 실제 일과다. 한곳에서 마감 순으로 보게 해 놓치는 공고를 줄인다.

## 목적
배우가 앱을 열면 지금 지원할 수 있는 공고를 마감이 가까운 순서로 보고, 관심 있는 공고를 눌러 원문에서 바로 지원한다.

## 입력·출력
| 입구 | 입력 | 출력 | 오류 |
|---|---|---|---|
| `GET /v2/auditions` | 없음(로그인 무관) | `AuditionPostingList` 200: 지원할 수 있는 공고 전부(아래 「열림」)와 마지막 수집 시각. 기능이 꺼진 서버는 빈 목록 | 없음 |
| `AuditionCollectScheduler.collect` (`AUDITION_COLLECT_CRON`, 기본 매일 07:00·19:00 KST) | 켜진 출처의 목록 페이지·RSS | 출처별로 공고를 넣거나 갱신 | 출처 하나가 실패해도 나머지는 계속한다. 실패는 External Failure 로 보고한다 |

`AuditionPostingList`는 `{items: AuditionPosting[], collected_at}`이다. `AuditionPosting`의 칸:

| 칸 | 뜻 |
|---|---|
| `id` | `<source>-<source_ref>` 문자열. 기기의 찜·봤음 저장 열쇠 |
| `title` | 원문 제목 그대로 |
| `category` | `film` `short_film` `drama` `web_drama` `short_form` `commercial` `music_video` `theater` `musical` `agency_open` `other` |
| `source` | 출처 코드 `shinsee` `emk` `sejong` `plfil` `otr` |
| `source_name` | 화면에 쓰는 출처 이름 |
| `pay_text` | 출연료 문구 원문 그대로, 없으면 null. 숫자로 바꾸지 않는다 |
| `apply_start`·`apply_end` | 접수 기간(날짜, KST). 원문에 없으면 null |
| `status_text` | 원문의 상태 문구(접수마감·모집중 등), 없으면 null |
| `posted_on` | 원문 게시일(날짜, KST) |
| `source_url` | 원문 주소. 지원은 항상 여기서 한다 |

## 상태
공고 행은 상태 칸을 두지 않는다. **열림**은 읽을 때 계산한다:

- `apply_end`가 있으면 `apply_end ≥ 오늘(KST)`이고 마감 표시가 없을 때. 마감 표시는 `status_text`에 마감·완료·종료가 있거나,
  `title`에 괄호로 묶인 마감 표시(`(완료)`·`[마감]`·`(모집마감)` 등)가 있는 것이다. 제목의 「10/20 마감」 같은 마감일 안내는 아니다.
- `apply_end`가 없으면 마감 표시가 없고 `posted_on`이 45일 안일 때.

끝 상태는 삭제다. 매일 수집 끝에 `apply_end`가 30일 지났거나, `apply_end`가 없고 `posted_on`이 180일 지난 행을 지운다.

## 규칙·제약
- 수집하는 출처와 등급은 ADR-034가 정한다. 출처는 `AUDITION_SOURCES`(쉼표 목록)로 켜며 **기본값에 `plfil`은 없다**.
- 기능 전체는 `AUDITION_ENABLED`(기본 false)로 켠다. 꺼져 있으면 수집하지 않고 `GET`은 빈 `items`를 준다.
- 저장하는 칸은 위 표뿐이다. 본문 전문·포스터 이미지·작성자·담당자 이름·이메일·전화는 저장하지 않는다. 저장 직전에
  이메일·휴대폰 번호 모양을 검사해 걸리는 공고는 버린다.
- 목록 페이지·RSS만 연다. 공고 상세 페이지는 열지 않는다(플필 상세는 비로그인 HTML에 담당자 연락처가 들어 있다).
- 같은 출처에 보내는 요청 사이에 2초를 둔다. 출처당 요청은 3쪽 이하다. User-Agent에 `ActtubBot`과 서비스 주소를 밝힌다.
- 같은 (`source`, `source_ref`)는 한 행이다. 다시 수집하면 칸을 새 값으로 갱신한다.
- 앱은 한국어를 쓰는 사람에게만 진입점을 보인다(한국 공고만 있다).
- 웹 `/auditions`는 공용 상단 바로 들어오고 `noindex, nofollow`이며 사이트맵에 넣지 않는다. 남의 공고를 모은 공개 페이지가
  검색에 걸리지 않게 하기 위해서다.

## 예외
- 출처의 HTML 구조가 바뀌어 0건이 나오면 그 출처의 기존 행은 건드리지 않는다(지우지 않는다).
- 수집이 한 번도 성공하지 않았으면 `collected_at`은 null이다.
- 원문이 지워져도 행은 위 삭제 규칙까지 남는다. 앱은 「원문에서 확인하세요」를 항상 함께 보인다.

## 검증 방법
- 출처별 저장된 HTML·RSS 조각을 파서에 넣으면 → 기대한 제목·분야·날짜·출연료 문구의 공고가 나온다.
- 세종문화회관 목록에 「안내원 모집」과 「아역 오디션」이 함께 있으면 → 아역 오디션만 나온다.
- OTR 목록에 「극장 대관」 글이 있으면 → 버린다.
- 제목이나 출연료 문구에 휴대폰 번호 모양이 있는 공고 → 저장하지 않는다. 기사 주소 속 긴 숫자열은 걸리지 않는다.
- 같은 공고를 두 번 수집하면 → 행은 하나이고 칸은 두 번째 값이다.
- `apply_end`가 어제인 공고, `(완료)`가 붙은 제목 → `GET /v2/auditions`에 나오지 않는다.
- `AUDITION_ENABLED=false` → `GET`이 빈 `items`, 스케줄러가 네트워크를 열지 않는다.
- `AUDITION_SOURCES`에 `plfil`이 없으면 → 플필 수집기가 돌지 않는다.

## 범위 밖
공고 상세 화면 안에서 원문을 다시 보여 주기, 앱 안 지원, 배역·나이 같은 본문 항목 추출(포스터 OCR 포함), 운영자 수동
등록 API, 푸시 알림, 서버에 찜 저장, 웹 페이지의 검색엔진 색인.

## 열린 질문
- 플필·OTR·필름메이커스 제휴 결과에 따라 출처 기본값을 바꾼다.
