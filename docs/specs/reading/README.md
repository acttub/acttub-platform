# 대본 리딩

[쓰는 법](../README.md)과 [공통 규칙](../common.md)을 먼저 읽는다.
영상 연습과 완전히 분리된 영역이다. 리딩 테이블은 users와 scripts에만 매달린다. (ERD 결정)
대본과 리딩 기록은 서버에 저장한다. 원래 기획(read.acttub.com, 2026-07-29)의 "대본은 기기에만"은
2026-09-14 ERD와 2026-09-21 요구사항에서 뒤집었다(ADR-031). 그 근거였던 저작권 문제는 법무 확인 표에 있다.

리딩은 연기를 평가·채점하지 않는다. 점수·등급·"잘했어요" 같은 반응을 내지 않고, 화면 문구는 무엇이
재생 중이고 다음이 누구 차례인지 같은 기능 설명에 그친다. 말한 것을 글자로 바꿔 원문과 맞추는
글자 대조만 예외이며, 그 결과도 "맞음·틀림"이라 하지 않는다. 앱은 "원문과 다르게 말한 대사"로 원문에서 다르게 말한
어절만 노랗게 칠하고 말한 것을 아래에 둔다([reading.session](session.md#규칙제약)). 웹 암기 대조는 넘어가기·다시·원문
보기·아직 안 나온 줄로 보여 준다. (상대역 리딩 흐름 메모, 기획 6절)
실험 기능 [reading.voice-feedback](voice-feedback.md)(기본 꺼짐)은 이 원칙의 예외로 다르게 들린 어구를 보인다 — 정식 도입은 제품 결정이 필요하다.
실험 기능 [reading.recording-coach](recording-coach.md)(기본 꺼짐, 회원 전용)는 이 원칙과 아래 「서버는 음성을 분석하지 않는다」의 예외다 — 녹음을 AI 코치가 듣고 들린 것 하나를 짚는다.

서버는 음성을 분석하지 않는다. 침묵 감지와 말한 것을 글자로 바꾸기(STT)는 우리 서버에서 돌지 않는다. 배역 나누기는 서버가
한다 — 대본 글을 OpenAI(gpt-6-luna)로 보내 배역·대사로 나누며([reading.script](script.md#규칙제약) 「나누기 작업」), 이 처리는
선택 동의 script_split을 따로 받는다. 글자 대조도 서버가 한다 — 기기가 보낸 전사 글을 원문과 맞춰 볼 뿐 음성은 읽지
않는다([reading.session](session.md#규칙제약)). 상대역 목소리도 기본은 기기(Supertonic 3 온디바이스)이고, 배우가 고품질
목소리를 켠 때만 서버가 문장을 합성한다([reading.cloud-voice](cloud-voice.md)). 앱의 STT는 OS 음성 인식을 쓰며, 기기 안 인식만 요구하지 않아
말소리가 OS 음성 인식 제공자(Google·Apple)에게 갈 수 있다(SOMA-741, ADR-037). 처리방침이 이를 알린다. 웹의 STT는 브라우저 음성 서비스라 말소리가 브라우저 제공자에게 가며, 화면과 처리방침이 이를
알린다. 서버가 음성을 건드리는 일은 웹 녹음의 형식 변환과 켠 사람의 상대 대사 합성 둘이고, 어느 쪽도 연기를 분석하지 않는다.
그래서 리딩의 어느 기능도 AI 분석 동의(ai_analysis)를 요구하지 않는다(고품질 목소리는 선택 동의 cloud_voice를, 대본 나누기는
선택 동의 script_split을 받는다). 게스트가 받는 문서는 [account.guest](../account/guest.md#규칙제약)의 기능별 표다. (확정 결정 4,
ADR-031의 「배역 나누기는 기기」는 2026-10-02 실측으로 뒤집었다)


## 용어

| 용어 | 뜻 | 피할 말 |
|---|---|---|
| Script (대본) | 배우가 리딩에 쓰려고 등록한 대본 한 편. 원문과 그것을 나눈 배역·줄의 묶음이다. | 문서, 원고, 시나리오, 텍스트 |
| Script Character (배역) | 대본 안에서 대사를 말하는 인물 하나. 줄은 이름이 아니라 이 id로 배역에 매달린다. Scene Context의 "인물"과 다르다. | 인물, 역할, role(코드 식별자로), 캐릭터 |
| Script Line (줄) | 대본을 순서대로 나눈 한 줄. 종류는 대사·지문·장면 셋이다. "대사 번호"는 대사 줄만 센 순번이다. | 문장, 배열 인덱스, 행(DB 행과 헷갈릴 때) |
| My Characters / Partner Character (내 배역 / 상대역) | 한 리딩 회차에서 배우가 직접 읽기로 고른 배역들이 내 배역, 나머지가 기기가 목소리를 내 읽는 상대역이다. | 주인공, AI 배우, 코치(상대역을 가리켜) |
| Reading Session (리딩 회차) | 리딩 한 번. 영상 연습의 회차(Practice)와 다르다. 리딩 안에서는 "회차"로 줄여 부른다. | 연습(수식 없이), 세션(수식 없이), 녹음 파일 |
| Reading Range (구간) | 한 회차에서 진행할 시작 대사부터 끝 대사까지. | 장면(구간 자체를 가리켜), 범위 번호 |
| Advance / Mask (넘김 / 가리기) | 넘김은 내 차례를 마치고 다음 대사로 가는 방식, 가리기는 어떤 대사 본문을 감출지 정하는 표시 방식이다. | 통과, 성공(넘김을 가리켜), 블러, 암기 상태(가리기를 가리켜) |
| Reading Recording (녹음) | 회차 안에서 내 대사 한 줄을 말한 음성 기록. | 회차 파일, 영상, 오디오 분석 |
| Line Match (대조) | 기기가 말한 것을 글자로 바꾼 결과를 서버가 대본의 말할 내용과 맞춰 보는 처리. | 채점, 정확도, 평가, 암기 판정 |
| Memorization Status (암기 상태) | 배우가 대사 한 줄을 외웠는지 스스로 남긴 표시. | 성적, 등급, 코치의 기억, 외운 줄 수(값을 가리켜) |
| Sample Script (예시 대본) | 대본 등록과 리딩을 바로 겪어 보도록 앱·웹에 내장한 글. 저장하면 보통 대본이 된다. | 공용 대본, 기본 대본, 시스템 대본 |

정본이라 여기 옮기지 않고 링크만 둔다. 2026-10-22 리딩 이슈(SOMA-663·709·646·792·785·597)를 정리하며 만들었고, 같은

## 리딩 자료의 이관·삭제·탈퇴

리딩 기능들이 서로 다르게 말하지 않도록 한 표에 둔다. 각 기능은 여기와 다른 점만 적는다.

| 대상 | 게스트 → 회원 이관 | 대본 삭제 | 회차 삭제 | 탈퇴, 미이관 게스트 30일 파기 |
|---|---|---|---|---|
| scripts | id 그대로, user_id만 바뀜(request_id가 겹치면 게스트 값을 비움) | 행째 삭제 | 그대로 | 행째 삭제 |
| script_characters, script_lines | id·부모 연결 그대로(소유자 컬럼 없음) | 행째 삭제 | 그대로 | 행째 삭제 |
| reading_sessions | id·설정·진행 그대로, user_id 바뀜(request_id 겹침은 대본과 같음) | 행째 삭제 | 행째 삭제 | 행째 삭제 |
| reading_recordings 행 | user_id 바뀜(회차와 함께) | 삭제 | 삭제 | 보관 동의자만 남기고(user_id 유지, 회차·줄 연결을 비움) 나머지는 삭제 |
| 녹음 객체 | 그대로(주인만 바뀜) | 삭제 장부로 지움 | 삭제 장부로 지움 | 보관 동의자는 3년 뒤, 나머지는 즉시 삭제 장부로 지움 |
| line_memorization | 줄 연결 그대로, user_id 바뀜 | 삭제 | 그대로 | 행째 삭제 |
| reading_session_ratings(회차 평가, SOMA-661) | 회차 연결 그대로, user_id 바뀜 | 행째 삭제 | 행째 삭제 | 행째 삭제(한 줄 포함) |
| reading_recording_coaches(녹음 코치 대화, 실험) | 없음(게스트는 쓰지 못한다) | 행째 삭제(회차를 따라) | 행째 삭제 | 행째 삭제(회차를 따라) |
| reading_voice_usage | 없음(게스트는 고품질 목소리를 못 쓴다) | 그대로 | 그대로 | 행째 삭제 |
| script_imports(나누기 요청. 원문은 나누는 동안만, 끝나면 비움) | 없음(게스트는 나누기를 못 쓴다) | 그대로(`script_id`가 지워진 대본을 가리킨다) | 그대로 | 행째 삭제, 진행 중 작업은 ai_jobs 취소 |
| script_uploads(원본 파일. 뽑은 글은 대본에 연결될 때 비움)·원본 객체 | 없음(게스트는 올리지 못한다) | 그 대본에 연결된 행 삭제, 객체는 올리기 주소 시한(15분) 뒤 삭제 장부로 | 그대로 | 행째 삭제(보관 동의와 무관), 객체는 같은 방법으로. 어느 대본에도 연결되지 않은 것은 하루 뒤 같은 방법으로 지운다 |
| 기기 자료(캐시·대기 업로드) | 옛 게스트의 쓰기·재시도를 멈춤 | 그 대본의 것을 지움 | 그 회차의 것을 지움 | 계정 자료를 전부 지움 |

행 삭제는 도중에 실패하면 아무것도 지워지지 않는다. 녹음 객체는 행을 지운 뒤 삭제 장부(account_cleanup_operations)가
지우므로, 객체 삭제가 실패해도 삭제 요청은 성공하고 화면에서는 이미 지워져 있다. 장부의 재시도와 운영자 알림은
[account.withdraw](../account/withdraw.md#상태)의 정리 장부를 따른다.
리딩의 쓰기(등록·수정·회차 시작·진행 저장·녹음 올리기·암기 갱신)는 [저장 직전 재확인](../common.md#저장-직전-재확인)을
따른다. 이관·탈퇴·삭제가 먼저 끝났으면 옛 계정으로 쓰지 않는다.
서버에서 파기된 계정의 기기 자료(캐시·대기 업로드)는 다음 실행이나 계정 상태 확인 때 지운다. 닫힌 기기에서의
즉시 삭제는 보장하지 않는다.
리딩의 쓰기는 게스트의 마지막 활동에 든다([account.guest](../account/guest.md#규칙제약)).
