# 대본 리딩

[쓰는 법](../README.md)과 [공통 규칙](../common.md)을 먼저 읽는다.
영상 연습과 완전히 분리된 영역이다. 리딩 테이블은 users와 scripts에만 매달린다. (ERD 결정)
대본과 리딩 기록은 서버에 저장한다. 원래 기획(read.acttub.com, 2026-07-29)의 "대본은 기기에만"은
2026-09-14 ERD와 2026-09-21 요구사항에서 뒤집었다(ADR-031). 그 근거였던 저작권 문제는 법무 확인 표에 있다.

리딩은 연기를 평가·채점하지 않는다. 점수·등급·"잘했어요" 같은 반응을 내지 않고, 화면 문구는 무엇이
재생 중이고 다음이 누구 차례인지 같은 기능 설명에 그친다. 말한 것을 글자로 바꿔 원문과 맞추는
글자 대조만 예외이며, 그 결과도 "맞음·틀림" 대신 넘어가기·다시·원문 보기·아직 안 나온 줄로 보여 준다.
(상대역 리딩 흐름 메모, 기획 6절)

서버는 대본·음성을 분석하지 않는다. 배역 나누기, 상대역 목소리(Supertonic 3 온디바이스), 침묵 감지, 말한 것을
글자로 바꾸기(STT), 글자 대조는 서버에서 돌지 않는다. 앱의 STT는 기기 안 처리를 보장하는 경우에만 쓰고 아니면
글자 입력으로 바꾼다. 웹의 STT는 브라우저 음성 서비스라 말소리가 브라우저 제공자에게 가며, 화면과 처리방침이 이를
알린다. 서버가 음성을 건드리는 유일한 일은 웹 녹음의 형식 변환이고 내용을 읽지 않는다. 그래서 리딩의 어느 기능도
AI 분석 동의를 요구하지 않는다. (account.guest, 확정 결정 4)

## 리딩 자료의 이관·삭제·탈퇴

다섯 기능이 서로 다르게 말하지 않도록 한 표에 둔다. 각 기능은 여기와 다른 점만 적는다.

| 대상 | 게스트 → 회원 이관 | 대본 삭제 | 회차 삭제 | 탈퇴, 미이관 게스트 30일 파기 |
|---|---|---|---|---|
| scripts | id 그대로, user_id만 바뀜(request_id가 겹치면 게스트 값을 비움) | 행째 삭제 | 그대로 | 행째 삭제 |
| script_characters, script_lines | id·부모 연결 그대로(소유자 컬럼 없음) | 행째 삭제 | 그대로 | 행째 삭제 |
| reading_sessions | id·설정·진행 그대로, user_id 바뀜(request_id 겹침은 대본과 같음) | 행째 삭제 | 행째 삭제 | 행째 삭제 |
| reading_recordings 행 | user_id 바뀜(회차와 함께) | 삭제 | 삭제 | 보관 동의자만 남기고(user_id 유지, 회차·줄 연결을 비움) 나머지는 삭제 |
| 녹음 객체 | 그대로(주인만 바뀜) | 삭제 장부로 지움 | 삭제 장부로 지움 | 보관 동의자는 3년 뒤, 나머지는 즉시 삭제 장부로 지움 |
| line_memorization | 줄 연결 그대로, user_id 바뀜 | 삭제 | 그대로 | 행째 삭제 |
| 기기 자료(캐시·대기 업로드) | 옛 게스트의 쓰기·재시도를 멈춤 | 그 대본의 것을 지움 | 그 회차의 것을 지움 | 계정 자료를 전부 지움 |

DB 삭제는 한 트랜잭션이고, 객체 삭제는 커밋 뒤 삭제 장부(account_cleanup_operations)가 재시도한다.
"삭제 도중 실패하면 아무것도 지워지지 않는다"는 DB 트랜잭션에만 해당하고, 커밋 뒤 객체 삭제 실패는
화면에서는 이미 지워진 채 장부에 남는다. 객체 삭제 작업은 성공할 때까지 대상 키를 지우지 않고, 7일 연속
실패하면 운영자에게 알리고 복구 대상으로 남긴다(제공자 연결 해제 비밀값의 7일 보관과 다르다). (account.withdraw)
리딩의 쓰기(등록·회차 시작·진행 저장·녹음 올리기·암기 갱신)는 최종 저장 직전에 현재 소유자·계정 상태·부모
행의 존재를 같은 트랜잭션에서 다시 확인한다. 이관·탈퇴·삭제가 먼저 끝났으면 옛 계정으로 쓰지 않고 이미 만든
객체는 장부로 정리한다. 이관·탈퇴·삭제는 리딩 행을 잠근 뒤 진행하므로 둘이 겹쳐도 순서가 정해진다.
서버에서 파기된 계정의 기기 자료(캐시·대기 업로드)는 다음 실행이나 계정 상태 확인 때 지운다. 닫힌 기기에서의
즉시 삭제는 보장하지 않는다.
게스트의 마지막 활동에는 대본 등록, 회차 시작, 진행 저장, 녹음 올리기, 암기 상태 갱신이 들어간다.
(account.guest 갱신)
