# reading.recording-coach — 리딩 녹음 코치 (실험)

> **실험 기능 · 기본 꺼짐 · 서버만(SOMA-791).** 리딩의 두 원칙 — 연기를 평가하지 않는다, 서버는 음성을 분석하지 않는다
> ([README](README.md)) — 의 예외다. 스위치 `ACTTUB_RECORDING_COACH_ENABLED=true` 인 배포에만 경로가 있고, 끄면 404 다.
> 앱 화면(리딩 완료 화면의 코치 카드)은 아직 없다. 정식 도입은 실험 결과(리딩 → 영상 업로드 전환)를 보고 제품 결정으로 정한다.

## 무엇
리딩 회차의 내 대사 녹음을 AI 코치(Gemini, 영상 코치와 같은 모델·키)가 듣고 두 차례 답한다. 무료다.

1. **첫 차례** — 녹음에서 실제로 들린 것 하나(속도·쉼·강세·억양·또렷함·크기)를 그 대사로 가리키고, 그 대사를 근거로
   인물의 이유·의도·관계를 묻는 열린 질문 하나.
2. **둘째 차례** — 배우의 답이 녹음과 맞는지 어긋나는지 들린 것으로 짚고, "소리로는 여기까지"라며 그 한 줄을 영상으로
   찍어 보자고 권한다. 권한 줄은 응답의 `video_line` 이다.

표정·시선·몸 같은 신체 원인, 점수·칭찬, 발음 교정·발성 훈련은 말하지 않는다(프롬프트
`apps/api/src/main/resources/reading/recording-coach-prompt.txt`). 운영 영상 코치(practice-loop)의 "음성만이면 발음·속도
같은 기술 평가를 하지 않는다" 규칙과 달리, 이 실험은 들린 것 하나를 짚는 것을 일부러 허용한다.

## 규칙·제약
- **회원 전용**이다. 경로가 `/v2/reading/**` 밖이라 웹 게스트는 쓰지 못한다. 배우의 소리를 AI 가 듣는 일이라 회원 필수
  동의(ai_analysis)의 범위에 둔다.
- **소리가 든 녹음**: 받아쓴 글(stt)이 있으면 비지 않아야 하고, 받아쓰기가 없으면(none) 0.8초보다 길어야 한다. 내 배역의
  대사 줄 녹음만, 줄마다 마지막 녹음만 센다. 셋보다 적으면 422 `recording_coach_not_enough_audio`.
- 한 번에 보이는 녹음은 대본 순서로 20줄·합계 15MB 까지다. 녹음은 저장소에서 받아 인라인 소리로 보내고 임시 파일은 바로 지운다.
- 대화는 **회차마다 하나**다. 같은 회차로 다시 시작하면 모델을 부르지 않고 200 으로 같은 대화를 준다. 둘째 차례가 끝난
  대화에 다시 답해도 모델을 부르지 않고 지금 값을 준다.
- 모델 실패·빈 답은 503 `recording_coach_unavailable`. 남의·없는 회차는 404 `session_not_found`, 남의·없는 대화는 404
  `recording_coach_not_found`. 배우 답은 1~1000자(앞뒤 공백을 걷는다).
- 모델의 숨은 칸(`<설계>`: 들린 것 목록·고른 녹음)은 응답에 싣지 않고 DB(`first_design`)에만 운영 검토용으로 남긴다.
- 저장: `reading_recording_coaches`(V48). 회차·사람에 ON DELETE CASCADE 라 회차 삭제·대본 삭제·탈퇴의 리딩 파기 때
  함께 지워진다. 모델 이름·보인 녹음 수도 남긴다.

- **소리는 서버가 잰 것만 말한다**(10/21 dev 시험에서 모델이 실제 음량과 반대로 말함): 줄마다 apps/pron `POST /measure` 로
  크기·빠르기(글자/초)·가장 긴 쉼·끝 높이·끝 크기를 재고, 다른 줄의 가운데 값과 확실히 다른 것만
  (크기 ±3dB, 빠르기 1.3배, 끝 높이 ±3반음 등 — `RecordingSoundCues`) 대본 뒤 `[서버가 잰 소리]` 칸으로 보인다.
  모델은 그 안에서만 고르고, 후보가 없으면 소리 이야기 없이 질문만 한다. 3초 넘게 쉰 줄(기다린 녹음)은 비교에서 뺀다.
  `PRON_SCORER_URL` 이 없으면 재지 않는다(질문만). 잰 칸은 `first_design` 앞에 함께 남긴다.

## API (스위치를 켠 배포만, OpenAPI 스냅샷 밖)
| 요청 | 응답 |
|---|---|
| `POST /v2/recording-coaches` `{reading_session_id}` | 201 새 대화 · 200 이미 있던 대화 |
| `GET /v2/recording-coaches/{id}` | 200 |
| `POST /v2/recording-coaches/{id}/reply` `{text}` | 200 |

응답: `{id, reading_session_id, status: asked|answered, messages: [{role: coach|actor, text}], video_line: {line_id, text}|null, created_at, updated_at}`

## 남은 것
- 앱: 리딩 완료 화면 카드("방금 녹음으로 코치랑 얘기해 볼래요?", 위에 크게·무료, 발음 보고서 PRO 는 아래 작은 줄),
  [이 한 줄 찍기] → 영상 코칭 연결. 앱 빌드가 필요하다.
- 소리 관찰의 정확도는 사람이 들어 확인하지 않았다.
- 응답 속도: 모델을 요청 안에서 동기로 부른다(스트리밍 없음).
