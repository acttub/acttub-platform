# reading.voice-feedback — 발성 피드백 (실험)

> **실험 기능 · 리딩 원칙의 예외.** 리딩은 연기를 평가·채점하지 않는다([README](README.md)). 이 기능은 그 원칙에서
> 벗어나 "관찰"을 보여 준다. 기본 꺼짐이고, 정식 도입 여부는 제품 결정(ADR)으로 정한다. 점수·등급·칭찬은 여전히 내지 않는다.

## 무엇
설정 「실험 기능 › 발성 피드백 (실험)」을 켜면 리딩이 끝난 화면에 **짚을 곳이 있는 내 대사**만 칩으로 보인다.
짚을 곳이 없는 줄은 보이지 않고, "내 대사 n줄 중 k줄에 짚을 곳"만 적는다.

| 칩 | 판단 (기준값 초안) |
|---|---|
| 알아듣기 어려운 곳이 있어요 | 받아쓰기와 대본의 대조 점수(closeness) < 0.7 |
| 목소리가 작거나 주변이 시끄러워요 | 목소리(상위 5%)와 주변 소리(하위 10%) 차이 < 15dB — 녹음 장치마다 절대 크기가 달라 차이로 본다 |
| 문장 끝이 흐려져요 | 끝 20%가 가운데 60%보다 ≥ 5dB 작음. 2초 미만 대사는 보지 않는다 |
| 조금 빨라요 / 조금 느려요 | 초당 음절(한글 글자 수 ÷ 말한 시간, 긴 멈춤 제외) > 6.5 / < 2.5 |
| 억양이 평평해요 | 음높이 폭(10~90% 반음) < 4 — 인식기 녹음(wav)이 있을 때만 |
| 중간에 오래 멈췄어요 | 대사 중간 0.7초 이상 무음 |

한 줄에 칩은 세 개까지, 위 표의 순서로.

## 규칙·제약
- 분석은 기기 안에서만 한다. 소리·지표는 서버로 보내지 않는다(계측은 칩 이름만: `reading_voice_feedback`).
- 소리: 인식기 녹음(wav, `supportsRecording()` 기기)이면 표본에서 크기·음높이를, 아니면 녹음기 미터링(50ms)으로 크기만 본다.
  피드백이 켜져 있으면 녹음이 꺼진 회차도 인식기 파일을 잠깐 남겨 분석한 뒤 지운다(올리지 않는다).
- 말한 구간이 0.4초 미만이거나 소리를 못 읽으면 그 줄은 건너뛴다.
- 결과는 그 회차 끝난 화면에만 있고 저장하지 않는다.
- 기준값은 TTS 변형·운영 녹음 37개로 잡은 초안이다(2026-10-05). 실녹음이 쌓이면 다시 잡는다.

## 화면
- 설정: 「실험 기능」 카드 토글(기본 꺼짐, 기기에만 저장 `acttub.reading.voiceFeedback`).
- 리딩 끝난 화면: 결과 요약 아래 「발성 피드백」 상자.
