# 2층 대화 평가 — 2026-09-15

## 변경 원칙

사용자가 할 법한 답이 있다고 가정하고 질문·설명을 작성한다. 기대답변은 출력이나 저장 필드가 아니다. 실제 사용자 답이 가정보다 우선한다. 질문만 이어가는 인터뷰와 일방적인 설명 모두 피한다.

## 실행

저장소의 합성 `coaching/record.json`으로 StructuredCoachEngine을 포함한 실제 경로를 호출했다. 실제 사용자 영상·대화는 전송하지 않았다. 로컬 기본 모델은 `gpt-5.6-luna`; dev 환경의 모델 설정과 동일한지는 확인하지 않았다.

- 모름 → 혼란 → 말실수 정정 → 종료
- 배우 목표 → 대사 생각하느라 나온 행동이라는 정정 → 방법 요청 → 종료

프롬프트를 네 차례 평가했다. 최종 실행에서 두 시나리오의 구조·상태·종료 검증은 통과했다. 대화 품질 통과를 뜻하지 않는다. 실호출 테스트는 기본 CI에서 꺼져 있으며 `ACTTUB_COACH_EVAL=1`과 `OPENAI_API_KEY`가 있을 때만 실행한다. 출력은 `apps/api/build/structured-coach-eval`에 저장한다.

## 최종 응답 직접 검토: 배포 보류

| 기준 | 결과 |
|---|---|
| 영상 근거로 대화 시작 | 구체적인 근거는 인용하지만 주로 고개 방향 확인에 머무름 |
| 사용자 정정 반영 | 정정 후 의도 해석을 철회함 |
| 모름·혼란에서 질문 부담 줄이기 | 미흡. 상대 위치 → 누구에게 한 말 → 직전 상황 질문으로 이어짐 |
| 목표를 몸짓의 원인으로 단정하지 않기 | 미흡. 붙잡으려는 목표를 듣고 고개 돌림을 상대를 따라간 것으로 연결함 |
| 방법 요청에 즉시 도움 | 미흡. 근거가 약한 지시나 현재 행동의 정당화가 남음 |
| 종료 요청 존중 | 통과 |
| 기대답변·내부 필드 노출 방지 | 사용자 메시지에서 노출 없음 |
| 비교 실험 요구 금지 | 두 최종 대화에서 비교 실험·재촬영 보고 요구 없음 |

이 PR의 형식 검증 통과만으로 코칭 품질이 개선됐다고 판단하거나 배포하지 않는다. 일반 대화 및 모름·혼란 상황의 의미 평가를 통과해야 한다.
