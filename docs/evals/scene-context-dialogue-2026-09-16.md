# 장면 맥락을 따르는 2층 대화

## 변경

첫 응답에서 시선·음량 같은 특징을 선택하는 대신 대사와 행동의 장면 맥락을 읽는다.
이유가 필요한 경우 구체적인 대사를 짚어 열린 질문을 한다. 이미 이유를 알면 다시 묻지 않는다.
후속 답변은 배우가 설명한 이유를 기준으로 피드백하며, 정정되면 판단도 바꾼다.
배우의 연습 목표(direction)가 없어도 피드백할 수 있다. 인물의 목적은 scene_context에 보존한다.
‘그래서’는 피드백 요구로 취급하며 관찰을 재설명하는 것으로 끝내지 않는다.
음량 차이 자체를 결함으로 삼지 않고 촬영 한계를 고려한다. 잘된 선택도 피드백할 수 있다.

공통 첫 응답 정책과 구조화 코치 프롬프트를 함께 수정했다. API·DB·검증기·모델 설정은 변경하지 않았다.
실제 사용자 영상/대화는 모델 평가나 이 문서에 포함하지 않았다.

## 검증

관련 회귀·구조 테스트 109개 및 새 실제 모델 평가 2개 통과.
평가 모델은 로컬 클라이언트 기본값 gpt-5.6-luna이며 dev의 모델 환경변수와 동일하다는 뜻은 아니다.
프롬프트 예시(돈을 빌려준 장면)와 다른 합성 장면(짐·과거의 떠남·열쇠 요구)을 사용했다.
재현: ACTTUB_COACH_EVAL=1 및 OPENAI_API_KEY가 있는 환경에서 SceneContextConversationEvalTest 실행.
생성 결과는 apps/api/build/scene-context-eval 아래 저장한다. CI 기본 실행에서는 유료 모델 평가는 생략한다.

1. 이유 설명 → 정정 → 도움 요청 → 종료
   - 첫 응답: “아직 네 짐이 여기 있잖아”라고 먼저 말하는 이유가 무엇인가요?
   - 인물의 목적을 정정하자 붙잡는 장면이라는 해석을 거두고 열쇠 요구를 기준으로 피드백했다.
   - 배우가 별도 연습 목표를 선언하지 않아도 피드백했고 direction은 null을 유지했다.
2. 모름 → 혼란 → 도움이 되는 피드백 요구 → 종료
   - 반복 질문 대신 확인된 장면으로 진행했다.
   - “그래서 뭐 어쩌라고” 뒤 마지막 요구를 짧게 끝낸 선택을 유지할 점으로 설명했다.
   - 사용자에게 실패 문구가 나오지 않았고 종료를 존중했다.

## 한계와 판정

첫 실행에서 과거 사건을 새로 만들고 모든 대사를 하나의 목적에 맞추는 경향이 확인되어 프롬프트를 보완했다.
최종 실행에서는 이 사건 추가가 나타나지 않았지만, 같은 속도를 ‘떠나보내지 않겠다는 흐름’과 연결하는
과도한 해석은 남았다. 질문에 답하지 않은 사례에서 장면에 맞다고 단정하는 표현도 완전히 해결되지 않았다.
따라서 두 대화의 구조적 통과는 전체 코칭 품질 보장이 아니다. 실제 모델 응답 원문을 별도 검토했다.
근거 범위·질문 검증으로 내부 재생성이 발생했으나 최종 응답은 정상 반환됐다.
이번 변경은 실패 대체 문구 및 오류 상태 전달을 수정하지 않는다. 해당 오류 경로는 별도 문제로 남는다.
전체 API 통합 검증은 Docker를 제공하는 CI에서 확인한다. dev 배포는 이 변경의 검증 완료와 별개다.
