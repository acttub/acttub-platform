# 2층 응답 선택

## 변경 목적

배우가 요청한 도움에 답한다. 질문을 이어가는 것 자체가 목표가 아니다. 첫 응답은 전체 장면에서 중요한 주제를 고르고, 이후에는 이미 받은 답을 활용한다.

## 서비스 계약

`reply_link.selection`은 현재 요청, 막힌 부분, 이미 확인한 근거, 질문이 필요한 경우 그 정보와 쓰임을 담는다. 장황한 사고 과정이나 예상 정답은 저장하지 않는다. 선택 정보는 서버 상태의 `last_reply`에 남고, 사용자 응답 `CoachReply`에는 메시지·상태·종료 시 노트용 인계만 전달한다. 기존 세션은 다음 응답부터 선택 정보를 기록하므로 별도 데이터 변환은 없다.

`move`는 기존 open/clarify/explain/correct/acknowledge/close에 simplify/suggest/assess/extend를 추가한다. 제안은 실행 사실이 아니며 proposal/attempt 이력으로 만들지 않는다.

서버가 확인하는 것은 구조적 조건이다: 질문의 정보·쓰임 누락, 없는 근거 참조, 관찰 없는 전달 평가, 종료와 추가 질문의 충돌. 질문의 유용성, 이미 답한 내용의 의미상 반복, 해석의 적절성을 완전히 판정하는 장치는 아니다. 이 부분은 실제 모델 대화 평가가 필요하다.

## 합성 대화 검토 기준

| 입력 상황 | 기대하는 도움 | 실패 예 |
| --- | --- | --- |
| 요청 없이 영상 업로드 | 전체 이야기의 역할을 묻는 짧은 첫 질문 | 눈에 띈 마지막 대사만 고르기 |
| 이유를 모르겠음 | 실제 대사 단서를 설명하거나 풀 수 있는 작은 질문 | 관계·사건 목록을 순서대로 질문 |
| 질문 자체가 이해 안 됨 | 직전 질문을 구체적으로 풀어 말하기 | 새 분석 주제로 이동 |
| 목적을 설명한 뒤 방법 요청 | 적용할 행동 하나 제안 | 목적 재확인 또는 불확실성만 설명 |
| 기존 해석에 반박 | 전제 수정 | 동의할 때까지 같은 질문 |
| 의도가 전달됐는지 질문 | 해당 관찰을 근거로 평가 | 대본 문장을 실제 전달 성과로 취급 |
| 상대 음성만 없음 | 배우 자신의 관찰로 가능한 피드백 | 모든 표현 평가 거부 |
| 잘된 연기를 확장하고 싶음 | 성공한 선택의 원리와 적용 맥락 | 결함 발명, 같은 억양 복제 |
| 이해했거나 종료 요청 | 필요한 정리 후 종료 | 질문을 붙여 계속 대화 |

## 검증 범위

`ResponseSelectionTest`는 정보 없는 질문, 근거 없는 평가, 종료 충돌, 구체적인 조언과 실행 이력의 분리를 검증한다. 기존 코칭·노트 테스트와 `CoachReportEndpointIT`는 상태 저장 및 인계 호환성을 검증한다. 실제 모델 평가에는 기존 합성 기록 기반 평가와 위 대화 기준을 함께 사용한다. 실호출을 실행하지 않은 상태에서 대화 품질 개선이 입증됐다고 판단하지 않는다.

2026-09-17 로컬 결과: 코칭·노트 테스트 135개 통과. 실호출 평가 12개는 키/실행 설정 부재로 건너뜀. `CoachReportEndpointIT` 21개는 Docker 부재로 테스트 컨텍스트 시작에 실패했으므로 저장 경로 검증 완료로 세지 않는다. dev 배포는 수행하지 않았다.
