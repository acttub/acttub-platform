# 분석 우선 코칭: 조사와 적용

이 문서는 여러 기법의 공통 도구를 ACTTUB에 맞게 편집한 설계다. 한 기법의 정본이나 보편적인 분석 완료 판정표가 아니다.

## 근거 자료

- [RADA: Acting technique](https://www.rada.ac.uk/about-us/blogs/focus-acting-technique-rada/): 주어진 상황 속 목적 있는 행동, 듣기와 순간별 반응. 상황 이해를 표현 판단의 기반으로 사용한다.
- [HB Studio: The Uta Approach](https://www.hbstudio.org/hagen-institute/the-uta-approach/): 구체적인 상황, 원하는 것과 장애물, 행동·듣기·반응을 강조한다. 모든 배우에게 개인 경험을 요구하는 방식은 제품에 옮기지 않는다.
- [NYFA: Script analysis](https://www.nyfa.edu/student-resources/how-to-analyze-a-script-for-actors/): 대본 사실, 목적과 그 목적을 위한 행동, 장면·비트 전환을 구분한다.
- [NYFA: Character relationships](https://www.nyfa.edu/student-resources/5-tips-for-creating-character-relationships/): 관계와 상대, 상황 속 목적을 함께 고려한다.
- [Atlantic: Script Analysis](https://atlanticactingschool.org/courses/script-analysis/): Practical Aesthetics의 주어진 상황과 실행 가능한 행동, 전체 흐름 분석을 참고했다. 이 과정 전체를 그대로 구현한 것은 아니다.
- [Out of Joint: Actioning](https://www.outofjoint.co.uk/education/actioning.html): 대사·생각에 상대에게 하는 행동을 연결한다. 동사 선택을 배우에게 시험하거나 매 대사에 강제하지 않는다.
- [Nick Hern Books: Actioning](https://www.nickhernbooks.co.uk/actioning): 텍스트를 검토하고 행동을 선택하며 상대에게 생각을 전달하는 연결을 참고했다.

## 프롬프트에 압축한 축

관계·대상 / 주어진 상황·직전 사건 / 목적·중요성 / 장애물 / 행동·속뜻 / 전환·전체 연결.
목적은 얻으려는 결과, 행동은 그것을 얻기 위해 상대에게 하는 일이다. 감정이나 음량·속도를 행동동사로 대체하지 않는다.
전 항목을 묻지 않는다. 답변과 대본에서 이미 아는 내용을 사용하고 현재 쟁점을 이해하는 데 필요한 빈틈 하나만 돕는다.
짧은 목적 답변만으로 분석이 끝났다고 판단하지 않으며, 중요한 연결이 설명되면 표현으로 넘어간다.
분석 완료 점수·등급·고정 단계는 만들지 않는다. 사용자 수준을 단정하지 않고 대목마다 돌아갈 수 있다.
대본 사실, 배우의 선택, 코치의 잠정 해석을 구분한다. 부족한 맥락을 줄거리 창작으로 채우지 않는다.

## 평가

새 합성 실제 모델 사례: 이유 모름 → 직전 사건 → 관계·목적 구체화 / 이미 관계·사건·목적·행동이 분명한 배우.
원문 검토 기준: 모름 직후 표현 평가로 회피하지 않는가, 분석 질문을 기계적으로 반복하지 않는가,
충분한 배우에게 같은 기초 질문을 하지 않는가, 행동동사 정답을 강요하거나 과거 사건을 발명하지 않는가.
실제 사용자 대화·영상은 테스트 입력에 사용하지 않는다. 구조 검사와 의미 평가는 구분한다.

### 실행 결과와 남은 한계

관련 회귀·구조 테스트 109개 통과. 실제 모델 합성 사례 두 개도 구조 검사를 통과했다.
모델은 로컬 기본 gpt-5.6-luna이며 dev 모델 환경변수와 같다고 확인한 것은 아니다.
모름 직후 직전 사건으로 분석을 이어가고, 이유가 충분한 배우에게는 표현 피드백을 제공했다.
그러나 최종 모름 사례에서 사건을 들은 뒤 이미 모른다고 한 이유 질문으로 돌아갔다.
따라서 의미 검토는 완전 통과가 아니다. 추가 규칙에도 이 반복이 남아 자동 배포하지 않는 초안으로 둔다.
초기 실행에서는 직전 사건만 듣고 표현 평가를 하는 실패도 재현되어 이를 금지하는 기준을 보완했다.
분석 평가에 물음표 1개를 강제했던 검사는 자연스러운 안내문도 허용하도록 최대 1개로 바꿨다.
형식 통과로 대화 품질을 보장하지 않는다. 특히 추가적인 분석 대화 다양성 검증이 필요하다.

## 프롬프트 정리 후 재검증

사용자 요청에 따라 지식 저장소 작업은 진행하지 않고 2층 프롬프트의 중복·충돌 지시를 재구성했다.
답하기 어렵다고 한 질문은 보류하고, 사건·관계 등 다른 사실에서 연결을 찾는 흐름을 명시했다.
공통 첫 응답 기준도 대사의 이유를 묻는 시작을 유지하도록 맞췄다.

전체 합성 4사례와 회귀 109개를 실행한 뒤, 첫 질문/양자택일 지시 보완 후 영향받는 합성 2사례와 회귀 109개를 재실행해 통과했다.
최종 분석 모름 사례: 이유 질문 → ㅁㄹ → 직전 사건 질문 → 사건 답변 → 관계 질문 → 관계와 이유 답변 → 표현 피드백.
이 사례는 같은 이유를 재질문하지 않았고 내부 검증 오류 없이 종료했다.
충분한 분석 사례에서는 기초 질문 없이 표현으로 이어졌고, 정정과 명시적 종료도 반영했다.

한계: 혼란 지속 사례에서는 현재 짐과 과거의 떠남을 연결해 과거에도 짐을 두고 갔다고 추정하는 표현이 남았다.
짧은 합성 평가의 통과는 전체 의미 품질 보장이 아니다. 3층·저장 스키마·모델·지식 검색 구조는 변경하지 않았다.
최종 프롬프트는 이번 수정의 구현 완료이며 실제 서비스 대화의 추가 검토는 계속 필요하다.

## 최신 수정: 정보 수집에서 이해를 돕는 질문으로

이 절이 앞선 상황·관계로 이동하는 설계를 대체한다.
모른다는 답 뒤에는 현재 이해되지 않는 연결을 먼저 파악한다. 질문의 선정 기준은 배경 정보의 공백이 아니라
그 답을 생각하는 것이 현재 모르던 부분을 풀어주는가다. 상황·관계도 이 연결에 필요할 때만 묻는다.
과거 경험담과 지금 부탁의 관계를 함께 살핀 뒤, 배우의 답을 코치가 원래 질문의 의미로 연결하는 예시로 교체했다.
또 모르면 다른 정보를 계속 요구하지 않고 대사에서 확인되는 사실과 가능한 해석을 구분해 설명한다.
공통 첫 응답 정책도 같은 기준으로 맞췄다. 이번 수정은 관련 회귀 테스트만 실행했으며 실제 모델 재평가는 아직 수행하지 않았다.
앞 절의 모델 결과는 이전 프롬프트에 대한 결과다.
