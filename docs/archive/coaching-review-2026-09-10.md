# 코칭 개선 및 검증 — 2026-09-10

최신 dev(`30bfea16`) 위에 로컬 코칭 수정을 통합했다. 이 기록 시점에는 PR 생성·머지와 운영 배포를 하지 않았다. API 요청·응답 DTO와 DB 스키마는 유지한다.

## 변경 내용

| 문제 | 변경 |
|---|---|
| 코치에게 하는 질문을 대사로 해석 | 채팅의 기본 의미를 코치에게 하는 말로 지정하고 질문에 먼저 답하도록 수정. 웹·모바일의 질문 버튼은 입력창에 초점을 주며 전송하지 않음 |
| 모른다는 답 뒤 선택지·실험 반복 | 쉬운 설명·예시 우선. 명확한 도움 요청이 반복되면 별도 복구 지시를 전달하고 직전 응답의 완전 반복은 한 번 재생성 |
| 앞선 정정이 요약에 묻힘 | 최근 4문답으로 자르던 제한을 제거해 현재 세션의 대화 원문 전체를 전달. 원문 정정이 이전 요약과 분석 초안보다 우선 |
| 영상 피드백 요청에도 근거를 활용하지 않음 | 1층 관찰 팩 전체의 장면 요약·흐름·소리 측정값·대사 인용·불확실성을 함께 쓰고, 관찰과 해석을 구분. 발음·음가 같은 기술적 질문에는 해당 방법을 설명 |
| 지원하지 않는 업로드·비교 안내 | 채팅은 텍스트 입력이며 모바일 마이크는 받아쓰기임을 명시. 대화 중 새 영상·음성 첨부나 자동 비교를 안내하지 않음 |
| 동의만 받고 실행·개선으로 정리 | 동의·실행·효과를 구분하도록 프롬프트 수정. 도움 버튼 문구와 짧은 모름 응답은 노트를 만들 근거 수에서 제외 |
| 실패해도 질문이 계속되거나 잘못된 노트 생성 | 빈 응답·종료 요청 및 응답 예산 위반을 재검증. 종료 응답 생성이 두 번 실패하면 결론을 만들지 않고 마무리. 그 상태로 노트 생성·재생성하거나 다음 표현 코칭의 분석 근거로 사용하는 것을 차단 |
| 영어 대화 중 한국어 응답 | 대화 언어 유지 지시와 완전히 한국어로 돌아온 응답의 재생성 검사 추가. 인용 대사와 명시적인 언어 변경 요청은 구분 |
| 실제 응답의 강조 기호가 화면에 그대로 노출 | 일반 텍스트 출력을 지시하고 Markdown 강조·제목·코드 기호가 남으면 재생성 |
| 기술적 설명이 원하는 결과를 반복 | 음가·속도 문제에 해당 대사를 이용한 작은 예시를 먼저 설명. 나중에 연습하겠다는 요청도 목적 설명만으로 대신하지 않음 |
| 단순한 장면에도 숨은 심리 추가 | 분석의 ‘표면적 뜻 이상의 의미’ 강제를 제거. 기존 상황·목표 안에서 적게 추정하는 설명을 사용하도록 보강 |

설명·나중에 연습 버튼은 명확한 요청 문장을 입력창에 준비한다. 배우가 보내기를 눌러야 요청한다. 이미 입력한 글은 코치에게 질문 버튼을 눌러도 보존된다.

합성 사례로 1층 근거·이른 정정의 마지막 응답 전달, 반복 도움 복구, 실제 발화 보존, 언어 검사, 실패한 분석의 후속 전달 차단을 검사했다. 최초 실호출은 기존 로컬 코드의 `gpt-5.6-terra`로 실행했고, dev 통합 후에는 dev 기본값인 `gpt-5.6-luna`로 11개를 다시 실행했다. 아래 표는 dev 통합 후의 결과다. 운영 대화와 개인정보는 테스트에 복사하지 않았고, 키를 파일이나 테스트 출력에 기록하지 않았다.

## 실제 응답 검토

| 합성 사례 | 최종 응답에서 확인한 내용 |
|---|---|
| `meta_question` | 질문을 대사로 잘못 이해했다고 인정한 뒤 상황에 직접 답함. 영상에서 확인할 수 없는 장소 분위기·상대 반응은 구분 |
| `repeated_unsure` | 선택지나 실행 요구 없이 약속 확인과 상대에게 답을 받는 의미를 설명. 새 버림받음의 사정은 넣지 않았으며 미확인 동기는 확정하지 않음 |
| `phonetic_correction` | 목적 대신 소리 처리를 다루며 마지막 모음을 붙잡지 않고 끝내는 방법을 설명. 지금 실행할 수 없다는 제약을 수용 |
| `video_feedback` | 1층의 문장 후반 속도와 전체 평균 대비 측정값을 근거로 직접 답함 |
| `missing_audio_evidence` | 음색 관찰이 부족함을 밝히며 녹음 파일 첨부 분석을 지원한다고 안내하지 않음 |
| `agreement_is_not_execution` | 마지막 ‘맞아’에도 tested=false와 observed_change=null을 유지. 노트는 blocked이고 추가 모델 호출 없음 |
| `practice_later` | 즉시 수행을 요구하지 않고 앞부분 말 간격을 뒷부분에 유지하는 방법을 설명 |
| `english_feedback` | 한국어 관찰 자료를 사용하면서 영어로 직접 피드백 |
| `positive_practice_change` | 실제 실행과 배우가 보고한 변화를 보존하고 표현 노트까지 생성. 추가 훈련은 tested=false |
| `safety_context_correction` | 젖은 계단에서 넘어지지 않게 하려는 직접적인 안전 지시만으로 충분하다고 답하고 심리적 의미를 더 찾지 않음 |
| `early_correction_final_summary` | 초반의 ‘이미 확정된 출발’ 정정을 마지막 handoff와 분석 노트까지 유지 |

dev 통합 시 폐기된 별도 받아쓰기 블록을 가정하던 회귀 테스트 2개를 현재 관찰 팩 구조로 수정했다. 최종 테스트는 초기 정정뿐 아니라 장면 흐름·소리 측정값·대사 인용이 마지막 응답까지 전달되는지 확인한다.

실제 응답에서 `delta_pct`의 전체 평균 대비 수치를 앞 구간 대비 수치로 오해하는 사례를 확인해 비교 기준을 명시했다. 속도 사례와 실행 동의 사례 4개를 보완 후 재검토해 전체 평균 대비 수치와 실행 미확인 상태를 확인했다. 한 응답에 `JSON need`라는 내부 형식 메모가 섞여 노출되어, 해당 형태를 재생성 대상으로 추가했다. 영상 피드백 사례를 다시 실행해 메모 없이 평균 대비 수치를 설명하는 응답을 확인했으며 회귀 테스트도 추가했다.

이 표는 저장된 최종 응답을 검토한 결과다. 자동 테스트의 통과 여부만으로 해석 정확성을 판정하지 않았다. 사례마다 한 번의 최종 응답을 확인한 제한적인 합성 회귀 검사이며, 사용자 만족도 상승이나 모든 장면에서의 품질을 보장하지 않는다. 1층 자체의 영상 분석 품질은 이 테스트의 범위에 포함하지 않는다.

재현 테스트는 `CoachQualityEvalTest`와 `src/test/resources/coach/quality-scenarios.json`이다. 테스트는 `.env`를 자동으로 읽지 않는다. 필요한 키를 현재 프로세스의 `OPENAI_API_KEY`로 명시적으로 전달한 상태에서 `apps/api`에서 실행한다.

```sh
ACTTUB_COACH_EVAL=1 ./gradlew test --no-daemon --rerun-tasks --tests '*CoachQualityEvalTest'
```

`ACTTUB_COACH_EVAL_CASES`에 쉼표로 구분한 사례 ID를 주면 해당 사례만 재실행한다. 응답·실호출 수·토큰 사용량은 Git에서 제외되는 `apps/api/build/coach-quality-eval/`에 남는다. 기본 자동 테스트는 API 키가 있어도 `ACTTUB_COACH_EVAL=1`이 없으면 실호출하지 않는다.

## 배포 전 남은 확인

Docker/Postgres 환경에서 `apps/api`의 `./gradlew test --no-daemon`을 완료해야 한다. 실제 배포 환경의 모델 설정이 다르면 그 설정으로 위 합성 사례를 다시 확인해야 한다. 배포 후에는 실제 사용자 세션의 반복 막힘·정정 뒤 응답·대화 종료와 노트 품질을 별도로 관찰해야 한다.

반복 방지와 언어의 서버 검사는 제한적인 규칙이다. 의미만 같은 반복이나 혼합 언어 전체를 자동 판정하는 평가기는 아니다.
