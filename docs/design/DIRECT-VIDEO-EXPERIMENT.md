# 기존 화면에서 Gemini 직접 영상 코칭

이 문서는 2026-09-21 최초 dev 실험 시점의 기록이다. 이후 운영 배포 및 응답별 분류·프롬프트 선택은
[Gemini 직접 영상 코칭](GEMINI-DIRECT-COACHING.md)을 따른다. 현재는 공통 원칙과 선택된 작업 지침을 조합하며,
아래의 단일 공통 프롬프트·dev 기본 활성화 설명은 당시 구성에 해당한다.

기존 `/home`·`/practice/new` 화면과 업로드·대화·저장 흐름을 그대로 사용한다.
별도 테스트 페이지는 제거했다. 프론트 코드는 실험 이전 dev와 동일하다.

`SITE_URL=https://dev.acttub.com`과 `ACTTUB_DIRECT_VIDEO_ENABLED=true`(dev 기본값)에서만 활성화한다.
운영 및 legacy 입력 경로는 바꾸지 않는다.

영상만 올린 신규 연습은 기존 분석 작업에서 업로드 무결성과 길이만 확인하고 빈 관찰 팩을 저장한다.
1층 영상 분석·받아쓰기·분류 모델을 호출하지 않는다. 기존 코치 시작/답변 API가 해당 배우 소유의
원본 영상을 내려받아 Gemini Files에 전달하고, 영상과 현재 세션의 실제 원문 대화로 답을 받는다.
프롬프트는 사용자가 확정한 `DirectVideoPrompts.common()` 하나다. 가상의 첫 발화나 분류 지시는 없다.

대화는 기존 DB·멱등 요청·revision으로 저장하므로 새로고침 후에도 이어진다.
응답 실패는 기존 오류·재시도 흐름을 사용하고 성공하지 않은 발화를 저장하지 않는다.
종료와 최대 10회 코치 응답은 서버가 처리하고, 원문 대화가 담긴 기존 handoff v2로 노트를 만든다.
영상 관찰·배우 의도·실행 여부는 자유 형식 응답에서 임의 추출하지 않으므로 구조화된 관찰 요약은 비어 있다.
노트 생성은 기존 3층이며 2층 공통 프롬프트에 노트 지침을 합치지 않는다.

Gemini 파일은 매 요청 뒤 성공·실패 모두 정리한다. 각 턴에서 원본을 다시 전송하므로 업로드 지연이 생길 수 있다.
원본 저장·삭제, 인증·동의·소유권, 세션 목록과 노트 화면은 기존 동작을 유지한다.
기존 로컬 비교용 `DirectVideoSessions`와 숨겨진 dev API는 호환성을 위해 남기되 공개 페이지는 제공하지 않는다.

롤백은 dev 플래그를 false로 바꾸면 된다. 분석을 건너뛴 실험 세션을 기존 텍스트 분석 경로로 이어갈 수는
없으므로 롤백 후에는 영상을 새로 올린다. DB 마이그레이션과 공개 API 타입 변경은 없다.
