# 기존 화면의 Gemini 직접 영상 코칭

운영 `main`을 기준으로 Gemini 코치 변경만 반영한다. 계정 1.0.0, 새 인증·동의 게이트,
웹·앱 화면 변경, DB 마이그레이션은 이번 배포에 포함하지 않는다.

기존 화면에서 장면 정보를 비워 영상만 올리는 새 연습은 기존 `three_layers_v1` 계약으로 생성한다.
`ACTTUB_DIRECT_VIDEO_ENABLED=true`일 때 분석 작업은 영상 길이와 업로드 무결성만 확인하고,
1층 영상 분석·받아쓰기 모델을 부르지 않는다. 코치가 소유한 원본 영상과 현재 세션 대화 원문을
Gemini에 직접 전달한다. 프롬프트는 사용자가 확정한 `DirectVideoPrompts.common()` 하나다.

API와 화면, 대화 저장·재개·멱등 요청·10회 제한·종료·3층 노트는 기존 것을 사용한다.
별도 실험 페이지나 임시 세션 API는 배포하지 않는다. 구조화된 영상 관찰은 생성하지 않으며,
코치의 자유 형식 응답을 확정된 배우 의도·실행 기록으로 바꾸지 않는다.
매 턴의 Gemini 파일은 응답 뒤 정리한다. 원본 재전송으로 지연이 추가될 수 있다.

배포 워크플로는 `DEPLOY_THREE_LAYERS_ENABLED=true` 및 `DEPLOY_DIRECT_VIDEO_ENABLED=true`를
전달한다. 배포 스크립트는 release.env에 기록하고 API 컨테이너에 실제 반영됐는지 대조한다.
애플리케이션은 직접 영상 플래그가 명시되지 않으면 기존 경로를 유지한다.
기존 GEMINI_API_KEY와 GEMINI_MODEL을 사용하며 새 계정용 키나 SITE_URL 설정을 요구하지 않는다.

롤백은 동일 이미지에서 두 플래그를 false로 명시하거나 직전 운영 이미지로 재배포한다.
분석을 생략한 테스트 세션은 기존 코치 경로로 이어갈 수 없으므로 새 영상을 올린다.
DB 마이그레이션이 없으므로 기존 운영 데이터 구조는 바뀌지 않는다.
