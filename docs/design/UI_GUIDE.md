# UI 디자인 가이드

> **방향 전환 (2026-07-13)**: 제품 방향이 외부 acting-api 기반으로 변경되었다 (`docs/API.md`, ADR-014~015). 관찰 확인 화면과 자기 정리 입력을 전제하는 규칙은 이전 방향 기준이며, 새 표면은 인터뷰(채팅)와 리포트 화면이다.

이 문서는 Acttub에만 필요한 UI 판단 기준을 적는다. Toss 디자인 시스템의 세부 토큰, 컴포넌트 수치, 타이포그래피, 컬러 팔레트는 여기로 옮겨 적지 않고 아래 원문을 직접 참조한다.

- 상세 레퍼런스: `docs/design/Toss-DESIGN.md`
- 원본 복사 출처: `/Users/insung/Downloads/Toss-DESIGN.md`

우선순위:

1. Acttub 제품 정체성과 금지 표현은 이 문서가 우선한다.
2. 시각 스타일, 토큰, 컴포넌트 수치는 `docs/design/Toss-DESIGN.md`를 참조한다.
3. Toss와 Acttub 맥락이 충돌하면 Toss를 그대로 복제하지 않고 Acttub 제품 의도에 맞게 낮춰 적용한다.

## 디자인 원칙
1. 도구처럼 보여야 한다. 마케팅 페이지가 아니라 배우가 매일 영상을 올리고 질문을 이어가는 연습 도구여야 한다.
2. 평가표처럼 보이면 실패다. 질문 대화, 관찰 확인, 자기 정리 입력이 핵심 표면이어야 한다.
3. 신뢰는 장식이 아니라 명료함에서 나온다. 흰 배경, 강한 타이포 위계, 충분한 여백, 낮은 shadow를 사용한다.
4. 모바일 우선이다. 375px 폭에서도 영상 업로드, 맥락 입력, 질문 대화가 막힘없이 이어져야 한다.
5. 한국어 가독성을 우선한다. 긴 문장을 줄이고, 한 화면에는 한 가지 결정만 요구한다.
6. AI가 전면에 나서지 않는다. 사용자가 주인이고, AI는 질문 경로를 돕는 보조자다.
7. 감정적으로 안전해야 한다. 카피와 상태 메시지는 사용자를 평가하거나 몰아붙이는 느낌을 주지 않는다.

## AI 슬롭 안티패턴 — 하지 마라
| 금지 사항 | 이유 |
|-----------|------|
| backdrop-filter: blur() | glass morphism은 AI 템플릿 느낌이 강하고, 도구 UI의 명료함을 해친다. |
| gradient-text | AI SaaS 랜딩처럼 보이며 연습 도구의 신뢰감을 떨어뜨린다. |
| "Powered by AI" 배지 | 기능이 아니라 장식이다. 사용자의 과업에 도움이 되지 않는다. |
| box-shadow 글로우 애니메이션 | 네온 글로우는 평가/AI 데모 느낌을 만든다. |
| 보라/인디고 AI 팔레트 | "AI = 보라색" 클리셰를 피한다. |
| 모든 카드에 동일한 rounded-2xl | 화면 전체가 템플릿처럼 보이고 정보 위계가 흐려진다. |
| 배경 gradient orb | 질문 연습 도구보다 홍보용 랜딩처럼 보인다. |
| 점수 원형 차트, 레이더 차트 | 평가 서비스처럼 보인다. |
| 강점/약점/개선점 카드 | 폐기된 피드백 카드 프레이밍으로 회귀한다. |
| AI 아바타가 코치처럼 판정하는 UI | 사용자가 평가받는 느낌을 받는다. |
| 과한 confetti, sparkles, emoji | 연기 고민을 다루는 안전한 공간의 톤과 맞지 않는다. |

## 색상
세부 색상값은 `docs/design/Toss-DESIGN.md`의 token과 color palette를 참조한다.

Acttub 적용 규칙:

- 밝은 배경, 중립 회색, 파란 액션 컬러를 기본으로 한다.
- Acttub 브랜드 컬러가 확정되면 semantic token만 교체하고 역할은 유지한다.
- 주 액션 컬러는 CTA, 링크, 선택 상태, 현재 step에 사용한다.
- 성공/오류 색은 상태 전달에만 사용하고 장식 색으로 쓰지 않는다.
- 질문 대화 화면에서 AI 메시지를 파란 카드로 과하게 강조하지 않는다. 파란색은 사용자의 주요 액션에 남겨둔다.
- “좋음/나쁨”처럼 평가를 암시하는 색상 매핑은 금지한다.

## 컴포넌트
세부 버튼, 입력, 카드, badge, tab, toast, dialog, toggle 규격은 `docs/design/Toss-DESIGN.md`의 component section을 참조한다.

Acttub 적용 규칙:

- 카드 안에 또 다른 카드 구조를 넣지 않는다.
- 질문 대화 전체를 큰 장식 카드로 감싸지 않는다.
- 반복되는 관찰, 질문, 입력 그룹처럼 명확히 묶어야 하는 단위에만 카드 스타일을 쓴다.
- 버튼은 주요 행동 하나가 가장 강하게 보이게 한다.
- 관찰 확인 버튼은 “맞음 / 아님 / 모르겠음”이 동등하게 안전해 보이도록 배치한다.
- 사용자가 막혔을 때 “힌트 보기”는 secondary action으로 둔다.
- 질문 대화 입력은 질문 아래 또는 하단 action 영역에 두고, 전송/저장 동작을 명확히 한다.
- 아이콘 라이브러리를 도입한다면 `lucide-react`를 우선 검토한다.
- 아이콘은 기능을 보조해야 하며, 의미가 불명확하면 tooltip 또는 `aria-label`을 제공한다.

권장 버튼 카피:

- “분석 시작”
- “이 관찰은 맞아요”
- “아니에요”
- “잘 모르겠어요”
- “다음 질문 보기”
- “내 문장으로 정리하기”
- “세션 마치기”

피해야 할 버튼 카피:

- “평가 받기”
- “점수 확인”
- “약점 보기”
- “정답 보기”
- “AI 피드백 받기”

## 레이아웃
권장 화면 흐름:

```text
Upload
  -> Context Form
  -> Analyzing
  -> Observation Confirm
  -> Question Dialogue
  -> Actor Sentence
  -> Session Summary
```

레이아웃 규칙:

- 첫 화면은 히어로 랜딩보다 바로 영상 업로드와 장면 맥락 입력이 보여야 한다.
- 질문 화면은 한 번에 하나의 질문과 하나의 주요 액션만 눈에 띄게 한다.
- 분석 대기 화면은 spinner만 두지 말고 현재 상태를 짧은 한국어 문장으로 표시한다.
- 관찰 확인 화면은 “AI가 본 단서”와 “내가 확인하는 버튼”을 가깝게 배치한다.
- 종료 화면은 사용자가 쓴 자기 정리 문장을 가장 강하게 보여주고, AI 요약은 보조 정보로 둔다.
- 모바일 375px 기준에서 모든 주요 CTA 텍스트가 어색하게 잘리지 않아야 한다.
- 터치 대상은 Toss 레퍼런스의 모바일 기준을 따른다.
- 데스크톱에서는 영상/장면 맥락 보조 패널과 질문 대화 메인 패널을 나눌 수 있다.

## 타이포그래피
세부 font stack과 hierarchy는 `docs/design/Toss-DESIGN.md`의 typography section을 참조한다.

Acttub 적용 규칙:

- 한국어 가독성을 우선한다.
- 질문 본문은 보조 설명보다 확실히 강해야 한다.
- 사용자의 자기 정리 문장은 종료 화면에서 가장 중요한 텍스트로 취급한다.
- viewport width에 따라 font-size를 직접 scale하지 않는다.
- letter spacing은 기본 0으로 둔다.
- Toss Product Sans 사용 가능 여부가 확정되지 않았으면 `Pretendard`, `SF Pro KR`, `Apple SD Gothic Neo`, `Noto Sans KR`, system sans-serif 계열을 우선 검토한다.

## 애니메이션
세부 motion 값은 `docs/design/Toss-DESIGN.md`의 motion section을 참조한다.

Acttub 적용 규칙:

- 상태 변화 이해를 돕는 데만 사용한다.
- AI가 “대단한 결과를 생성했다”는 느낌의 연출을 피한다.
- 분석 대기 시간이 길어질 수 있으므로 progress copy와 취소/나가기 상태를 명확히 둔다.
- glow pulse, gradient background animation, dramatic reveal은 사용하지 않는다.

## 아이콘
세부 SVG/icon 규칙은 `docs/design/Toss-DESIGN.md`의 iconography section을 참조한다.

Acttub 적용 규칙:

- 업로드, 재생, 일시정지, 전송, 닫기, 뒤로가기, 체크, 경고처럼 익숙한 기능에는 익숙한 심볼을 사용한다.
- 아이콘 색은 `currentColor`를 상속하게 한다.
- 아이콘을 둥근 배경 박스에 반복적으로 넣어 장식하지 않는다.
- AI, magic, sparkle 아이콘은 사용하지 않는다.
