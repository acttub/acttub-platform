# PRD: Acttub

배우가 연습 영상을 올리면 관찰을 뽑아내고, 코치와의 대화를 거쳐 근거 기반 연습 노트를 남기는 연습 도구다.

용어는 루트 [CONTEXT.md](../CONTEXT.md)가 정본이고, 되돌리기 어려운 결정의 기록은 [docs/ADR.md](ADR.md)에 있다. 화면 규칙은 [docs/design/UI_GUIDE.md](design/UI_GUIDE.md), API 계약의 판정 기준은 [apps/api/CONTRACT.md](../apps/api/CONTRACT.md)다. 이 문서는 그 넷이 답하지 않는 것 — **제품이 무엇이고 누구를 위한 것인가** — 만 적는다.

## 목표

근거 있는 질문을 통해, 배우가 자신의 의도와 실제 연기 사이의 간극을 스스로 발견하고 좁혀 캐릭터를 구체화하게 돕는다.

이 제품은 연기 점수나 등급을 매기는 평가 서비스가 아니다. 코치는 영상 관찰과 배우의 답변을 근거로 질문을 이어가고, 연습이 끝나면 관찰과 대화에 근거한 연습 노트로 정리해 준다.

핵심 문제:

- 배우 지망생과 초보 배우는 혼자 영상을 돌려보며 연습하지만, 무엇을 다시 생각해야 하는지 찾기 어렵다.
- 1:1 코칭은 비용과 접근성의 제약이 크고 매일 사용할 수 없다.
- 표정, 동작, 발성 같은 결과만 고치라는 피드백은 배우가 심리와 행동을 분리해서 수행하게 만들 수 있다.

## 사용자

주요 사용자는 연기 영상을 반복적으로 촬영하고 혼자 복기해야 하지만, 매번 전문가에게 코칭받기 어려운 배우다.

1차 대상:

- 연극영화과 입시생
- 연기 전공 재학생
- 현업 초보 배우 — 단편·웹드라마·공연을 준비하며 멘토링을 자주 받을 수 없는 배우

셋을 하나로 묶는 것은 학교나 경력이 아니라 **반복 촬영과 혼자 하는 복기**다. 셋 모두 독백·자유연기·오디션 영상을 반복해서 찍고, 그것을 봐 줄 사람이 매번 있지는 않다.

1차 알파 페르소나:

- 이름: 지윤
- 나이: 19세
- 상황: 연극영화과 입시를 준비하는 재수생
- 행동: 입시 독백을 매일 혼자 촬영하고 돌려본다.
- 문제: 스스로는 무엇이 어색한지 느끼지만, 왜 그렇게 보이는지와 무엇을 다시 생각해야 하는지 잘 찾지 못한다.
- 제약: 1:1 코치는 비싸고 자주 만나기 어렵다.
- 기대: 평가표보다 "내가 장면에서 무엇을 더 생각해야 하는지"를 묻는 파트너가 필요하다.

후속 세그먼트:

- 연기 스터디 그룹
- 입시 학원 또는 개인 코치의 보조 도구
- 보호자가 결제자인 입시 준비 사용자

사용자 요구:

- 영상과 장면 맥락을 가볍게 입력할 수 있어야 한다. 적을 것이 떠오르지 않는 날에도 연습을 시작할 수 있어야 한다.
- 질문은 한 번에 하나씩 나와야 한다.
- 정답 처방이 아니라 스스로 생각을 채우게 돕는 질문을 받아야 한다.

## 제품 구조

**본체는 연습 도구다** — 영상을 올리고, 관찰을 받고, 코치와 대화하고, 연습 노트를 남기는 한 바퀴. 제품의 가치는 여기서 나오고 나머지는 전부 이것을 돕거나 이것으로 돌아오게 만드는 장치다.

| 자리 | 무엇 | 왜 있나 |
|---|---|---|
| 본체 | 연습 도구 | 제품의 가치가 여기서 나온다 |
| 성능 | **Actor Memory** | 코치가 지난 연습에서 알아낸 것을 알고 시작한다 — 연습 도구를 더 잘 듣게 만든다 |
| 부가 | **Admissions** | **유입** — 입시 정보를 찾다 들어온다 |
| 부가 | **Community** | **리텐션** — 배우가 다시 오게 만든다 |
| 부가 | 푸시 알림 | **리텐션** — 분석이 끝났을 때·연습이 뜸할 때 부른다 |

부가 기능은 연습 자체를 낫게 만들지 않는다. 커뮤니티와 연습은 사람만 공유하고 데이터가 이어져 있지 않다 — 연습에서 무엇을 했는지는 커뮤니티로 흘러가지 않는다.

## 연습 도구

연습 하나는 **Practice Stage** 여섯을 지난다. 화면이 어떻게 나뉘는지는 [docs/design/UI_GUIDE.md](design/UI_GUIDE.md)에 있다.

```text
준비 -> 막힘 선택 -> 업로드 -> 분석 -> 대화 -> 연습 노트
```

### 준비

- Google 또는 Apple 계정으로 로그인한다.
- 연기 영상을 한 장면(5분 이내) 단위로 올린다. 양쪽 다 클라이언트에서 긴 변 720px로 압축해 서버 재압축을 건너뛰게 한다. 웹은 압축 결과가 100MB를 넘으면 올리기 전에 거부하고, 앱은 원본 크기만 본다.
- **Scene Context**(상황·인물·목표)를 적는다. **선택 입력이다** — 안 적어도 연습을 시작할 수 있다(ADR-021).
  - 웹은 세 칸이 모두 비었을 때 건너뛰기를 띄우고, 건너뛴 값을 빈 문자열로 저장해 끝까지 다시 묻지 않는다.
  - 앱은 건너뛰기 버튼 없이 빈 칸 그대로 지나가고, 빈 칸을 웹과 같은 빈 문자열로 보낸다. 예전 앱 빌드가 보내던 자리표시자(`.`)는 서버가 빈 값으로 저장한다.
- 준비 화면 안에서 사람이 채우는 순서는 **Setup Step** 셋이다 — 영상 올리기 · 장면 적기 · 질문 받기.
- 여기서 노리는 것은 짧은 줄 몇 개만으로, 또는 한 줄도 안 적고도 첫 연습을 시작하게 하는 것이다.

### 막힘 선택

- 무엇에 막혔는지 고른다(**Blockage Selection**). 큰 갈래를 고르고 필요하면 하위 갈래와 상세를 고른다.
- 이 값이 동작을 가른다 — 코치가 어느 프롬프트를 쓸지, 연습 노트를 어느 틀로 쓸지가 여기서 갈린다. 받아쓰기는 갈래와 무관하게 세 갈래 모두에서 돈다.
- 고르지 않고 지나갈 수 있다 — 웹은 "잘 모르겠어요"를 고르거나 아무것도 고르지 않고 시작하면, 앱은 "잘 모르겠어요 · 건너뛰기"를 누르면 둘 다 중립값 `"그 외"`를 보낸다(ADR-021 개정). 이 값이 받아쓰기를 끄지는 않는다.

### 업로드·분석

- 올린 영상과 Scene Context로 **Observation**을 만든다. 6축 관찰과 이상 구간으로 이루어진다(ADR-AI-004).
- **연습을 시작할 때 한 번만 분석한다**(ADR-AI-003). 대화 도중에 다시 분석하지 않는다.
- 배우의 실제 성격·가족관계·트라우마·정신상태를 추론하지 않고, 계측치를 지어내지 않는다.

### 대화

- 채팅 화면이고, 질문은 한 번에 하나씩 표시한다.
- 목적은 배우가 자신의 의도와 실제 연기 사이의 간극을 스스로 발견하도록 돕는 것이다(ADR-004).
- **대화를 임의로 끊는 버튼은 없다.** 배우가 답변에 종료 의사를 적거나("그만"·"종료"·"끝"·"여기까지"), 코치가 응답으로 마무리를 알린다. 화면의 "연습 마치기"는 대화가 아니라 **연습을 끝내고 나가는** 버튼이다.
- 코치는 판정하지 않는다. 점수·등급을 매기지 않고, 결과를 처방하기보다 그 결과를 만든 생각·심리·상황·관계·목표를 묻는다.

### 연습 노트

- 대화가 끝나면 그 연습의 연습 노트를 만들어 보여준다. 배우가 대화에서 스스로 말한 것이 가장 크게 보인다.
- **나눈 이야기가 짧으면 노트가 남지 않는다.** 그때는 노트 대신 그 사실을 말해 주고 연습을 마친다 — 남길 근거가 없는 노트를 지어내지 않는다.
- 이전 연습의 노트 목록을 볼 수 있다. 보존을 약속한 데이터는 백엔드 DB가 정본이다(ADR-008).
- 노트는 그 연습 하나만 말한다. **이전 연습과 견주지 않는다** — 연습을 가로지르는 연결은 Actor Memory가 맡는다.
- 끝난 연습에서 **이어서 새 연습**을 시작할 수 있다. 코치가 그 연습의 대화를 이어받는다. 장면을 미리 채워 주는 것은 **앱에서 방금 끝낸 연습의 노트로 이어갈 때뿐**이고, 지난 기록에서 이어가거나 웹에서 이어갈 때는 빈 준비 화면에서 시작한다.

### Actor Memory

배우 한 사람에 대해 연습을 가로질러 남는 값이다. 무엇이 어떻게 쌓이는지는 [CONTEXT.md](../CONTEXT.md)가 정본이다.

제품에서의 자리는 **연습 도구의 성능**이다 — 코치가 지난 연습에서 알아낸 것을 알고 시작하므로 같은 이야기를 다시 묻지 않는다. 연습 하나로 닫히지 않는 것을 이쪽이 맡는다. 노트가 이전 연습과 견주지 않아도 연습들이 이어지는 것은 이것 때문이다.

## 부가 기능

### Admissions — 유입

연기·뮤지컬 실기 전형 공고 카탈로그다. 대학 모집요강을 사람이 읽어 정리하고, 마감이 가까운 순으로 보여준다. 로그인 없이 볼 수 있는 표면이라 입시 정보를 찾던 사람이 제품으로 들어오는 입구가 된다.

### Community — 리텐션

배우들이 글과 댓글을 주고받는 자리다. 무엇이 여기 속하는지는 [CONTEXT.md](../CONTEXT.md)가 정본이다. 연습 자체를 낫게 만들지는 않고, 배우가 다시 오게 만드는 쪽이다.

### 푸시 알림 — 리텐션

분석이 끝났을 때와 연습이 뜸할 때 부른다. 앱에만 있다.

## 웹과 앱

**웹과 앱은 같은 제품이고, 연습 한 바퀴는 양쪽에 다 있다.** 한쪽에만 있는 연습 화면은 없다. 그러나 **준비 화면의 정책은 아직 갈려 있다** — 표의 ⚠ 두 행이다.

| 기능 | 웹 | 앱 |
|---|---|---|
| 연습 한 바퀴 | ✅ 라우터 이동 없이 한 화면에서 | ✅ 라우트로 나뉘어 |
| 이어서 새 연습 | ✅ 장면은 새로 적는다 | ✅ 방금 끝낸 연습에서만 장면이 채워진다 |
| 연습 기록 | ✅ | ✅ |
| Actor Memory | ✅ | ✅ |
| Community | ✅ 신고·차단 포함 | ✅ 신고·차단 없음 |
| Admissions | ✅ | ✅ |
| 푸시 알림 | ❌ | ✅ |
| 설정(이름·동의 관리·회원 탈퇴) | ❌ 로그아웃만 | ✅ |
| 랜딩·앱 다운로드 안내 | ✅ | ❌ |
| Scene Context 건너뛰기 | 버튼 + 빈 문자열 저장 | ⚠ 버튼 없음 · 빈 문자열 저장 |
| 막힘 건너뛰기 | 버튼 없음 · 고르지 않으면 `"그 외"`를 보낸다 | 버튼 있음 · `"그 외"`를 보낸다 |

갈리는 이유는 셋이고 서로 다르다.

- **표면의 성격** — 검색으로 처음 닿는 곳은 웹이고, 알림을 받을 수 있는 것은 앱이다. 랜딩과 푸시가 여기 속한다.
- **스토어 심사** — 계정 삭제를 앱 안에서 찾을 수 있는지 보기 때문에 설정 화면이 앱에 있다.
- **⚠ 는 이유가 아니라 부채다** — ADR-021이 정한 정책을 앱이 아직 다 따라오지 못했다. 그 ADR 자신이 "웹과 모바일의 정책이 갈린다 … 두 앱을 같은 제품으로 설명하기 어려워진다(별도 티켓)"고 적어 둔 자리표시자 갈림은 서버가 `.`을 빈 값으로 저장하면서 닫혔고, 막힘 건너뛰기도 두 앱이 같은 값을 보내고 서버가 같게 다루므로 닫혔다(ADR-021 개정). 남은 것은 Scene Context 건너뛰기 버튼 부재다. 새 화면을 만들 때 이 행을 근거로 삼지 않는다.

## 지금 하지 않는 것

지금 기준으로 다시 센 목록이다. **이미 있는 것을 여기 적지 않는다** — 이 절이 낡으면 다음 사람이 있는 기능을 새로 만들려 든다.

- 점수, 등급, 레벨, 랭킹, 4축 평가, 평가표 (ADR-005)
- 강점·약점·개선점 카드 — 폐기된 피드백 카드 프레이밍이다
- 관찰 확인(맞음/아님/모르겠음) 화면과 배우가 직접 쓰는 자기 정리 문장 (ADR-014) — 그 역할은 대화와, 대화에서 배우가 한 말을 담는 노트 칸(`actor_discovery`·`actor_words`)이 대신한다
- 배우 개인 심리, 트라우마, 치료적 영역을 파고드는 질문
- 첫 촬영 잠금, 전/후 비교 (ADR-007) — 영상 비교도, 노트끼리의 비교도 없다
- 대화 도중 재분석, 건너뛴 Scene Context를 나중에 채우는 **화면** (ADR-021)
- 멀티모달 파인튜닝 (ADR-010)
- YouTube 영상 원본·오디오·프레임·자막의 저장·캐싱·백업·자체 서버 보관·RAG 인덱싱 (ADR-011) — 참고 영상은 공식 임베드로만 보여준다
- "비슷한 프로 배우 영상" 추천 표현 — 쓴다면 "참고할 수 있는 장면 예시"로 낮춘다

## 디자인

- 과한 UI보다 조용한 연습실 톤 우선.
- 제품 화면은 마케팅 랜딩이 아니라 매일 쓰는 연습 도구처럼 보여야 한다.
- "Powered by AI" 같은 장식 배지, 보라색 AI SaaS 느낌, gradient orb, glassmorphism, 과한 glow animation은 사용하지 않는다.

적용 규칙과 금지 표현의 전문은 [docs/design/UI_GUIDE.md](design/UI_GUIDE.md)에 있고, 색상값·컴포넌트 수치는 [docs/design/Toss-DESIGN.md](design/Toss-DESIGN.md)를, 랜딩·대화 화면 구조는 [docs/design/telta-interview-pro.md](design/telta-interview-pro.md)를 참조한다(ADR-012).
