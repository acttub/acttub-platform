# PRD: Acttub

AI와 함께하는 연기연습

## 목표

근거 있는 질문을 통해, 배우가 자신의 의도와 실제 연기 사이의 간극을 스스로 발견하고 좁혀 캐릭터를 구체화하게 돕는다.

이 제품은 연기 점수나 등급을 매기는 평가 서비스가 아니다. AI는 영상 관찰과 배우의 답변을 근거로 질문을 이어가고, 세션이 끝나면 관찰과 대화에 근거한 리포트로 정리해 준다.

핵심 문제:

- 배우 지망생과 초보 배우는 혼자 영상을 돌려보며 연습하지만, 무엇을 다시 생각해야 하는지 찾기 어렵다.
- 1:1 코칭은 비용과 접근성의 제약이 크고 매일 사용할 수 없다.
- 표정, 동작, 발성 같은 결과만 고치라는 피드백은 배우가 심리와 행동을 분리해서 수행하게 만들 수 있다.

## 사용자

주요 사용자는 연기 영상을 반복적으로 촬영하고 혼자 복기해야 하지만, 매번 전문가에게 코칭받기 어려운 배우 지망생과 초보 배우다.

1차 알파 페르소나:

- 이름: 지윤
- 나이: 19세
- 상황: 연극영화과 입시를 준비하는 재수생
- 행동: 입시 독백을 매일 혼자 촬영하고 돌려본다.
- 문제: 스스로는 무엇이 어색한지 느끼지만, 왜 그렇게 보이는지와 무엇을 다시 생각해야 하는지 잘 찾지 못한다.
- 제약: 1:1 코치는 비싸고 자주 만나기 어렵다.
- 기대: 평가표보다 “내가 장면에서 무엇을 더 생각해야 하는지”를 묻는 파트너가 필요하다.

우선 세그먼트:

- 연극영화과 입시생
- 연기 전공 재학생
- 독백, 자유연기, 오디션 영상을 반복 촬영하는 배우 지망생
- 멘토링을 자주 받을 수 없는 초보 배우

후속 세그먼트:

- 단편 영화, 웹드라마, 공연 준비 배우
- 연기 스터디 그룹
- 입시 학원 또는 개인 코치의 보조 도구
- 보호자가 결제자인 입시 준비 사용자

사용자 요구:

- 영상과 장면 맥락을 가볍게 입력할 수 있어야 한다.
- 질문은 한 번에 하나씩 나와야 한다.
- 정답 처방이 아니라 스스로 생각을 채우게 돕는 질문을 받아야 한다.

## 핵심 기능

현재 MVP는 별도 배포된 acting-api에 의존한다. 엔드포인트와 요청/응답 계약은 `API.md`를 따른다.

### 1. 사용자 입력

- Google 로그인으로 사용자를 식별한다.
- 연기 영상을 한 장면(5분 이내) 단위로 업로드한다. 클라이언트에서 모바일 앱과 같은 규격(긴 변 720px, 6MB 목표)으로 압축해 서버 재압축 단계를 건너뛰게 하고, 실제 업로드 파일이 100MB를 초과하면 업로드 전에 거부한다.
- 장면 맥락을 입력한다:
  - 상황: 장면에서 무슨 일이 벌어지는지
  - 인물 설정: 누구이며 상대와 어떤 관계인지
  - 서브텍스트: 겉으로 보이는 태도와 실제 속마음의 차이
- 입력 순서는 영상 업로드, 미리보기, 상황 입력, 인물 설정 입력, 서브텍스트 입력, 분석 시작 순서다.
- 목표는 짧은 줄 몇 개만으로 첫 세션을 시작하게 하는 것이다.

### 2. 연기 연습 분석

- 업로드된 영상과 장면 맥락을 세션 시작 시 1회 분석한다.
- `situation`, `character`, `subtext`, `video`만 acting-api에 전달한다.
- 분석 동작과 출력은 acting-api의 `POST /summarize` 계약을 따른다 (`API.md` 참조).

### 3. AI 인터뷰

- 채팅 화면으로 만든다.
- 질문은 한 번에 하나씩 표시한다.
- 목적: 배우가 자신의 의도와 실제 연기 사이의 간극을 스스로 발견하도록 돕는다.
- 사용자가 임의 종료할 수 있는 버튼은 포함하지 않는다. 인터뷰 종료는 클라이언트가 판단하지 않고 API가 응답으로 알려주는 종료 조건을 따른다.
- 배우가 답변에 `그만`, `종료`, `끝`을 쓰면 인터뷰가 종료된다 (버튼 대신 대화로 종료).
- 인터뷰 중 이탈은 브라우저 탐색(뒤로가기)으로 한다. 세션이 acting-api 인메모리에 있어 중단된 인터뷰의 이어하기는 보장하지 않으며, 세션이 사라졌으면(404) 처음부터 다시 시작한다.
- 대화 진행은 acting-api의 `POST /coach/start`(첫 질문), `POST /coach/reply`(이후 turn) 계약을 따른다 (`API.md` 참조).

### 4. 리포트

- 인터뷰가 끝나면 세션 리포트를 생성해 보여준다.
- 사용자는 자신의 이전 연습 리포트 목록을 볼 수 있다. 목록은 플랫폼 DB에 복제 저장된 리포트에서 조회한다 (ADR-015 참조).
- 같은 사용자의 이전 리포트가 있으면 리포트에 비교(`comparison`)가 포함된다.
- 리포트 생성은 acting-api의 `POST /report` 계약을 따른다 (`API.md` 참조).

## MVP 제외 사항

- 연습 종료 후, 그 연습의 내용을 유지한 채 이어서 하는 추가 연습 (이전 리포트 열람은 가능)
- 점수, 등급, 레벨, 랭킹
- 4축 평가, 평가표
- 배우 개인 심리, 트라우마, 치료적 영역을 파고드는 질문
- retake 기능, 첫 촬영 잠금, 같은 장면 전/후 영상 비교
- 모바일 앱
- Spring Boot 정식 백엔드 구현
- 멀티모달 파인튜닝
- YouTube 영상 원본, 오디오, 프레임, 자막 다운로드/저장/캐싱/RAG 인덱싱
- “비슷한 프로 배우 영상” 추천 표현

## 임시 API와 향후 백엔드 이전

- 초기 제품 개발 중에는 `apps/web`의 Next.js Route Handler로 `/api/v1/*` 임시 API를 만들 수 있다.
- UI는 route handler 구현에 직접 결합하지 않고 `src/lib/api/*`를 통해 API를 호출한다.
- HTTP path, DTO, status code, validation 규칙은 향후 `apps/api`의 Spring Boot 백엔드로 이전할 수 있게 안정적으로 유지한다.

## 디자인

- 과한 UI보다 조용한 연습실 톤 우선
- 제품 화면은 마케팅 랜딩이 아니라 매일 쓰는 연습 도구처럼 보여야 한다.
- AI 관련 장식 배지, 보라색 AI SaaS 느낌, gradient orb, glassmorphism, 과한 glow animation은 사용하지 않는다.
