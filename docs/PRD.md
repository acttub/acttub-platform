# PRD: Acttub

배우가 연습 영상을 올리면 관찰을 뽑아내고, 코치와의 대화를 거쳐 근거 기반 연습 노트를 남기는 연습 도구다.

다른 문서가 무엇의 정본인지는 루트 [CLAUDE.md](../CLAUDE.md) 「조건부 정본」이 정한다. 이 문서는 **제품이 무엇이고 누구를 위한 것인가** 만 적는다.

## 목표

근거 있는 질문을 통해, 배우가 자신의 의도와 실제 연기 사이의 간극을 스스로 발견하고 좁혀 캐릭터를 구체화하게 돕는다.

이 제품은 연기 점수나 등급을 매기는 평가 서비스가 아니다. 코치는 영상 관찰과 배우의 답변을 근거로 질문을 이어가고, 연습이 끝나면 관찰과 대화에 근거한 연습 노트로 정리해 준다.

핵심 문제:

- 배우 지망생과 초보 배우는 혼자 영상을 돌려보며 연습하지만, 무엇을 다시 생각해야 하는지 찾기 어렵다.
- 1:1 코칭은 비용과 접근성의 제약이 크고 매일 사용할 수 없다.
- 표정, 동작, 발성 같은 결과만 고치라는 피드백은 배우가 심리와 행동을 분리해서 수행하게 만들 수 있다.

## 사용자

주요 사용자는 연기 영상을 반복적으로 촬영하고 복기해야 하지만, 매번 전문가에게 코칭받기 어려운 배우다.

현재 대상:

- 연극영화과 입시생
- 연기 전공 재학생
- 현업 초보 배우 — 단편·웹드라마·공연을 준비하며 멘토링을 자주 받을 수 없는 배우
- 연기 스터디 그룹
- 보호자가 결제자인 입시 준비 사용자

모두를 하나로 묶는 것은 학교나 경력이 아니라 **반복 촬영과 복기**다. 모두 독백·자유연기·오디션 영상을 반복해서 찍고, 그것을 봐 줄 전문가가 매번 있지는 않다.

후속 세그먼트:

- 입시 학원 또는 개인 코치의 보조 도구

사용자 요구:

- 영상과 장면 맥락을 가볍게 입력할 수 있어야 한다. 적을 것이 떠오르지 않는 날에도 연습을 시작할 수 있어야 한다.
- 질문은 한 번에 하나씩 나와야 한다.
- 정답 처방이 아니라 스스로 생각을 채우게 돕는 질문을 받아야 한다.

## 제품 구조

**본체는 연습 도구다** — 영상을 올리고, 관찰을 받고, 코치와 대화하고, 연습 노트를 남기는 한 바퀴. 제품의 가치는 여기서 나오고 나머지는 전부 이것을 돕거나 이것으로 돌아오게 만드는 장치다.

| 자리 | 무엇 | 왜 있나 |
|---|---|---|
| 본체 | 연습 도구 | 제품의 가치가 여기서 나온다 |
| 성능 | **Actor Memory** | 코치가 지난 연습에서 알아낸 것을 알고 시작한다 — 연습 도구를 더 잘 듣게 만든다 |
| 부가 | **대본 리딩** | 상대 없이도 장면의 흐름 안에서 자기 대사를 말해 보고 외운다 |
| 부가 | **Admissions** | **유입** — 입시 정보를 찾다 들어온다 |
| 부가 | **챌린지** | **리텐션** — 같은 대사를 연기한 영상을 서로 보고 반응한다 |
| 부가 | 푸시 알림 | **리텐션** — 돌아올 때를 알려 준다 |
| 계정 | 게스트·회원, 프로필, 포트폴리오 | 웹은 로그인 없이 써 보고, 앱에서 회원으로 이어 간다 |

부가 기능은 연습 자체를 낫게 만들지 않는다. 대본 리딩과 챌린지는 연습과 사람만 공유하고 연습의 관찰·대화·노트가 그쪽으로
흘러가지 않는다. Community(게시판)는 0.1.0에서 내렸다([커뮤니티 스펙](specs/community/README.md)).

## 기능

무엇을 어떻게 하는지는 [기능 스펙](specs/README.md)이 정본이다. 여기에는 기능마다 무엇을 하는지와 제품이 지키는 선만 둔다.

### 연습 도구

연습 하나가 지나는 화면 단계는 [ARCHITECTURE 「연습 화면의 전환」](ARCHITECTURE.md#연습-화면의-전환)에 있다.

- **준비** — 영상을 새로 찍거나 보관함에서 고르고, 장면 맥락(상황·인물·목표)과 막힌 곳을 적는다. 둘 다 건너뛸 수 있다 —
  적을 것이 떠오르지 않는 날에도 연습을 시작하게 하는 것이 목표다(ADR-021). → [practice.start](specs/practice/start.md)
- **분석** — 올린 영상을 코치가 읽을 수 있게 준비한다. 무엇을 뽑고 코치가 영상을 어떻게 보는지는 코칭 경로마다 다르다.
  → [practice.analyze](specs/practice/analyze.md), [practice.coach](specs/practice/coach.md)
- **대화** — 코치는 영상과 배우의 답을 근거로 질문을 이어가, 배우가 자신의 의도와 실제 연기 사이의 간극을 스스로 발견하게
  돕는다(ADR-004). → [practice.coach](specs/practice/coach.md)
- **연습 노트** — 대화가 끝나면 그 연습에서 나온 것을 노트로 남긴다. 남길 근거가 없으면 지어내지 않는다.
  → [practice.note](specs/practice/note.md)
- **이어하기** — 끝난 연습에서 같은 영상이나 새 영상으로 다음 회차를 만든다. → [practice.resume](specs/practice/resume.md)
- **보관함** — 영상은 연습과 따로 남는 자산이라 다시 골라 쓸 수 있다. →
  [practice.record](specs/practice/record.md), [practice.library](specs/practice/library.md)
- **이탈 설문** — 대화나 노트에서 나갈 때 서비스 사용 소감을 한 번 묻는다. 연기 평가가 아니다.
  → [practice.feedback](specs/practice/feedback.md)

### Actor Memory

배우 한 사람에 대해 연습을 가로질러 남는 값이다. 연습 하나로 닫히지 않는 것을 이쪽이 맡는다 — 노트가 이전 연습과 견주지
않아도 연습들이 이어지는 것은 이것 때문이다. → [practice.memory](specs/practice/memory.md)

### 대본 리딩

대본을 넣으면 기기가 배역과 줄을 나누고, 상대역 대사를 기기 목소리로 읽어 주며 내 차례에서 기다린다. 내 대사를 녹음하고
외웠는지 스스로 표시한다. 리딩도 연기를 판정하지 않는다. → [대본 리딩 스펙](specs/reading/README.md)

### Admissions

연기·뮤지컬 실기 전형 공고 카탈로그다. 대학 모집요강을 사람이 읽어 정리하고, 마감이 가까운 순으로 보여준다. 로그인 없이
본다. 데이터를 넣고 검사하는 법은 [admissions README](../apps/api/src/main/resources/admissions/README.md)에 있다.

### 챌린지

대사 한 줄과 기간이 주어지면 배우들이 그 대사를 연기한 영상을 올리고, 서로의 영상에 좋아요·댓글을 남기며 좋아요순 랭킹을
본다. 내 참여작은 AI 리포트로 다른 참여작과의 관찰 차이를 설명받을 수 있다. 다른 사람이 보는 콘텐츠라 신고와 차단이 함께
있다. 회원·앱 전용이다. → [챌린지 스펙](specs/challenge/README.md)

### 푸시 알림

분석이 끝났을 때, 챌린지에 반응이 왔을 때 서버가 부르고, 연습이 뜸한 날 저녁에는 폰이 스스로 부른다. 앱에만 있다.
→ [account.notification](specs/account/notification.md)

### 계정

- 로그인(구글·애플·카카오·네이버)은 앱에만 있다. 웹은 로그인 없이 **게스트**로 연습과 리딩을 써 보고, 앱에서 코드를 넣어 자료를
  회원 계정으로 옮긴다(ADR-028). → [account.login](specs/account/login.md), [account.guest](specs/account/guest.md)
- 회원은 동의 문서와 프로필 필수 항목을 마쳐야 기능을 쓴다. 프로필은 코치가 읽는 값이다.
  → [account.consent](specs/account/consent.md), [account.profile](specs/account/profile.md)
- 포트폴리오는 오디션에 낼 소개글·경력·사진이고 공유 링크로 로그인 없이 보인다. 프로필과 다르다(ADR-030).
  → [account.portfolio](specs/account/portfolio.md)
- 탈퇴는 앱 설정에 있다. → [account.withdraw](specs/account/withdraw.md)

## 웹과 앱

**웹과 앱은 같은 제품이고, 연습 한 바퀴는 양쪽에 다 있다.** 한쪽에만 있는 연습 화면은 없다. 그러나 **준비 화면의 정책은 아직 갈려 있다** — 표의 ⚠ 행이다.

| 기능 | 웹 | 앱 |
|---|---|---|
| 계정 | 게스트(로그인 없음), 이관 코드 받기 | 회원 로그인, 이관 코드 넣기 |
| 연습 한 바퀴 | ✅ 라우터 이동 없이 한 화면에서 | ✅ 라우트로 나뉘어 |
| 이어하기 | ✅ | ✅ (장면을 미리 채우는 경우는 [practice.resume](specs/practice/resume.md)) |
| 연습 기록·보관함 | ✅ | ✅ |
| Actor Memory | ✅ | ✅ |
| 대본 리딩 | ✅ | ✅ |
| Admissions | ✅ | ✅ |
| 챌린지 | 참여작 공유 페이지만(`/e/<id>`) | ✅ |
| 포트폴리오 | 공개 페이지만 | ✅ 편집 |
| 푸시 알림 | ❌ | ✅ |
| 설정(프로필·동의·알림·탈퇴) | ❌ | ✅ |
| 랜딩·앱 다운로드 안내 | ✅ | ❌ |
| Scene Context 건너뛰기 | 버튼 + 빈 문자열 저장 | ⚠ 버튼 없음 · 빈 문자열 저장 |
| 막힘 건너뛰기 | 버튼 없음 · 고르지 않으면 `"그 외"`를 보낸다 | 버튼 있음 · `"그 외"`를 보낸다 |

갈리는 이유는 넷이고 서로 다르다.

- **표면의 성격** — 검색으로 처음 닿는 곳은 웹이고, 알림을 받을 수 있는 것은 앱이다. 랜딩과 푸시가 여기 속한다.
- **계정** — 웹은 설치 없이 바로 써 보는 자리라 로그인으로 막지 않는다. 회원 자료는 앱에서만 본다(ADR-028). 챌린지·포트폴리오
  편집처럼 회원만 쓰는 기능이 앱에 있는 이유다.
- **스토어 심사** — 계정 삭제를 앱 안에서 찾을 수 있는지 보기 때문에 설정 화면이 앱에 있다.
- **⚠ 는 이유가 아니라 부채다** — ADR-021이 정한 정책을 앱이 아직 다 따라오지 못했다. 남은 것은 Scene Context 건너뛰기
  버튼 부재다. 새 화면을 만들 때 이 행을 근거로 삼지 않는다.

## 지금 하지 않는 것

지금 기준으로 다시 센 목록이다. **이미 있는 것을 여기 적지 않는다** — 이 절이 낡으면 다음 사람이 있는 기능을 새로 만들려 든다.

- 연기에 매기는 점수, 등급, 레벨, 순위, 4축 평가, 평가표, 합격 가능성·재능·성격 판정 (ADR-005) — 챌린지의 좋아요 랭킹은
  반응 수라서 예외다(ADR-005 개정)
- 강점·약점·개선점 카드 — 폐기된 피드백 카드 프레이밍이다
- 관찰 확인(맞음/아님/모르겠음) 화면과 배우가 직접 쓰는 자기 정리 문장 (ADR-014) — 그 역할은 대화와, 대화에서 배우가 한 말을 담는 노트 칸(`actor_discovery`·`actor_words`)이 대신한다
- 배우 개인 심리, 트라우마, 치료적 영역을 파고드는 질문
- 첫 촬영 잠금, 전/후 비교 (ADR-007) — 영상 비교도, 노트끼리의 비교도 없다
- 대화 도중 재분석, 건너뛴 Scene Context를 나중에 채우는 **화면** (ADR-021)
- 멀티모달 파인튜닝 (ADR-010)
- YouTube 영상 원본·오디오·프레임·자막의 저장·캐싱·백업·자체 서버 보관·RAG 인덱싱 (ADR-011) — 참고 영상은 공식 임베드로만 보여준다
- "비슷한 프로 배우 영상" 추천 표현 — 쓴다면 "참고할 수 있는 장면 예시"로 낮춘다

## 디자인

화면 정본은 [acttub/pen](https://github.com/acttub/pen)의 `acttub 디자인.pen`이다. 색상·간격·컴포넌트 수치는
pen 파일과 옆 화면이 쓰는 값을 따르고, 여기에는 제품 정체성에서 나오는 규칙만 둔다.

- 과한 UI보다 조용한 연습실 톤 우선. 마케팅 랜딩이 아니라 매일 쓰는 연습 도구처럼 보여야 한다.
- 평가표처럼 보이면 실패다. 점수 원형·레이더 차트, 판정을 내리는 코치 아바타를 만들지 않는다(ADR-005).
  "좋음/나쁨"처럼 평가를 암시하는 색 매핑도 쓰지 않는다.
- AI 템플릿 장식을 쓰지 않는다: "Powered by AI" 배지, 보라·인디고 AI 팔레트, gradient로 칠한 글자, 배경
  gradient orb, glass morphism 카드, box-shadow 글로우 애니메이션, AI·magic·sparkle 아이콘, 과한
  confetti·emoji. 스크롤 헤더의 반투명, 랜딩 히어로 배경처럼 이미 있는 실물은 문자열만 보고 위반으로 판정하지
  말고 무엇을 하는 코드인지 먼저 본다.
- 애니메이션은 상태 변화를 이해시키는 데만 쓴다. 예외로 연속 연습일(streak)이 늘어난 순간의 전체화면
  축하는 습관 보상이라 스프링 등장·숫자 바뀜·칸 차오름을 허용하되, 글로우·그라데이션 흐름은 쓰지
  않는다(SOMA-494).

카피:

- 화면 문장은 한국어 존댓말("~해요")로 쓴다. 제품 개념의 이름은 [용어 표](agents/domain.md)를 따른다.
- 연습의 산출물은 "리포트"가 아니라 **연습 노트**다. "AI 리포트"는 챌린지 참여작의 설명에만 쓴다.
- 연습 화면 안에서 배우와 마주 앉은 상대는 "AI"가 아니라 "코치"다. 유입 표면(웹 랜딩, 앱 홈 카드,
  스토어 리스팅)은 아직 "AI"를 쓰며 어느 쪽으로 모을지 정하지 않았다. 새 화면은 그 화면이 속한 쪽을 따른다.
- 쓰지 않는 말: "평가 받기" · "점수 확인" · "약점 보기" · "정답 보기" · "AI 피드백 받기".
- 웹은 금지어 가드 테스트([product-language-guard](../apps/web/tests/product-language-guard.test.mjs))가 그 목록의 말을 막는다.
  목록 밖의 구절(예: "정답 보기")과 모바일은 손으로 지킨다.
