# PRD: acttub

## 목표
acttub은 배우가 자신의 연기 영상에서 아직 충분히 생각하지 못한 장면, 인물, 관계, 목표, 서브텍스트를 AI의 질문을 통해 스스로 발견하고 정리하게 돕는 **질문 기반 AI 연기 연습 파트너**다.

이 제품은 연기 점수나 평가 결과를 제공하는 서비스가 아니다. AI가 배우를 판단하거나 정답을 내려주는 대신, 사용자의 영상과 장면 맥락을 바탕으로 관찰 가능한 단서를 확인하고, 그 단서에 연결된 질문을 하나씩 이어가며 배우가 자기 말로 생각을 채우게 한다.

핵심 문제:

- 배우 지망생과 초보 배우는 혼자 영상을 돌려보며 연습하지만, 무엇을 다시 생각해야 하는지 찾기 어렵다.
- 1:1 코칭은 비용과 접근성의 제약이 크고 매일 사용할 수 없다.
- 표정, 동작, 발성 같은 결과만 고치라는 피드백은 배우가 심리와 행동을 분리해서 수행하게 만들 수 있다.
- 점수, 등급, 강점/약점 카드처럼 보이는 결과지는 초보 배우에게 안전한 연습 파트너보다 평가자로 느껴질 위험이 있다.

제품이 해결하려는 한 줄 문제:

> 배우가 자신의 연기 영상에서 놓친 생각과 서브텍스트를 AI의 근거 있는 질문을 통해 스스로 발견하게 한다.

성공 기준:

- 사용자가 세션 종료 시 “내가 놓쳤던 생각/선택/관계/목표”를 자기 문장으로 남길 수 있다.
- 사용자가 AI를 평가자보다 질문 파트너로 느낀다.
- AI 질문은 timestamp, 관찰 단서, 사용자가 입력한 장면 맥락, 또는 명시적으로 부족한 맥락 중 하나에 근거한다.
- 불확실하거나 해석 위험이 있는 관찰은 질문 근거로 사용하기 전에 사용자 확인을 거친다.
- 사용자가 거절한 관찰은 후속 질문 근거로 다시 쓰지 않는다.

## 사용자
주요 사용자는 연기 영상을 반복적으로 촬영하고 혼자 복기해야 하지만, 매번 전문가에게 코칭받기 어려운 배우 지망생과 초보 배우다.

1차 알파 페르소나:

- 이름: 지윤
- 나이: 19세
- 상황: 연극영화과 입시를 준비하는 재수생
- 행동: 입시 독백을 매일 혼자 촬영하고 돌려본다.
- 문제: 스스로는 무엇이 어색한지 느끼지만, 왜 그렇게 보이는지와 무엇을 다시 생각해야 하는지 잘 찾지 못한다.
- 제약: 1:1 코치는 비싸고 자주 만나기 어렵다.
- 기대: 평가표보다 “내가 장면에서 무엇을 더 생각해야 하는지”를 묻는 파트너가 필요하다.

우선 세그먼트:

- 연극영화과 입시생
- 연기 전공 재학생
- 독백, 자유연기, 오디션 영상을 반복 촬영하는 배우 지망생
- 멘토링을 자주 받을 수 없는 초보 배우

후속 세그먼트:

- 단편 영화, 웹드라마, 공연 준비 배우
- 연기 스터디 그룹
- 입시 학원 또는 개인 코치의 보조 도구
- 보호자가 결제자인 입시 준비 사용자

사용자 요구:

- 영상과 장면 맥락을 가볍게 입력할 수 있어야 한다.
- AI가 영상만 보고 확정할 수 없는 맥락을 단정하지 않아야 한다.
- 관찰이 틀렸을 때 안전하게 “아님” 또는 “모르겠음”으로 거절할 수 있어야 한다.
- 질문은 한 번에 하나씩 나와야 한다.
- 막혔을 때 정답이 아니라 생각의 발판을 받아야 한다.
- 세션 끝에는 AI 결론이 아니라 사용자가 직접 쓴 자기 정리 문장이 남아야 한다.

## 핵심 기능
1. 연기 영상과 장면 맥락 입력
   - 사용자는 연기 영상을 업로드한다.
   - 입력 순서는 영상 업로드, 미리보기, 매체/장르 선택, 상황 입력, 인물 설정 입력, 서브텍스트 입력, 분석 시작 순서다.
   - 매체/장르는 클릭형 칩으로 받는다.
   - 필수 맥락은 매체/장르, 상황, 인물 설정이다.
   - 서브텍스트는 선택 입력으로 두되 질문 품질을 높이는 핵심 맥락으로 안내한다.
   - 목표는 “칩 1클릭 + 짧은 줄 2개” 수준의 부담으로 첫 세션을 시작하게 하는 것이다.

2. 영상 1회 분석과 관찰 저장
   - 영상은 세션 시작 시 한 번 분석한다.
   - 분석 결과는 사용자에게 바로 평가표로 보여주지 않는다.
   - 분석 결과는 관찰 단서, timestamp, confidence, 관련 맥락, 확인 상태로 저장한다.
   - 이후 대화 turn에서는 영상을 다시 통째로 분석하지 않고 저장된 관찰과 대화 이력을 사용한다.

3. 관찰 확인
   - confidence가 낮거나 해석 위험이 있는 관찰은 먼저 사용자에게 확인한다.
   - 사용자는 관찰에 대해 맞음, 아님, 모르겠음으로 답할 수 있다.
   - accepted 관찰만 grounded question의 근거로 쓸 수 있다.
   - rejected 관찰은 `blocked_for_questioning=true`와 같은 상태로 다시 질문 근거에 쓰지 않는다.

4. 질문 대화
   - 핵심 화면은 결과지가 아니라 질문 대화 화면이다.
   - 질문 단위는 부족한 부분 가설, 근거 확인, 질문, 배우 답변, 후속 질문 또는 정리의 흐름을 따른다.
   - 질문은 한 번에 하나만 한다.
   - 질문은 timestamp/관찰 단서, accepted 관찰, 사용자가 입력한 맥락, 또는 명시적으로 부족한 맥락 중 하나에 연결되어야 한다.
   - MVP 질문 수는 5~10개 핵심 질문을 기준으로 한다.
   - 배우가 “모르겠다”고 답하면 정답을 주지 않고 관점을 좁혀주는 힌트만 제공한다.

5. 질문 초점과 탐침 축
   - 표면: 영상에서 무엇을 했는가
   - 의도: 인물은 무엇을 원했는가
   - 동기: 왜 그 의도를 가졌는가
   - 상황/감정: 왜 그렇게 느꼈는가
   - 감정 강도: 어느 순간 감정의 크기가 바뀌었는가
   - 표현 의도: 어떤 태도나 선택을 보여주려 했는가
   - 간극: 입력한 의도와 실제 관찰 사이에 어떤 차이가 있는가

6. 세션 종료와 자기 정리
   - 세션은 AI가 결론 카드를 주는 방식으로 끝나지 않는다.
   - 사용자가 직접 “내가 놓쳤던 생각/선택/관계/목표/서브텍스트”를 한 문장으로 정리한다.
   - 이 문장을 actor-authored filled-thought sentence로 저장한다.
   - 종료 화면은 점수, 등급, 강점/약점이 아니라 “다음에 다시 볼 질문”과 “사용자가 남긴 자기 정리”를 보여준다.

7. 검증 데이터 수집
   - 1차 검증은 “AI 피드백이 맞았는가”가 아니라 “배우가 질문을 통해 놓친 생각을 자기 말로 발견했는가”를 확인한다.
   - 수집 항목은 참가자/동의, 장면/인물 맥락, 질문 대화 turn 로그, 관찰 확인 상태, 세션 종료 자기 정리, 사후 설문이다.
   - 핵심 지표는 `felt_helped_find_gap_1_7`, `felt_scored_1_7`, `rejection_safety_1_7`, `answerability_1_7`, `reuse_intent_1_7`, `rejected_observation_reuse_count`, `forbidden_language_count`, `final_sentence_result`다.

8. 임시 API와 향후 백엔드 이전 가능성
   - 초기 제품 개발 중에는 `apps/web`의 Next.js Route Handler로 `/api/v1/*` 임시 API를 만들 수 있다.
   - UI는 route handler 구현에 직접 결합하지 않고 `src/lib/api/*`를 통해 API를 호출한다.
   - HTTP path, DTO, status code, validation 규칙은 향후 `apps/api`의 Spring Boot 백엔드로 이전할 수 있게 안정적으로 유지한다.

## MVP 제외 사항
- 점수, 등급, 레벨, 랭킹
- 4축 평가, 평가표, 결과 카드
- 강점/약점/개선점 카드
- “이렇게 하세요” 식 처방형 코칭
- 연기 잘함/못함, 진정성, 감정 전달력, 몰입도, 자연스러움 판정
- 관객 반응 단정
- 배우 개인 심리, 트라우마, 치료적 영역을 파고드는 질문
- rejected 관찰을 다시 근거로 쓰는 질문
- retake 기능
- 첫 촬영 잠금
- before/after 비교
- 성장 리포트
- 장기 학습 루프
- 보호자 결제 설득용 전/후 결과
- 모바일 앱
- Spring Boot 정식 백엔드 구현
- 멀티모달 파인튜닝
- YouTube 영상 원본, 오디오, 프레임, 자막 다운로드/저장/캐싱/RAG 인덱싱
- “비슷한 프로 배우 영상” 추천 표현

## 디자인
- 상세 UI 레퍼런스 파일: `docs/Toss-DESIGN.md`
- UI 방향은 Toss 스타일의 명료함, 낮은 장식성, 모바일 우선, 한국어 가독성, 강한 정보 위계를 참고한다.
- 제품 화면은 마케팅 랜딩이 아니라 매일 쓰는 연습 도구처럼 보여야 한다.
- 첫 화면은 큰 홍보 문구보다 바로 영상 업로드와 장면 맥락 입력으로 진입해야 한다.
- 주 배경은 흰색 또는 매우 밝은 회색을 기본으로 한다.
- 주요 액션은 Toss Blue 계열 `#3182f6`를 기준으로 하되, Acttub 브랜드 컬러가 확정되면 semantic token만 교체한다.
- 검정에 가까운 본문 색은 `#191f28` 계열을 기준으로 한다.
- 회색 계열은 `#f9fafb`, `#f2f4f6`, `#e5e8eb`, `#8b95a1`, `#4e5968`, `#333d4b` 계열을 사용한다.
- 버튼과 입력은 모바일 터치 목표를 우선해 48~56px 높이를 기본으로 한다.
- shadow는 최소화하고, 레이어 구분은 배경색, border, spacing으로 처리한다.
- 질문 대화 화면은 평가 리포트처럼 보이면 안 된다. 채팅, 확인 버튼, 한 문장 정리 입력을 중심으로 설계한다.
- 사용자 노출 카피는 “평가”, “점수”, “약점”, “개선점”, “진단 결과”, “피드백 카드”를 피하고 “관찰”, “질문”, “다시 생각해볼 지점”, “내가 놓친 생각”을 우선 사용한다.
- AI 관련 장식 배지, 보라색 AI SaaS 느낌, gradient orb, glassmorphism, 과한 glow animation은 사용하지 않는다.
